## 1. 変更の理由

従来のP4-04はテスト戦略、RED、Run Manifestを主対象としており、P4-08で接続するフロントエンドの画面別実装契約と、P4-06〜07で接続するAPI別実装契約が独立成果物として不足していた。

このままでは、画面構成、状態、API結線、エラー、キーボード操作、アクセシビリティ、レスポンシブ、テスト証跡を実装者が補完する余地があるため、P4-H1前に詳細設計へ分離する。

## 2. P4-04の新しい順序

1. `P4-04A`：全P4 canonical API詳細設計
2. `P4-04B`：全21画面UI詳細設計
3. `P4-04C`：API／UI詳細設計に接続するRED・Run Manifest・trusted scope・Evidence設計
4. `P4-05`：上記を含む統合レビュー、改訂、P4-H1提出候補

P4-04A/B/Cは親Step `P4-04`の順次サブプロンプトである。P4-H0が許可したP4-01〜05の設計・RED範囲に留め、P4-H1が必要な実装、依存導入、実行Run、UIソース変更を先取りしない。

## 4. 後続Stepへの反映

- `P4-05`は、全API inventory、21/21画面coverage register、画面×状態表、API/UI bindingをCritical／High判定の対象にする。
- `P4-06`は、承認済みの基底canonical APIをローカルapplication層に実装する。未承認のHTTP transportや依存は導入しない。
- `P4-07`は、P4-04Aの全API-P4-IDを実装または設計どおりUNSUPPORTEDにする。
- `P4-08`は、P4-04BでP4実装対象とした全画面・全状態・API bindingを固定ダミーUIへ接続する。P4対象外は境界表示に留める。
- `P4-09`と`P4-10`は、全APIと21/21画面の設計・実装・Test・Evidenceの整合を完了条件にする。

## 5. Human Gateと安全境界

`P4-H0`は承認済みのままである。今回の改訂は、既に許可された設計・RED範囲を詳細化したものであり、実装権限を追加しない。

`P4-H1`の承認対象には、P4-03、P4-04A/B/C、P4-05のCritical／High=0、Core差分0、全P4 API inventory、21/21画面coverage、画面×状態、対象Run ID、target_paths、fixture hash、trusted scope、停止条件を追加した。

外部Data、Broker、Secret、Paper、Live、実資金、Cloud、実Risk値、Account、Order、Core変更は、改訂後もP4-H1前後を問わず承認された範囲外である。

- `src/`、`tests/`、`ui/mock/`、Core、fixture、依存、WSL、外部接続を変更していない。
- 未登録Runを実行していない。
