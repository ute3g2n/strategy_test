## 5. DB／ER詳細設計の実施結果

### 5.1 保存責務

- metadata DBはRun、RunCondition、RunStateTransition、Job、QueueItem、Checkpoint、
  ResultReference、EvidenceReference、SweepParent、SweepMember、CsvJob、
  IdempotencyRecord、AuditEvent、HoldoutAssessment、SchemaMigrationを保存単位として定義した。
- Core ResultStoreはResult本文の正本とし、metadata DBにはrelative reference、commit marker、
  result hash、definition versionだけを保存する。
- Evidence／CSVはfileの正本とし、metadata DBはrelative reference、bundle／output hash、
  verification stateを保存する。任意path、UNC、reparse、Secret、外部I/Oは許可しない。

### 5.2 ER図と受渡し

正式HTMLの7章にMermaid `erDiagram`を作成し、以下を明記した。

- RunとConditionの1対1、RunとState／Job／CSV／Audit／Evidenceの1対多
- JobとQueueのoptional 1対1、JobとCheckpointの1対多
- ResultReferenceの公開結果参照、EvidenceReferenceの相対file参照
- SweepParent／SweepMember／child Runの親子
- append-only履歴、IdempotencyRecord、SchemaMigrationの監査接続
- Core ResultStore、CSV file、Evidence fileとの境界

ER図直後にrelationshipごとのFK、所有者、作成／更新者、状態不変条件、破損時停止を置き、
ER図と本文の孤立・未定義FK・重複所有を点検した。

### 5.3 全API-P4-ID coverage

P4-04AのAPI-P4-001〜019をすべて6章へ一行以上で接続した。各行にread/write table、
transaction境界、commit順、IdempotencyRecord、expected revision、lease／fencingまたはN/A理由、
optimistic lock、同時実行、retry、recovery、AuditEvent、Evidence／hash、Fail-closed条件を記録した。
API-P4-X01〜X05はP4外として保存副作用なしのUNSUPPORTED／BLOCKED契約にした。

重点確認対象はAPI-P4-003／004／007／010／011／016／019、Worker、ResultStore、
CSV atomic outputであり、partial write、crash、marker／hash不一致、migration不整合、
stale revision、duplicate requestを成功へ変換しない設計にした。

### 5.4 logical／physical schema

8章で全15保存単位のcolumn、logical type、required／nullable、default、PK、FK、unique、
check、index、revision、保持、削除／archive、Secret／path境界、根拠を記録した。11章では
SQLiteのTEXT／INTEGER／0-1、FK／unique／check、WAL、candidate DDL、migration version、
transaction isolation、backup／restore境界を候補として分離した。

P4-03の条件付きADRを無条件の実装確定へ変換せず、retention、backup／restore、SQLite version、
同時writer、migration direction、physical feature、storage rootをUnknownとして残した。
