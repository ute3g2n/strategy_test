## 1. 30秒で分かる結論

このシステムは、運用者一人が、先物・株式・FX・暗号資産を対象に、日足、4時間足、1時間足、30分足、15分足を選び、Turtle System 1/2などの売買ルールを組み合わせて運用単位を作る仕組みである。異なる時間足の単位は同時に動かせるが、同じ銘柄×時間足の重複単位は同時に動かさない。

運用者は、初期設定、データ品質確認、Strategy設定、Backtest単一Run、下限・上限・ステップを使う網羅検証、結果比較、Forward、Shadow、Paper、Live候補、Liveの確認、日常監視、警告、停止、照合、手動再開、履歴・削除・再実行を画面から行う。画面は認証を要求しないが、危険操作にはHuman Gate（運用者が内容を確認して進める関門）を表示する。

## 2. 今回の利用者と安全境界

### 2.1 利用者

| 利用者 | できること | 認証 |
|---|---|---|
| 運用者（開発者本人） | 設定、Run、監視、停止、復旧、承認、削除、記録確認の全て | 不要 |

ユーザー管理、ログイン、Role切替は作らない。ただし、認証不要であることは、未承認のLive実行や停止解除を許可することではない。

認証不要は、この自PCまたは運用者本人のスマートフォンから、閉じた運用環境で使う前提のUI方針である。candidate UIはローカル表示・外部公開なしであり、誰でも到達できる場所へ公開しない。実システムでスマートフォンから接続する方式、端末制限、ネットワーク境界、TLS、公開範囲は、実接続を許可する後続Gateで証拠を確認するまでUnknownとして扱う。

### 2.2 絶対に越えない境界

- UIモックは固定Seedの匿名ダミーデータだけを使い、実Broker、実口座、Secret、実注文、実市場データへ接続しない。
- Riskが未入力ならBacktestを含む全モードの開始を許可しない。Riskの値の範囲・妥当性を検査する仕様にはしない。
- データ品質不合格、接続断、Heartbeat異常、Position不一致、注文不一致ではSignal・新規注文を止める。
- 全体Kill Switchまたは個別停止後は、データ・注文・Positionを照合し、運用者が手動で再開する。自動再開しない。
- Live自動承認は設定画面で明示的にONにしたときだけ有効。切替・対象・設定版・Risk・端末・時刻を記録し、再起動後はOFFに戻す。
- Live自動承認はHuman Gateの別モードであり、確認と取消モードと同じく対象・設定版・Risk・影響・端末・時刻を確認したDialogを経て記録する。モードを選んでも実注文は送らない。
- 取消、停止、再開、Strategy有効化・無効化・新版保存・ロールバックなどの変更操作は、理由入力、確認Dialog、操作記録を経て受け付ける。
- Q-277の旧「Q-243を先に閉じる」方針は撤回済み。RQU-19/RQU-19Aを現在方針とし、Q-243の4領域を今回の構造確認と後続実証へ分ける。

## 4. 使い方（画面を操作する順番）

### 4.1 初回準備

1. `SCREEN-01`でシステム状態、禁止事項、未承認、実行不可項目を確認する。
2. `SCREEN-20`で提供元名、通知、自動更新Switch、更新間隔[s]を設定する。Secret値は入力しても表示しない。
3. `SCREEN-05`でAsset Classと初期候補5件を選ぶ。D1/H4/H1/M30/M15のデータ時刻と品質を確認する。M1は内部処理用であり選択しない。
4. `SCREEN-06/07`でTurtle System 1/2を作り、版、Long/Short、Entry、Stop、Exit、追加条件を検証する。
5. `SCREEN-04`で運用単位を作る。Risk未入力、実シンボル未確認、同じ銘柄×時間足の重複は開始不可になる。

### 4.2 Backtest単一Run

1. `SCREEN-08`の単一Runタブで銘柄、時間足、Strategy、期間、Risk、コスト、設定ファイルを入力する。
2. 「事前検証」で未入力、Manifest、データ品質、候補承認状態を確認する。不合格なら開始Buttonは押せない。
3. 「開始」でRunを作り、`SCREEN-09`でQueue、進捗、経過、残り見積、成功・一部失敗・失敗を確認する。
4. 取消と停止を別に扱う。どちらも確認Dialogと操作記録を経て受け付け、取消は途中結果を未完了として保存し、停止は再開条件の確認を必要とする。再実行も同じ確認手順を使う。
5. `SCREEN-10/11`で総損益、最大の落ち込み、取引回数、勝率、総残高、資産曲線、取引、Signal、想定と実績の差分を確認する。

### 4.3 パラメータ網羅検証

1. `SCREEN-08`の網羅検証タブを選ぶ。
2. 設定ファイルまたは画面で、変更する各パラメータの下限、上限、ステップを指定する。画面では値を編集でき、設定ファイルを選択した場合はファイル名を確認してから読み込み候補にする。
3. `VIEW-01`で組合せ数、見積時間、資源負荷、上限警告を確認して開始する。
4. `SCREEN-09`で組合せごとの進捗、成功、部分失敗、失敗、取消を確認する。
5. `SCREEN-10/12`で全組合せの総損益、最大の落ち込み、取引回数、勝率、総残高を表形式で確認し、検索・絞込・並替・比較・CSV出力を行う。最良設定は運用者が判断する。

### 4.4 Forward、Shadow、Paper、Live候補、Live

1. Backtest結果と運用単位を確認し、`SCREEN-13`でForwardまたはShadowを開始する。
2. 停止・再開は、データ・注文・Positionの照合を経て運用者が確認する。
3. `SCREEN-14/18`でPaper、Live候補、Liveの条件を順番に確認する。未承認項目があれば次へ進めない。
4. Live自動承認を使うときは、確認・取消モードとの違い、対象、Risk、設定版、再起動後OFFを確認する。自動承認でもHuman Gateの確認Dialogと記録を省略しない。
5. candidateとUIモックでは、実注文を送らず、状態とDialogの表示だけを確認する。

### 4.5 日常監視、停止、復旧

1. `SCREEN-02`で全運用単位の最新データ、Heartbeat、次回判断時刻、Signal、Position、警告、総残高を確認する。手動更新と自動更新を選べる。
2. 遅延・接続断・Heartbeat異常は`SCREEN-17`で確認し、10/30/60秒の再試行後に停止する。
3. 危険がある場合は個別停止または全体Kill Switchを二段確認で実行する。
4. 再起動後はSnapshot、データ、注文、Positionを`SCREEN-18`で照合する。照合前の再開はできない。

### 4.6 検索、出力、非表示、削除、再Run

1. `SCREEN-19`でRun、Result、Manifest、設定版、hash、操作、Gate、停止を検索する。
2. CSV・レポートは非同期で出力し、進捗・成功・失敗・取消を表示する。
3. 同一条件Runは許可し、最新結果表示と内部Run保存を分ける。
4. 通常一覧から隠す操作と削除操作を分ける。削除は確認Dialogと監査記録を必須とする。

## 7. Backtestと段階運用の状態

### 7.1 単一Runと網羅検証

| 観点 | 単一Run | 網羅検証 |
|---|---|---|
| パラメータ | 1セット | 各値の下限・上限・ステップ |
| 進捗 | 1 Run | 全組合せ、Queue、部分失敗 |
| 結果 | 5指標と詳細 | 全組合せの5指標表 |
| 操作 | 取消、停止、再Run、Replay | 取消、停止、部分再実行、CSV |
| 判断 | 運用者が確認 | システムは最良設定を自動決定しない |

### 7.2 段階

`Backtest → Forward → Shadow → Paper → Live候補 → Live`の順である。各段階は前段の結果・品質・Risk・承認・証拠を確認してから開始する。停止後は照合と運用者の確認が必要であり、再起動後に自動再開しない。

## 8. 後続GateとUnknown

| 項目 | 今回candidateで定義すること | 後続Gateで実証すること |
|---|---|---|
| 安全境界 | Risk未入力停止、Kill、照合、手動再開、Live自動承認の記録 | 実Broker、実注文、実機、Liveの具体値 |
| 初期候補 | MCL/M6A/MZC/MZS/MZW、4 Asset Class、状態表示 | 実シンボル、取引所、限月、ロール、単位、契約、提供元 |
| 実行可能性 | UIモックの固定ダミー、React+TypeScript、Playwright境界、外部I/O禁止 | Frontend本実装、最終Engine、負荷、復旧、Broker照合 |
| 性能 | 初回一覧3秒、追加2秒、CSV非同期、初期3〜5目安、負荷時制御を受入対象化 | 実PC負荷、20〜40単位、遅延、復旧実測 |
| バックアップ | 対象、非表示、削除、復旧UIの構造 | 実保存先、日次30世代、月次復元確認の実証 |

Q-277の撤回済み方針、Q-81の質問時点未回答、古い「履歴管理不要」は履歴として残すが、現在の構造方針を上書きしない。Unknownは決定時期、開始禁止条件、停止条件、証拠先を追跡表と統合台帳で管理する。

候補HTMLは表示・導線確認用の静的版で、ボタンの状態変更や危険操作の実処理は行わない。操作可能性、Dialog、入力値、状態切替の証跡はReact実装版で確認し、静的版は21画面の情報・リンク・外部通信なし・PC/スマートフォンの表示確認に限定する。実システムの端末アクセス、性能、監査保存、バックアップ復元、Broker接続は後続Gateの証拠が揃うまでPassにしない。

## 9. 追跡と正式化条件

- `ADD-UC-*` → `RQU-UI-REQ-UC*` → `SCREEN-*` → `UISTATE-*` → `E2E-UI-*` → `AC-UI-*`を追跡マトリクスで辿る。
- UIモック候補は`SCREEN-01`〜`SCREEN-21`を`data-testid=screen-SCREEN-xx`で公開し、左ナビの`nav-SCREEN-xx`から到達できる。各画面の`REQ`・`UC`は本candidate、RQU-UI-05、追跡表へ戻れる。
- 21画面、10状態、67ユースケース、40受入確認項目の未判定を残さない。実装前の項目は`NOT-RUN`、後続実証は`BLOCKED`であり、Passにしない。
- RQU-UI-07〜13のUI実装、E2E、Visual、a11y、専門・Red Teamレビューが完了し、RQU-UI-H3でcandidateの意味・安全境界・画面・証拠を承認した後に、正式Markdown、正式HTML、`doc/index.html`を同じ版へ更新する。

## 10. 用語

| 用語 | このシステムでの意味 |
|---|---|
| 運用単位 | 銘柄×時間足×売買ルール×口座×モードを持つ独立インスタンス |
| Human Gate | 運用者が対象・影響・Risk・証拠を確認して進める安全上の関門。認証ではない |
| 1N Risk | 1回の取引で許容する基準リスク。未入力は開始不可、値の範囲検査はしない |
| Kill Switch | 全体または個別の新規Signal・注文を止める操作 |
| Replay | 同一条件を再実行し、結果一致を確認する操作 |
| 非表示 | 通常一覧から隠すだけ。削除とは別の操作 |
| 網羅検証 | 下限・上限・ステップで全パラメータ組合せを試すモード |
