## 5. 原子要求の必須テンプレート

各原子要求は、次の順で一つの正本節に記載する。shall文は観測可能な対象・条件・動作を含め、「適切に」「必要に応じて」だけで終わらせない。

```text
### REQ-V2-0001 <短い名称>
- Shall: システムは、[主体]が[条件]のとき、[対象]について[観測可能な動作]をしなければならない。
- Source: Q-ID / UC-ID / RQU-20章 / 既存成果物または承認記録
- Reason: この要求が必要な理由
- Assumptions: 採用した前提。未確定ならUN​​K-IDを付ける
- Inputs: 入力、形式、単位、時刻、来歴
- Processing: 正常処理、順序、判定、冪等性
- Outputs: 出力、状態、利用者表示、次工程へのリンク
- Exceptions: 入力不正、欠損、競合、外部失敗、未知値
- Stop: 停止条件、fail-closed条件、Human Gate
- Recovery: 再開、取消、復旧、再試行の条件
- Persistence: 保存対象、版、hash、監査記録、削除境界
- Acceptance: 機械確認、レビュー、証拠ID、受入条件
- Implementation status: CONFIRMED / IMPLEMENTED_VERIFIED / NOT_IMPLEMENTED / LATER_GATE / UNKNOWN / BLOCKED
- Target phase: 実現予定Phaseまたは「未定」
```

要求の正本は一つだけにする。別章では`参照: REQ-V2-0001`と目的を記載し、shall文を複製しない。

## 6. 状態語・用語の固定

| 状態語 | 意味 | 禁止される読み替え |
|---|---|---|
| `CONFIRMED` | 回答・承認・正本入力で内容が確定 | 実装済みを意味しない |
| `HISTORY` | 撤回・旧方針として履歴参照のみ | 現行要求へ再利用しない |
| `LATER_GATE` | 後続Human/品質Gateで決める | 現在のPassにしない |
| `UNKNOWN` | 根拠不足で未確定 | 推測値で埋めない |
| `BLOCKED` | 条件不足で開始・判定を停止 | 運用者上書きを機械Passと混同しない |
| `IMPLEMENTED_VERIFIED` | 固定範囲の実装と対応証拠を確認 | 実市場・利益・本番運用へ拡張しない |
| `IMPLEMENTED_UNVERIFIED` | 実装の存在は確認したが証拠不足 | 受入済みとしない |
| `NOT_IMPLEMENTED` | 実装未確認または未実装 | 要件の不在を意味しない |
| `OUT_OF_SCOPE` | 本Step・本Phaseの対象外 | 永久に不要とはしない |
| `PASS_WITH_OPERATOR_OVERRIDE` | 運用者の権限で継続を許可した | 欠落証拠をPASSへ置換しない |

## 7. HTML・リンク・証拠の規則

- 章anchorは`ch-00`〜`ch-62`、要求anchorは`req-REQ-V2-0001`、UCは`uc-UC-V2-001`、画面は既存の`SCREEN-01`を基準とする。
- HTML化時は各anchorを一意にし、見出し番号の変更だけでリンク先が変わらないようにする。
- UIリンクは`../ui_mock/01_自動トレードシステム_UIモック.html#SCREEN-XX`を基準にし、画面名ではなくScreen IDをリンクテキストへ含める。
- 証拠リンクは、成果物から`tests/evidence/...`または計画・ログの相対パスへ向ける。存在しない証拠をリンクだけで作らない。
- 外部URLは公式一次情報を使う場合だけ記録し、確認日を付ける。外部取得を実行したこととは扱わない。
- 正式HTMLは`doc/index.html`から到達可能にする。作業用Markdownは正式成果物と表示しない。

## 8. 正本節と参照節

要求、UC、Screen、State、Gate、Unknownの意味を最初に定義した節を正本とする。後続断片は正本ID、章anchor、目的だけを参照する。同じ要求の説明が必要な場合は「要約」「画面上の見え方」「検証手順」を分離し、shall文・受入条件・状態判定は正本節へ戻す。
