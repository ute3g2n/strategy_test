## 1. 回答の重要な整理

### 1.1 実行環境・性能

- Q-237は、性能基準用にPC仕様を別途確定する必要はない、という決定である。すべての処理と確認は、このPCで行う。
- Q-238は、初回一覧3秒以内、追加読み込み2秒以内、CSV全件出力は別処理で進捗表示、を採用する。
- Q-239は、異常終了後に10秒・30秒・60秒の待ち時間で最大3回再試行し、失敗後は停止して確認を求める。
- Q-240は、実時間運用を優先し、新しいBacktestを待機させる。動作中のBacktestは安全に一時停止できる場合だけ停止する。

### 1.2 運用対象・Risk・Live

- 初期候補は `MCL / M6A / MZC / MZS / MZW` の5件で確定している。
- 先物・株式・FX・暗号資産の4種類すべてについて、データ取込からLive候補までの経路を用意する。ただし実Live注文は別の接続・承認条件を満たすまで実行しない。
- Risk値は未入力なら開始しない。ただし、Risk値の範囲や他のRisk値との整合性を検査する機能は設けない。入力済みかどうかだけを開始条件とする。Q-261の設定ファイル検査は、Risk値以外の項目に適用する。
- Live自動承認は、条件未達でも警告を表示したうえで運用者がONにできる。再起動後OFF、緊急停止、操作記録など、既に決めた安全記録は維持する。

### 1.3 技術・接続

- PCとスマートフォンは初回ペアリング、端末秘密情報、HTTPS、失効・再登録で限定する。
- PCは楽天モバイル回線から外向きに接続し、IIJmioスマートフォンは外部HTTPS入口または中継へ接続する。PCのアプリポートは直接公開しない。
- Python APIはFastAPI、保存と長時間処理はSQLite（WAL）・Alembic・別プロセスの作業キュー、画面はEChartsと大規模表表示部品を採用候補として固定する。
- Playwright E2Eは、PC・スマートフォン幅、主要操作、通常・読込中・データなし・警告・停止・エラー・未承認の状態を確認し、証跡を保存する。
