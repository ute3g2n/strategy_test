## 1. 読み方とID規則

この表は、要件定義書とUIモックを作る前の追跡骨格である。既存の正式要求IDを勝手に再定義せず、追加要件候補へ一時IDを割り当てる。

| ID | 意味 |
|---|---|
| `ADD-UC-*` | RQU-11で定義されたユースケースID |
| `RQU-UI-REQ-UC*` | この計画で追加する要求候補。RQU-UI-06で正式要求IDとの対応を確定する |
| `REQ-*` | RQU-03・正式要件で既に使われている要求領域。意味を変更しない |
| `SCREEN-*` | RQU-11の21必須画面候補 |
| `VIEW-*` | 21画面の機能を補助する画面内View候補 |
| `UISTATE-*` | UI共通状態候補。通常、読込中、空、未入力、警告、停止、失敗、復旧、Human Gate、未承認 |
| `E2E-UI-*` | Playwrightで作成する操作旅程の候補。RQU-UI-11で期待値と証跡を確定する |
| `NOW-STRUCTURE` | 機能・操作・状態・入力欄など、今回の要件/UI構造へ反映する方針 |
| `LATER-GATE` | 実データ、外部接続、契約、実数値、実機、実運用証拠を後続Gateで確定する事項 |
| `HISTORY-REVIEW` | 旧回答・撤回・質問票内の履歴。現在の方針として採用しない |
