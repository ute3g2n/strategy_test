## 3. 観点別レビュー結果

### 3.1 Design / Traceability（A90統合）

- `ADD-UC-001`〜`ADD-UC-086`のうち、追跡表には67件のユースケースがあり、RQU-UI-11で新設したT01〜T08にもIDを付けた。重複IDは検出されなかった。
- candidate Markdown/HTML、UIモック、追跡表、受入確認表、統合台帳のローカル相互リンクは機械確認済みである。
- 正式要件HTML、正式UI、`doc/index.html`はH3前のため未変更であり、candidateと正式版を混同しない境界は保たれている。
- ただし、21×10状態の実証不足（F-008）、静的HTMLとReactの意味差（F-010）、画面操作の一部欠落（F-002〜005）が残る。

### 3.2 Risk / Account / OMS（A60相当）

- Risk未入力で開始不可、Risk値の範囲検査を行わない、Kill Switch後の照合と手動再開、Broker差異時の新規注文停止は要求と整合する。
- 取消・停止・再開の一貫した状態機械と、Live自動承認の両モード記録が不足している（F-001/F-002）。
- 同じ銘柄×時間足をルール違いで重ねない制約が実装判定に反映されていない（F-004）。

### 3.3 Ops / Security / Red Team（A70相当）

- 実Broker、Secret、実注文、外部通知を未接続に保つ境界は確認できた。
- 認証不要を採用する以上、自PC・自スマートフォン以外からの接続を防ぐ境界を別途定義しなければ、Live候補画面の露出範囲を保証できない（F-006）。
- Kill Switch、停止理由、照合前再開禁止は文言としてあるが、ボタン操作から状態・監査記録までの閉ループが不足する（F-002）。
- Backup、復元、削除保持は後続Unknownであり、今回Passにしていない（F-012）。

### 3.4 Visual / a11y（A171相当）

- RQU-UI-11のaxe critical/seriousはReact/静的HTMLのPC・スマートフォン各21画面で0件、Dialogと基本keyboard操作はPassだった。
- ただし画像撮影の遷移待ち不足と、静的HTMLのVisual対象範囲不足により、画像証跡は正式化にそのまま使えない（F-007）。
- Reactの主要画面は読みやすいが、静的HTMLと操作意味を一致させる文言・Dialogが不足する（F-010）。
- 詳細画面の時間足選択不足は、表示の網羅性に関わる（F-009）。
