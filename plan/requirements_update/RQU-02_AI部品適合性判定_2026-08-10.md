## 1. 判定の目的

今回の要件定義書アップデートに、専用のSkill、サブエージェント、Orchestratorを追加する必要があるかを判定した。

「C4モデルで書く」「中学生にも分かるようにする」「Mermaid図を描く」という要求だけを理由に、Phase専用部品を増やすことはしない。既存の汎用部品で責務を分担できるか、今回限りの編集ルールで対応できるか、将来も再利用する恒久責務なのかを分けて確認した。

## 2. 判定基準

| 判定観点 | 適合の条件 |
|---|---|
| 事実の整理 | 要件、台帳、最終判定、実装、テスト、証拠を分けて読める |
| 領域設計 | Architecture、Strategy/QA、Execution/PoC、Adapter、Risk/Account、Ops/Securityを担当分けできる |
| 詳細設計基盤 | AF-D14〜17を品質構造として参照し、要件定義と詳細設計の境界をレビューできる |
| HTML統合 | HTML、メタ情報、履歴、相互リンク、`doc/index.html`を統合できる |
| Mermaid | 図種ごとの文法をローカル資産で試験し、検証結果を残せる |
| 中学生向けレビュー | 説明本文を切り出して`student-reviewer`で補助評価できる |
| 安全性 | UnknownをPASSにせず、未承認のBroker/Paper/Live/Secret/Cloudを許可済みと書かない |
| 部品変更統制 | 不足が恒久責務の場合だけ、RQU-H1後にLifecycle基盤で変更できる |

## 8. RQU-H1の判定

RQU-02では、既存部品の組合せで次の要求を満たせる。

- 現在事実の棚卸し
- 技術領域別のC4境界整理
- 詳細設計AI基盤によるLevel 3/4接続レビュー
- HTMLと`doc/index.html`の統合
- Mermaid互換性の工程内検証
- 中学生向け説明本文の補助レビュー
- Unknown、Human Gate、安全境界の保持

不足は「恒久的なAI部品の責務」ではなく、RQU-04以降の作業用入力・検証手順として計画書に明記すれば扱える範囲である。

**判定:** `SKIPPED_REUSE_SUFFICIENT`

したがって、今回のRQU-02完了時点でRQU-H1を開かない。RQU-02Aは実行しない。

## 9. RQU-02Aを再検討する条件

後続工程で次の状態になった場合だけ、RQU-H1を開き、具体的な部品名と変更範囲を提示する。

1. 既存部品の組合せで、C4 Levelごとの要求・図・状態・証拠追跡を統制できない。
2. 同じ不足が今後の複数Phaseで繰り返し使う恒久責務である。
3. 作業プロンプトの補足ではなく、Skill/Agent/Orchestratorの責務として固定する価値がある。
4. 変更後のAI基盤HTML、ルール、索引、検証を同じ変更セットで更新できる。

この条件を満たさない場合は、新設しない。
