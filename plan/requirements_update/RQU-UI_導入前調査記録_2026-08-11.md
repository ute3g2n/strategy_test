## 1. 結論

現時点のリポジトリには、UIモック用のReact/Vite/Storybook/Playwright構成は存在しない。ルートのNode構成はプロジェクト監視とMermaid生成に限られ、`package-lock.json`からnpmを使っていることは確認できる。

したがって、次の導入先を推奨候補とする。

- パッケージマネージャ: npm（ルートに`package-lock.json`があるため）。
- Frontendソースルート: 既存Frontendがないため、新規`ui/mock/`を第一候補とする。ただし、RQU-UI-H1で運用者が承認するまで確定しない。
- UI実装候補: React＋TypeScript＋Vite。
- 部品候補: shadcn/ui CLI。Base UIとRadixはRQU-UI-03の小規模pilot後にRQU-UI-H2で決定する。
- 品質候補: Storybook、`@storybook/addon-vitest`、`@storybook/addon-a11y`、Vitest、axe、`@playwright/test`、標準`npx playwright`、固定Seedの`@faker-js/faker`。
- AI向け`@playwright/cli`: 必須導入には含めず、RQU-UI-H1-V0相当の承認がある場合だけ匿名モック探索に限定する。
- Vercel v0、Figma MCP、Chromatic、Playwright MCP: 今回の導入前調査では対象外。未利用でも計画は継続できる。

### 3.2 版固定の扱い

RQU-UI-02では、外部registryから現行最新版を取得して決めることはしていない。`latest`を正式版として記録せず、RQU-UI-H1承認資料には次の値を埋める。

- 実際に導入するパッケージ名と版。
- Node/npmの実行版、lockfileVersion、ブラウザ版。
- npm registryから取得する場合のresolved URL、integrity、license。
- `npm ci`または承認済みの同等コマンド。
- `npx playwright install`で取得するブラウザ、保存先、hashまたは版証跡。
- rollback用に保存する`package.json`、lockfile、設定ファイル、導入前のgit状態。

## 4. RQU-UI-H1承認資料案

RQU-UI-03へ進むには、H1で以下を別途承認する。RQU-UI-02では承認を代行しない。

1. Frontendの正本ルート（推奨候補 `ui/mock/`）。
2. npm利用、registryへのパッケージ取得、取得対象、版、license、費用の有無。
3. React/Vite、shadcn、Storybook、Vitest、axe、Playwright、Fakerの固定依存セット。
4. Chromium等のブラウザ取得、保存先、取得量、hash/版記録。
5. Base UI/Radix比較用pilotをRQU-UI-03で実行すること。
6. 既存ルート監視scripts・Pythonソース・正式HTMLを変更しないrollback境界。
7. `@playwright/cli`を使う場合の匿名モック限定範囲。使わない場合も計画は継続する。
8. Vercel v0等の外部AIサービスはこの承認に含めない。利用する場合は`RQU-UI-H1-V0`を別に承認する。

### 4.1 RQU-UI-H1前の停止条件

- package manager、Frontend正本ルート、固定版、license、rollbackが確定していない。
- 外部registry、ブラウザ取得、外部AIサービス、費用発生の範囲が承認文にない。
- 既存未コミット変更を保存・比較できない。
- Node 24.18.1と候補依存の互換性が確認できない。
- Secret、実口座、Broker、実市場データ、個人情報を使う必要がある。
