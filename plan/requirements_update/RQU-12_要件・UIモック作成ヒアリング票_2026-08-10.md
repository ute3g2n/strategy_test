## 1. このヒアリングの目的

この文書は、要件定義書を「このシステムで何ができて、運用者がどの画面でどう使うか」まで分かる内容へ更新し、対応するUIモックHTMLを作る前に、必要な判断を集めるための質問票である。

すでに決まっている次の内容は、質問し直さない。

- 利用者は運用者（開発者本人）1名である
- 本システム内のログイン、パスワード、ユーザー管理、役割別の権限管理は作らない
- 取引対象の時間足は、15分足、30分足、1時間足、4時間足、日足である
- 1分足は内部の元データまたは発火専用として扱う
- 外部Broker接続、Paper実行、Live実行、Secret、Cloudは現在の許可範囲ではない

この質問への回答は、将来の要件を決めるためのものに限る。回答そのものは、外部接続や実資金運用の承認ではない。

## 2. 回答方法

各質問は、原則として一つ選ぶ。

- `A`〜`C`：用意した選択肢
- `Z`：自由記述。用意した選択肢で合わない場合に選び、希望を書く
- `（推奨）`：現時点での推奨案。採用を強制しない

回答例：

```text
Q-01=A
Q-02=Z：最初はBacktestを中心にし、Paper準備までを今回の範囲にしたい。
Q-03=B
```

一度に全問へ答える必要はない。まずは第1回の`Q-01`〜`Q-22C`から回答し、その後に第2回以降を進めることを推奨する。

## 3. 用語の短い説明

| 言葉 | この文書での意味 |
|---|---|
| 過去検証（Backtest） | 過去の値動きを使い、売買ルールを試すこと |
| 実時間確認（Forward / Shadow） | 今から入ってくる値動きで、実際には注文せずルールの動きを見ること |
| 練習口座（Paper） | 実際のお金を使わず、注文や約定の流れを試すこと |
| 実運用（Live） | 実際のお金を使って注文すること |
| 運用単位 | 銘柄、時間足、売買ルール、運用モードなどをまとめた一つの運用設定 |
| Signal | 売買ルールが出した「買いたい・売りたい・何もしない」という判断記録 |
| 停止スイッチ（Kill Switch） | 新しい注文をすぐ止める安全操作 |

## 4. 回答後の扱い

| 回答の種類 | 次に行うこと |
|---|---|
| すぐ決められる回答 | 要件定義書の追加候補へ反映する |
| 複数案で迷う回答 | Unknownとして残し、UIモックでは比較できる形にする |
| Broker、Secret、費用、実資金、Cloudに関する回答 | 統合台帳のHuman Gate・再開条件と照合する。回答だけでは実行しない |
| 現時点で不要な機能 | 対象外または将来候補として明記する |
