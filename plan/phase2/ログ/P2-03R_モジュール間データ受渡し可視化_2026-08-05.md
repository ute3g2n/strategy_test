# P2-03R モジュール間データ受渡し可視化ログ

- 実施日: 2026-08-05
- 対象: P2-D05、P2-D06、P2-D07、P2-D15、AF-D14からAF-D17、詳細設計AI基盤、Phase 2実行計画書
- 変更理由: モジュール構造図から、部品の接続だけでなく、部品間で渡す依頼・データ・用途・停止条件を追えるようにする。

## 採用した表現

構造図を別形式へ置き換えず、Mermaidのフローチャートを維持した。各実線矢印には短い受渡し名を付け、図の直後に次の4列を持つ表を置いた。

| 列 | 記載する内容 |
|---|---|
| 送る部品 | どの部品が情報を渡すかを、図のノード名と一致させて記す。 |
| 受け取る部品 | どの部品が情報を受け取るかを、図のノード名と一致させて記す。 |
| 渡すデータ・依頼 | 契約名だけで済ませず、何を含むかを日本語の文章で記す。 |
| 受け取り側の用途と停止条件 | 受け取った情報を何に使い、欠落・不明・不整合時に何を止めるかを日本語の文章で記す。 |

ノードへ長文を詰め込む方式は、文字見切れと読みにくさを招くため採用しない。受渡しが存在しない場合だけ、理由・確認者を付けた `N/A` を認める。秘密、認証値、口座情報は図・表に記録しない。

## 反映成果物

- P2-D05 v0.6: 取得依頼、確認済み依頼、元データ、利用可否、銘柄観測の受渡しを可視化した。
- P2-D06 v0.4: 元データ識別子、台帳版、正規化行、品質報告、データ版、差分の受渡しを可視化した。
- P2-D07 v0.4: 外部記号観測、営業日・契約属性、台帳版、検索結果、停止理由、監査情報の受渡しを可視化した。
- AF-D14からAF-D17、`settings/ai_component_rules.md`、詳細設計用Skill、A82、A91、専用Orchestrator、AI基盤仕様書群、P2-03Rプロンプトへ、同じ必須条件を反映した。

## 確認結果

| 観点 | 結果 |
|---|---|
| P2-D05からP2-D07の構造図 | 各図の実線矢印に短い受渡し名を付け、直後にモジュール間データ受渡し表を置いた。 |
| 可読性 | 詳細説明を表へ分離し、ノード内の文字量を増やしていない。 |
| AI基盤 | 作成Skill、レビューSkill、A82、A91、専用Orchestrator、テンプレート、依頼プロンプト、ルールのすべてに同じ条件を記録した。 |
| 発火制御 | 新規AI部品は作成せず、既存の詳細設計AI基盤のみを更新した。`default_orchestrator` は変更していない。 |
| Unknown | 受渡し内容が未確定な箇所は、既存のUnknownと停止・縮退方針を維持し、Pass扱いにしていない。 |
