# 中学生向け解説ドキュメント生成システム構築計画

## 1. この計画の目的

`research/タートルズ・トレンドフォロー戦略.md` の第3章から第11章を、中学生でもわかる解説文書に変換するための仕組みを作る。

この計画では、いきなり章を書き換えない。まず、必要な `agent skills`、サブエージェント、オーケストレータを作成する。その後、ユーザーが次のように指示するだけで、指定範囲の章を並列処理できる状態にする。

```text
research/タートルズ・トレンドフォロー戦略.md の 3～5 章を中学生でも分かるように解説して
```

この指示を受けたら、オーケストレータが対象章を分解し、各サブエージェントを並列に動かし、章ごとの成果物を `research` ディレクトリに保存する。

## 2. 最終的に作りたい仕組み

### 2.1 実行イメージ

ユーザー:

```text
research/タートルズ・トレンドフォロー戦略.md の 6～8 章を中学生でも分かるように解説して
```

オーケストレータ:

```text
第6章、第7章、第8章を処理対象として認識する。
各章ごとに作業ジョブを作る。
章ごとのサブエージェント群を並列で起動する。
レビューと修正まで完了した最終版を research に保存する。
```

出力例:

```text
research/中学生向け_第06章_リスク管理とストップロス.md
research/中学生向け_第07章_エグジットルール.md
research/中学生向け_第08章_ドローダウン対策.md
```

### 2.2 モデル指定

| 役割 | 使用モデル |
|---|---|
| オーケストレータ | gpt-5.6-luna |
| サブエージェント | gpt5.4 |

## 3. 作成する agent skills

最初の数ステップで、次の agent skills を作成する。

| skill 名 | 役割 |
|---|---|
| `chapter-range-parser` | ユーザー指示から対象ファイルと章範囲を読み取る |
| `chapter-extractor` | Markdown 原文から指定章だけを切り出す |
| `middle-school-rewriter` | 原文を中学生向けの超わかりやすい文章に直す |
| `formula-free-explainer` | 数式、記号、難語を使わずに説明し直す |
| `student-reviewer` | 中学生が理解できるかをレビューする |
| `fidelity-reviewer` | 原文の意味が変わっていないかをレビューする |
| `revision-integrator` | レビュー結果を反映して最終版に直す |
| `research-file-writer` | 最終版を `research` ディレクトリに保存する |
| `final-output-auditor` | 指定範囲の全成果物を最終確認する |

## 4. 作成するサブエージェント

最初の数ステップで、次のサブエージェントを作成する。

すべて `gpt5.4` で実行する。

| サブエージェント名 | 使用 skill | 担当 |
|---|---|---|
| Range Parser Agent | `chapter-range-parser` | 指示文からファイルパスと章範囲を取り出す |
| Chapter Extractor Agent | `chapter-extractor` | 章本文を抜き出す |
| Explainer Agent | `middle-school-rewriter` | 初稿を作る |
| Formula Cleaner Agent | `formula-free-explainer` | 数式なしの説明に整える |
| Student Review Agent | `student-reviewer` | わかりやすさを確認する |
| Fidelity Review Agent | `fidelity-reviewer` | 原文とのズレを確認する |
| Revision Agent | `revision-integrator` | レビュー結果を反映する |
| File Writer Agent | `research-file-writer` | 成果物を保存する |
| Final Audit Agent | `final-output-auditor` | 全ファイルを確認する |

## 5. 作成するオーケストレータ

最初の数ステップで、`Middle School Explanation Orchestrator` を作成する。

モデルは `gpt-5.6-luna` とする。

役割:

- ユーザーの章範囲指定を受け取る
- `Range Parser Agent` に対象範囲を解析させる
- 指定された各章ごとに処理ジョブを作る
- 各章の処理を並列実行する
- 各章内で、抽出、初稿、数式除去、レビュー、修正、保存を順番に進める
- すべての章が保存されたら `Final Audit Agent` に確認させる
- 不合格ファイルがあれば修正ループを回す
- 最終的な作成ファイル一覧を報告する

## 6. フェーズ1: 実行基盤を作成する

次の skills を作成する前提で、それぞれの役割、入力、出力、禁止事項、品質基準を定義してください。

- chapter-range-parser
- chapter-extractor
- middle-school-rewriter
- formula-free-explainer
- student-reviewer
- fidelity-reviewer
- revision-integrator
- research-file-writer
- final-output-auditor

制約:

- 投資助言にしない
- 原文の意味を変えない
- 保存先は research ディレクトリにする

- fidelity-reviewer
- revision-integrator

## 8. 章ごとの内部処理フロー

オーケストレータは、指定された各章について次の流れを実行する。

```text
Chapter Extractor Agent
  ↓
Explainer Agent
  ↓
Formula Cleaner Agent
  ↓
Student Review Agent
  ↓
Fidelity Review Agent
  ↓
Revision Agent
  ↓
File Writer Agent
```

`Student Review Agent` と `Fidelity Review Agent` は、同じ本文を対象に並列で動かしてよい。

各章の処理は互いに独立しているため、第3章、第4章、第5章のような複数章指定では、章単位のジョブを並列実行する。

## 9. 各章成果物のフォーマット

各章の Markdown は、次の形に統一する。

```markdown
# 第X章 タイトル

## この章でわかること

- この章で理解するポイントを3つから5つ書く

## まず一言でいうと

この章の結論を、中学生向けに短く書く。

## やさしい解説

数式を使わず、短い文で説明する。

## たとえ話

学校、部活、ゲーム、天気、買い物など、身近な例で説明する。

## 気をつけること

誤解しやすい点やリスクを説明する。

## この章のまとめ

- 最後に覚えることを3つから5つ書く
```

## 10. 品質基準

最終成果物の合格条件:

- 数式が残っていない
- 変数や記号に頼った説明がない
- 中学生が読める文の長さになっている
- 専門用語には説明がある
- 原文の重要な意味が保たれている
- リスク説明が弱くなっていない
- 投資助言になっていない
- 章ごとのファイルが `research` に保存されている
- 原文ファイルを変更していない

目標スコア:

| 評価項目 | 合格ライン |
|---|---:|
| 中学生向け理解度 | 85点以上 |
| 原文忠実性 | 90点以上 |
| 最終監査 | 合格 |

## 11. 修正ループ

レビューで合格ラインを下回った場合、オーケストレータは対象章だけを修正ループに戻す。

```text
Revision Agent
  ↓
Student Review Agent
  ↓
Fidelity Review Agent
  ↓
File Writer Agent
  ↓
Final Audit Agent
```

修正ループは最大3回まで行う。

3回でも合格しない場合、オーケストレータは次を記録する。

- 対象章
- 合格できなかった理由
- 人間に確認してほしい点
- 現時点の暫定ファイル
