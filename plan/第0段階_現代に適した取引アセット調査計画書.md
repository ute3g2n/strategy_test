# 第0段階 現代に適した取引アセット調査計画書

## 目的

タートルズ・トレンドフォロー戦略を現代の自動売買システムで運用するため、API取引、データ取得、証拠金、小口資金、流動性、分散価値の観点から候補資産を調査する。

## 最終成果

- 最終候補: 30から50件
- 初期候補: 3から5件
- 候補単位: エクスポージャー × 取引手段 × Broker/Venue

## 工程

| ステップ | 日本語名 | 目的 | Human Gate |
|---|---|---|---|
| P00 | 実行基盤確認 | フォルダ、スキーマ、ログを準備 | なし |
| P01 | 調査憲章作成 | 調査範囲、Gate、Scorecardを固定 | H0 |
| P02 | 分類とスキーマ | 資産分類、候補スキーマ、証拠スキーマを固定 | なし |
| P03 | 候補ロングリスト | 公式情報から広い候補群を作る | H1 |
| P04 | 証拠検証 | Broker/API/日本居住者可否の証拠を確認 | なし |
| P05 | エクスポージャーと取引手段の対応 | 重複と代替関係を整理 | なし |
| P06 | ハードゲート | 資金・証拠金・N計算可否を判定 | H2 |
| P07 | データベンダー | データ取得可否、費用、品質を調査 | なし |
| P08 | 構造スコア | Backtest前の構造評価 | なし |
| P09 | バックテスト手順 | 試行回数、Holdout、ルールを固定 | H3 |
| P10 | 頑健性バックテスト | 固定手順でBacktestを行う | なし |
| P11 | ポートフォリオ選定 | 30から50件へ整理 | なし |
| P12 | レッドチーム監査 | 情報源、Bias、計算を監査 | H4 |
| P13 | 最終選定 | 初期3から5件と実装準備を凍結 | H5 |

## 重要ルール

- Backtest結果で候補を作らない。
- 候補別にパラメータ最適化しない。
- 不明な重要情報を通過扱いにしない。
- 証拠金、N/ATR、契約倍率、最小数量が不明な候補はP06を通過できない。
