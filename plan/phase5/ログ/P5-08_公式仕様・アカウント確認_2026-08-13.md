## 公式情報から確認できたこと

| 項目 | 確認結果 |
|---|---|
| Historical API | `https://hist.databento.com/v0/`形式のHTTP API。 |
| 認証 | API keyで認証し、公式clientは`DATABENTO_API_KEY`環境変数を利用できる。Secret値を文書・ログへ保存しない。 |
| Dataset | Dataset IDは`PUBLISHER.DATASET`形式で、`GLBX.MDP3`は公式Dataset IDの例として記載されている。 |
| 課金 | Historicalは使用量ベースで、データの未圧縮binary sizeを基準に課金される。metadata、symbology、account管理は無料と説明されている。 |
| Batch／streaming | Batchはリクエスト単位、streamingは送信データ単位で扱われるため、Runnerでは実行後usage監査を保存する。 |
| ライセンス | 再配布条件はDatasetごとの元出版社のライセンスに依存する。一般公開情報だけでP5の内部利用権限を確定しない。 |
| 無料credits | 新規ユーザー向けcreditsの記載はあるが、現在のアカウント残高・有効期限を公開情報から推測しない。 |

## 個別アカウントで確認する項目

次の値は、アカウント画面またはアカウント由来のsanitized metadataで確認し、Secret値・Account ID・決済情報は保存しない。

- `GLBX.MDP3`、`definition`、`ohlcv-1m`、`statistics`、TBBO pilotの利用可否。
- `2025-02-24T00:00:00Z`〜`2026-08-01T00:00:00Z`の期間利用可否。
- Historical only、Liveなし、外部再配布なしの契約・ライセンス。
- Provider／チームbudget controlの25 USD／50 USD設定と80%警告・100%停止。
- `DATABENTO_API_KEY`の用途、期限、mask、rotate／revoke監査。

## 結論

公式公開情報はP5-DATA-G1のProvider／Endpoint／認証／課金方式の一般仕様を裏付ける。個別entitlement、契約、残高、budget control、Secret metadataは未確認であり、P5-08の実行前にアカウント側の証跡を埋める必要がある。費用見積りは開始必須条件から除外したが、費用上限と実行後usage監査は維持した。

## ローカル安全確認

- `DATABENTO_API_KEY`はプロセス／ユーザー環境に存在することだけを確認した。Secret値は表示・保存・Evidence化していない。
- この確認から、個別アカウントのentitlement、契約、残高、期限、budget control、host isolationが確認済みになったとは扱わない。
- 外部I/O、Provider接続、費用発生、Data取得は0件。Runnerの標準モードはlocal dry-runである。
