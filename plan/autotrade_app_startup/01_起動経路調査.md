## 1. 中学生向けの全体像

このアプリは、1個のファイルだけでできているわけではない。画面を表示する部品と、Backtestの計算を受け付ける部品が別々に動く。

- **UI**: ブラウザに見える画面。Viteのpreviewで配信する。
- **API**: UIから受けた「計算して」というお願いを処理する窓口。Pythonで動く。
- **build**: UIのソースコードを、ブラウザが読める完成ファイルへ変換する作業。
- **health check**: 「その部品が生きていて返事をできるか」を確認する短い質問。

したがって、利用者が画面を使うには、build、API起動、UI起動、health確認、ブラウザ起動を順番に行う必要がある。これを1個のbatから呼び出す。

## 2. 確認した起動部品

| 部品 | 現状 | 一括起動での扱い |
|---|---|---|
| UI build | `ui/mock/package.json`の`build` | 毎回起動時に実行し、最新ソースを配信する |
| UI preview | `npm run preview -- --host 127.0.0.1` | 4173で別プロセスとして起動 |
| Application API | `py -3 scripts/phase5r/backtest_api_server.py --port 8765` | 8765で別プロセスとして起動 |
| ブラウザ | `http://127.0.0.1:4173` | 両health成功後に既定ブラウザで開く |
| 依存 | `ui/mock/node_modules` | なければ`npm ci`。lockfile以外の依存指定はしない |
| Python | `.venv/Scripts/python.exe`または`py -3` | venvを優先し、なければPython Launcherを確認 |

## 3. 失敗時の考え方

| 失敗 | 利用者への説明 | 自動でしてよいこと |
|---|---|---|
| Pythonなし | Pythonを入れてから再実行 | 停止 |
| npmなし | Node.js/npmを入れてから再実行 | 停止 |
| 依存なし | `npm ci`が必要 | lockfileに従って実行 |
| build失敗 | UIが古いままなので起動しない | 停止、build logを案内 |
| 8765競合 | API以外が同じポートを使っている可能性 | 何もkillせず停止 |
| 4173競合 | UI以外が同じポートを使っている可能性 | 何もkillせず停止 |
| health timeout | 部品が起動できていない | logを案内して停止 |

## 4. Step 1結論

PowerShellを本体にすることで、batの複雑な引用符処理を減らし、プロセス、ログ、終了コード、待機、ポート確認を扱いやすくする。batは利用者がダブルクリックする入口に限定する。停止処理も別のbat入口を用意する。
