# Language Rules

このプロジェクトでは、生成物は原則として日本語で作成する。

## 日本語で作成するもの

- 計画書、要件定義書、設計書、調査レポート、運用メモ
- Markdown、CSV、ログ、チェックリスト、承認依頼、レビュー結果
- AIエージェント向けのプロンプト、手順書、引き継ぎ資料
- ユーザー向けの説明、要約、判断材料

## 例外

- 実装コード、設定ファイル、API名、ライブラリ名、コマンド、識別子、URL、Stable ID は、必要に応じて英語または既存形式を維持する。
- 既存コードや既存仕様が英語命名を前提としている場合は、その一貫性を優先する。
- 外部サービス、取引所、Broker、商品名、シンボルなどの正式名称は、誤解を避けるため原文を併記または維持してよい。

## 判断基準

日本語化によって追跡性、実行可能性、コード互換性、外部仕様との対応が壊れる場合は、英語のIDや正式名称を残す。ただし、その意味を説明する文章は日本語で書く。

## 指摘・リスクの説明

- レビュー、レッドチーム監査、Blocked、Unknown、Human Gateの指摘は、技術者向けの正確な記述に加えて「中学生でも分かる説明」を必ず併記する。
- やさしい説明には、何が起きるか、なぜ危険か、何を確認すれば進めるかを短い日本語で書く。専門用語をなくすのではなく、用語の意味を具体例で補う。
- 台帳、HTML、Markdownのどれでも同じルールを適用し、承認者が専門知識なしに停止理由と再開条件を把握できるようにする。
- 説明用の列を増やして表を横に広げず、「問題内容」と「修正方針」の欄に、元の記述の直下へやさしい説明を置く。
- 人による承認の欄は、承認者が行動を理解できる日本語で書く。「Human Gate」「handoff禁止」などの英語だけの表現は避け、「H2-3の承認が必要」「Phase 3への引渡しを禁止」のように記載する。識別子やコード名は追跡性のため残してよい。

## ディレクトリ運用ルール

- `plan/` は計画書、要件定義、実行プロンプト、承認条件、進行管理メモを置く場所とする。
- 設計書ドキュメント類の正式成果物である `.html` ファイルは `doc/` 配下へ保存する。
- Phase単位の設計書HTMLは、原則として `doc/phaseX/` 配下へ保存する。
- 補助ログ、CSV、作業中の台帳、実行記録は、必要に応じて `plan/` または用途別ディレクトリへ置いてよい。
- `doc/` 配下のすべてのHTML成果物は、単一の `doc/index.html` からリンクで到達できるようにする。
- 新しいHTML設計書を追加した場合は、同時に `doc/index.html` のリンク一覧も更新する。
