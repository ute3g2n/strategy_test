# Agent Skills 設計定義

## 1. 目的

`research/タートルズ・トレンドフォロー戦略.md` の指定章を、中学生向けの解説ドキュメントへ変換するために必要な agent skills を定義する。

この設計は、後続ステップで実際の skill、サブエージェント、オーケストレータを作成するための仕様として使う。

共通制約:

- 最終成果物に数式を残さない
- 投資助言にしない
- 原文の意味を変えない
- 保存先は `research` ディレクトリにする
- 原文ファイルは変更しない
- 章ごとの成果物は Markdown 形式にする

## 2. `chapter-range-parser`

### 役割

ユーザーの自然文指示から、対象ファイルと章範囲を読み取る。

例:

```text
research/タートルズ・トレンドフォロー戦略.md の 3～5 章を中学生でも分かるように解説して
```

この指示から、対象ファイル、開始章、終了章、実行目的を取り出す。

### 入力

- ユーザー指示文
- デフォルト対象ファイル
- 許可する章範囲

### 出力

```yaml
source_file: research/タートルズ・トレンドフォロー戦略.md
start_chapter: 3
end_chapter: 5
chapters:
  - 3
  - 4
  - 5
task: middle_school_explanation
```

### 禁止事項

- 指定されていない章を勝手に追加しない
- `research` 外の保存先を許可しない
- 存在しない章を有効な章として扱わない
- 章範囲があいまいな場合に推測だけで実行しない

### 品質基準

- ファイルパスを正確に抽出できる
- `3～5`、`3-5`、`3から5`、`第3章から第5章` のような表記を扱える
- 単章指定にも対応できる
- 範囲外の章が指定された場合はエラーを返す
- 後続エージェントが使いやすい構造化データを返す

## 3. `chapter-extractor`

### 役割

Markdown 原文から、指定された章だけを正確に切り出す。

### 入力

- 原文ファイルパス
- 対象章番号
- 次章番号
- 章見出しの検出ルール

### 出力

```yaml
chapter_number: 3
chapter_title: ボラティリティとポジションサイジング
source_excerpt: |
  # 3. ボラティリティとポジションサイジング
  ...
section_headings:
  - 3.1 True Range
  - 3.2 Nの計算式
important_points:
  - 値動きの大きさに応じて取引量を調整する
  - 1 Unit は最大損失1%という意味ではない
```

### 禁止事項

- 対象章以外の本文を混ぜない
- 見出しだけを抜き出して本文を省略しない
- 原文を要約して出力しない
- 文字化けした本文をそのまま渡さない

### 品質基準

- 対象章の開始見出しから次章直前までを抽出する
- UTF-8 として正しく読み取る
- 章タイトルと節見出しを正確に取得する
- 後続の書き換えで落としてはいけない重要点を列挙する

## 4. `middle-school-rewriter`

### 役割

抽出した章本文を、中学生でも理解できる初稿に書き換える。

### 入力

- 対象章の原文
- 章タイトル
- 重要点一覧
- 出力フォーマット

### 出力

Markdown の中学生向け初稿。

基本構成:

```markdown
# 第X章 タイトル

## この章でわかること

## まず一言でいうと

## やさしい解説

## たとえ話

## 気をつけること

## この章のまとめ
```

### 禁止事項

- 数式を使わない
- 原文の意味を変えない
- 投資をすすめる表現を入れない
- 「必ず勝てる」「安全にもうかる」などの断定をしない
- 専門用語を説明なしで使わない
- 長い一文を続けない

### 品質基準

- 1文を短くする
- 最初に章の結論を示す
- 専門用語は日常語で説明する
- 例え話を入れる
- 原文の重要点を落とさない
- リスク説明を弱めない

## 5. `formula-free-explainer`

### 役割

中学生向け初稿から、数式、記号中心の説明、難しすぎる表現を取り除く。

### 入力

- 中学生向け初稿
- 用語置換ルール
- 禁止表現リスト

### 出力

数式なしに整えた Markdown。

### 禁止事項

- 数式を残さない
- 変数名だけで説明しない
- 記号や英字略語を説明なしで使わない
- 原文にない意味を足して簡単にしない
- 表だけで説明を終わらせない

### 品質基準

- `N` は「最近の値動きの大きさを表す目安」と説明する
- `Unit` は「一度に持つ取引量のまとまり」と説明する
- `ストップ` は「損が大きくなりすぎる前にやめる線」と説明する
- `ブレイクアウト` は「今までの値動きの範囲を外に抜けること」と説明する
- `ドローダウン` は「資金が一時的に大きく減ること」と説明する
- 数式が完全に消えている
- 数式を消しても、意味が大きく崩れていない

## 6. `student-reviewer`

### 役割

中学生の読者目線で、文章のわかりやすさをレビューする。

### 入力

- 数式なしに整えた本文
- 対象章番号
- 対象読者レベル

### 出力

```yaml
score: 88
good_points:
  - 章の結論が最初にある
  - たとえ話が自然
required_fixes:
  - 「相関」の説明がまだ難しい
suggested_revisions:
  - 「同じように動きやすい関係」と説明する
pass: true
```

### 禁止事項

- 原文忠実性だけを見てレビューしない
- 専門家向けの文体をよしとしない
- 難しい言葉を別の難しい言葉で置き換えない
- 投資成果を期待させる方向に直さない

### 品質基準

- 中学生が最初から最後まで読めるかを評価する
- 難しい用語を具体的に指摘する
- 修正案を実際に使える文章で出す
- 100点満点で採点する
- 85点以上を合格とする

## 7. `fidelity-reviewer`

### 役割

原文と中学生向け本文を比較し、意味が変わっていないかをレビューする。

### 入力

- 対象章の原文
- 中学生向け本文
- 章の重要点一覧

### 出力

```yaml
score: 92
preserved_points:
  - 値動きに応じて取引量を変える考え方が残っている
missing_or_weakened_points:
  - ギャップで損失が予定より大きくなる説明が弱い
required_fixes:
  - ストップは損失を保証しない点を追加する
pass: true
```

### 禁止事項

- わかりやすさだけを優先して、原文の意味の変化を見逃さない
- 原文にない断定を許可しない
- リスク説明の弱体化を許可しない
- 投資助言のような表現を許可しない

### 品質基準

- 原文の重要点が残っている
- 重要な注意点が削られていない
- 数式を消したことで不正確になっていない
- 原文にない約束や断定が追加されていない
- 100点満点で採点する
- 90点以上を合格とする

## 8. `revision-integrator`

### 役割

`student-reviewer` と `fidelity-reviewer` のレビュー結果を反映して、最終版の本文を作る。

### 入力

- 数式なしに整えた本文
- student review 結果
- fidelity review 結果
- 対象章の重要点一覧

### 出力

最終版 Markdown。

### 禁止事項

- レビュー指摘を無視しない
- 修正で数式を復活させない
- 原文の意味を変えない
- 読みやすさのためにリスク説明を削らない
- 投資をすすめる表現を追加しない

### 品質基準

- 必須修正点が反映されている
- わかりやすさと正確さの両方が改善している
- 見出し構成が統一されている
- 章末に「この章のまとめ」がある
- 最終成果物としてそのまま保存できる

## 9. `research-file-writer`

### 役割

最終版 Markdown を、指定された `research` ディレクトリ配下のファイルに保存する。

### 入力

- 最終版 Markdown
- 出力ファイルパス
- 対象章番号
- 上書き可否

### 出力

```yaml
written: true
path: research/中学生向け_第03章_ボラティリティとポジションサイジング.md
encoding: UTF-8
```

### 禁止事項

- `research` ディレクトリ外に保存しない
- 原文ファイルを変更しない
- 指定と異なるファイル名で保存しない
- 空ファイルを成功扱いしない

### 品質基準

- UTF-8 で保存する
- Markdown として読める
- 出力ファイル名が章番号と一致している
- 保存後にファイル存在確認を行う
- ファイルサイズが極端に小さくない

## 10. `final-output-auditor`

### 役割

指定章範囲の最終成果物がそろい、品質基準を満たしているかを確認する。

### 入力

- 対象章一覧
- 期待される出力ファイル一覧
- 保存済みファイル一覧
- 品質基準

### 出力

```yaml
pass: true
checked_files:
  - research/中学生向け_第03章_ボラティリティとポジションサイジング.md
missing_files: []
files_requiring_revision: []
summary: すべての対象章ファイルが存在し、数式なし、投資助言なし、指定フォーマットで保存されています。
```

### 禁止事項

- ファイル未作成を合格にしない
- 数式が残っているファイルを合格にしない
- 投資助言のような表現を見逃さない
- 原文ファイルの変更を見逃さない
- 章番号とファイル名の不一致を見逃さない

### 品質基準

- 指定範囲の全ファイルが存在する
- 各ファイルが指定フォーマットに従っている
- 数式が残っていない
- 投資助言ではない
- 原文の意味が大きく変わっていない
- リスク説明が弱くなっていない
- 原文ファイルが変更されていない

## 11. Skill 間の受け渡し

全体の受け渡しは次の順序で行う。

```text
chapter-range-parser
  ↓
chapter-extractor
  ↓
middle-school-rewriter
  ↓
formula-free-explainer
  ↓
student-reviewer
  ↓
fidelity-reviewer
  ↓
revision-integrator
  ↓
research-file-writer
  ↓
final-output-auditor
```

`student-reviewer` と `fidelity-reviewer` は、同じ本文を対象に並列実行できる。

章範囲が複数指定された場合、`chapter-extractor` 以降の処理は章ごとに独立して並列実行する。

## 12. 完了条件

この設計ステップは、次の条件を満たしたら完了とする。

- 9個の agent skills の役割が定義されている
- 各 skill の入力と出力が定義されている
- 各 skill の禁止事項が定義されている
- 各 skill の品質基準が定義されている
- 後続の skill 作成ステップでそのまま使える粒度になっている
