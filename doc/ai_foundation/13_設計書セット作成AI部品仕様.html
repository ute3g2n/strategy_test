13 設計書セット作成AI部品仕様

文書ID: AF-D13
作成日: 2026-08-04
文書状態: v0.1 / 設計書セット作成AI部品 反映済み
対象: autotrade_skill_design_doc_set_writer_v0_1, AutoTrade_A81_DesignDocSetWriter_v0_1, AutoTradeProject_DesignDocSet_Orchestrator_v0_1

1. 目的

Phase 2以降では、1つのPhase内で複数の正式HTML設計書を作成する場面が多い。本仕様は、複数HTMLを個別作成で散らさず、設計書セットとして共通メタ情報、相互リンク、追跡ID、Unknown、レビュー履歴、doc/index.html 導線を揃えるためのAI部品を定義する。

2. 再利用判断

既存部品再利用する責務不足した責務
AutoTrade_A80_DocumentIntegrator_v0_1単体HTML作成、レビュー反映、index更新。Phase内の複数設計書をセット単位で整合させる責務が弱い。
autotrade_skill_html_doc_writer_v0_1単体HTMLの必須構成と導線維持。文書セット全体の共通メタ、相互リンク、成果物ID対応表の統制が不足。
AutoTradeProject_Orchestrator_v0_1Phase横断のDAG、Gate、レビュー統合。設計書大量作成ステップだけを軽く回す専用Runbookがない。

5. 標準フロー

1. Validate explicit component names and Phase Runbook
2. Load document set plan, sources, existing HTML, and doc/index.html
3. Extract requirements, decisions, Unknowns, and artifact IDs
4. Draft or update the HTML document set
5. Run design review and red-team review
6. Integrate adopted findings with revision records
7. Update doc/index.html and record Human Gate status

6. 停止条件

  • 指定AI部品が存在せず、現在ステップが作成ステップでもない。
  • 設計書セットの対象範囲を入力から推定できない。
  • 正式HTMLが doc/index.html から到達不能になる。
  • UnknownをPass扱いしないと成果物を完了できない。
  • Secret、API key、Account IDをHTMLやログへ出す必要がある。
  • default_orchestrator 変更が必要になる。

7. Phase 2への適用方針

Phase 2では、P2-D01からP2-D08、およびP2-D11からP2-D15のような設計・レビュー・完了判定HTML群に適用する。P2-05やP2-07の実装そのものは AutoTradeProject_Orchestrator_v0_1 を中心に扱う。実装担当者が直接使う詳細設計は、本部品だけで完結させず、AF-D15 実装詳細設計AI基盤仕様を併用する。
