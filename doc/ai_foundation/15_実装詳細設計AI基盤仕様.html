3. 実行フロー

1. Validate explicit component names and Runbook
2. A10: extract requirements, decisions, Unknowns, repository constraints
3. A20/A40/A50: provide approved domain-specific decisions
4. A82: make DD-01..DD-12 coverage matrix and draft detailed design set
5. A91: detailed-design completeness review (findings first)
6. A90 + Red Team: cross-document, safety, traceability review
7. A80 + A81: adopt findings, revise HTML, update links and history
8. A91: re-review revised coverage matrix
9. Record residual Unknowns, Human Gate, implementation handoff in plan/
10. Update doc/index.html and stop only when completion gate is met

6. レビュー・改訂の強制条件

段階必須確認未達時
A91初回レビューDD-01からDD-12の充足、N/A理由、実装影響。Fail。A82/A80/A81へ改訂指示を返す。
A90/Red Team領域整合、安全、Secret、fail-closed、追跡、危険な先送り。FailまたはHuman Gate。実装へ渡さない。
改訂統合指摘ごとの採用/部分採用/保留/却下理由、HTML・リンク・Unknown更新。採否表不足としてFail。
A91再レビュー改訂後の同一カバレッジ表、Critical/High 0件。再改訂。完了宣言禁止。

7. Human Gate

外部API実取得、費用、Secret、実装言語/永続化方式の選択、後方互換性を壊すmigration、roll等の業務判断は人間承認対象とする。詳細設計AI基盤は承認判断を代行せず、承認対象と未承認時の停止・縮退を記録する。
