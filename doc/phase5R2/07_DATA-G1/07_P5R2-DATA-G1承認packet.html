状態：APPROVED_BOUNDED_P5R2_18
利用者から移譲されたP5R2 Human Gate権限に基づき、下記のbounded pilotだけを承認した。無制限のProvider利用、他銘柄・他期間への拡張、Data再配布、Secret、費用、P6開始は承認していない。

1. このpacketで判断すること

判断対象は、P5R2-18で実Providerからsource 1mを限定取得し、品質検査後にlocal Catalogへ昇格する範囲である。上位足をProviderから直接取得せず、取得した1m sourceからアプリ内で15m／30m／1h／4h／1dを生成する。P5R2-19以降のUI、DELETE-G1、H2、P6の承認はこのpacketの対象外である。

2. 推奨する承認範囲

既存P5のProvider方針転換履歴と、今回のP5R2要件をつなぐ最小の受入範囲として、次を推奨する。これは「全銘柄・全期間」の無制限承認ではなく、動作と停止条件を確認するbounded pilotである。

4. 取得後の昇格条件

  1. download jobをSTAGEDで受理し、対象URL、symbol、market、interval、UTC範囲、Run、Evidence rootを記録する。
  2. zipをstagingへ排他的に保存し、CHECKSUMが存在する場合はsource-data integrityのために検査する。これは管理用hashやreceipt hashではない。
  3. CSVを展開し、schema、timestamp unit、UTC昇順、重複、始端・終端、欠損、OHLC／Volume品質を検査する。欠損を勝手に埋めない。
  4. 検査に合格したsourceだけをCatalog previewへ束縛し、promotionをatomicに行う。失敗・cancel・再起動・途中停止はRECOVERY_REQUIREDまたはusable=falseにする。
  5. source 1mからだけ上位5時間足を生成し、provenance、期間、quality、source identityをCatalogへ表示する。競合値は利用者の明示replaceなしに上書きしない。

7. P5R2-18の停止・rollback

  • 承認外host、symbol、期間、interval、URL、redirect、proxy、Secret、課金表示が一つでも出たら、そのHTTP requestを継続せず停止する。
  • partial downloadはstagingのままにし、Catalog current／usableへ公開しない。復旧不能ならstagingを隔離し、DELETE-G1未承認の既存保存物を削除しない。
  • 値競合、重複、欠損、timestamp unit不一致、schema不一致、source integrity不一致はSTOP／UNUSABLEとする。補間はP5R2-CREQ-TF-002のlocal derived規則に限る。
  • 外部RunのEvidenceはlocal fixed GateのEvidenceと混ぜない。完了後もprovider termsがUnknownなら、Unknownを解消済みと書かない。
