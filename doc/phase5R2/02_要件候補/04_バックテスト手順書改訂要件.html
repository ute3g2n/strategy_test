文書ID: P5R2-ART-04 ／ Phase: P5R2 ／ Step: P5R2-04 ／ 作成日: 2026-08-22 ／ 状態: CANDIDATE / NOT_CURRENT / P5R2-HREQ_UNAPPROVED

対象Manual: 01_バックテスト手順書 v0.5。この文書は改訂の要件であり、Manual本体、画像、Playwright、Testは変更しない。

P5RのManual v0.5は当時の完了成果物として残す。P5R2-HREQ/H1/H2未承認のまま、新機能を「現在使える」と書いたり、未撮影の画像を完成扱いにしたりしない。

1. 改訂の原則

  1. 実装済み・検証済みの操作だけを成功手順として載せる。
  2. 画面名、ボタン名、API、画像、エラーコードは実装とassertで確認するまで候補として扱う。
  3. 各操作には「できること」「場所」「手順」「成功確認」「失敗時」「復旧」「してはいけないこと」「関係する受入条件」を置く。
  4. 画像は対象画面のDOM/assert成功後に撮影し、desktop/mobile、アクセシビリティ、外部通信0の確認先を残す。
  5. 結果非表示を物理削除と誤解させず、実削除はDELETE-G1承認後の別手順と明記する。

2. 現行Manualのtraceと改訂対象

現行箇所・用語現在の事実P5R2改訂要件反映条件
Spot / 1m / UTC、BT-MAN-07、PreflightP5R限定DataとUTC・品質を説明している。1mをsourceと説明し、戦略時間足15m/30m/1h/4h/1d、UTC anchor、指定終了と有効終了、closed barを追加する。TF UI/API/検証が完了し、実画面・エラー文言を確認後。
機能一覧・最短コース既存Backtest機能への導線がある。Historical Data取得、Data一覧、時間足生成を機能一覧と最短コースへ追加し、不足時の生成確認遷移を説明する。画面導線・状態・アクセシビリティ確認後。
品質・QUALITYエラー品質確認済みDataを使うことを説明している。USABLE_WITH_WARNINGとUNUSABLE、欠損・競合・provenance、警告を無視してはいけない理由を追加する。品質状態と表示内容のTest後。
履歴・比較・保存先・再起動復元Run結果、CSV、checkpoint、legacy/復元境界を説明している。DataSet ID/version、非重複期間マージ、旧version保持、結果非表示後も保存物が残ることを追加する。永続化・復元・比較のTest後。

削除に関する記述なし実削除の操作手順は現行Manualにない。結果サマリーの「削除」は表示非表示・再表示だけであることを掲載する。物理削除、Trash、purge、復元はDELETE-G1前に掲載しない。表示状態のTest・監査確認後。物理削除は別Gate後。
証跡・改訂履歴BT-MAN-01〜17と画像registry、Playwright記録を持つ。新規・改訂操作ごとにTest、画像、Evidence、受入条件、改訂日、未対応理由を追跡する。P5R2-H2前のManual受入時。

3. 新規・改訂する操作単位（候補）

Manual項目候補利用者が確認すること失敗・復旧必要な証拠候補
時間足を選んでSingle Backtestを開始する15m/30m/1h/4h/1dの一つ、1m sourceとの違い、UTC・有効終了。不足Data、partial bar、future data、範囲外を理由付きで止める。Preflight Test、画面assert、desktop/mobile画像。
不足時間足を生成する不足時のエラー、確認ダイアログ、銘柄引継ぎ、複数時間足・期間、既定の生成可能全期間。元1m不足、期間不正、Job失敗・取消時にRunを開始しない。遷移・状態Test、監査、画像。
Historical Dataを取得・一覧管理するJobとDataSetの違い、品質、coverage、version、legacy、警告。FAILED/PARTIAL/CANCELLED/CONFLICTをusableと見せず、再試行条件を示す。状態遷移・Catalog Test、監査、画像。
Runを取消するQUEUED/RUNNINGだけを取消し、3画面の表示が同じであること。二重押下、terminal、RECOVERY_REQUIRED、LEGACY_RESULT_ONLYを安全に扱う。idempotency・復元Test、監査、画像。
結果を非表示・再表示する結果サマリーだけから隠し、Run/Data/保存結果は残ること。物理削除と混同せず、再表示・監査を確認する。表示状態Test、監査、画像。

4. 用語・画像・Evidenceの必須改訂

区分追加・更新する内容禁止
用語strategy timeframe、1m source、derived Data、Download Job、DataSet、coverage、version、provenance、USABLE_WITH_WARNING、UNUSABLE、結果非表示、再表示を平易に説明する。「削除」を物理削除とだけ説明すること。
画像選択、生成確認、Catalog、警告、取消、非表示・再表示、失敗・復旧の各状態を実装後に撮影する。候補画面・ダミー画面を実機能の画像として載せること。
Evidence操作ごとにRequirement、Acceptance、Test、assert、画像registry、監査確認、改訂履歴へのリンクを残す。画像だけ、成功系だけで受入とすること。
