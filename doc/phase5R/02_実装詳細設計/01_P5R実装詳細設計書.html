やさしい要約：この設計は、画面の「開始」ボタンを押したら、画面が勝手に数字を作るのではなく、PythonのApplication APIが本物のローカルP5 Dataを読み、Backtestを計算し、結果と失敗理由を画面へ返す道筋を決める。外部Data、Broker、実注文は扱わない。

対象はP5R-AC-01〜16。対象Dataは既存ローカルP5 EvidenceのBTCUSDT/ETHUSDT、Spot、1m、UTC、半開区間[2025-02-24T00:00:00Z, 2026-08-01T00:00:00Z)だけである。成果物は実Application API、実UI、品質Evidence、Playwright画像付き手順書である。

2. ドメイン概要

Backtestは、過去の完成したローソク足を一つずつ「時間順に再生」し、そのとき出るSignal、仮想Fill、残高を記録する実験である。Runは一回の実験、Sweepは条件を少しずつ変えたRunの束、CSV Jobは結果表をファイルにする仕事、Holdoutは最後まで隠す確認用期間、Walk-forwardは時間をずらした複数の窓で同じ実験を繰り返す仕組みである。

6. 計算・保存・証跡

指標は同一Runのledgerから計算する。総損益は最終評価残高−初期残高、最大DDは残高の過去最高からの最大下落、勝率は確定した売買組のうち利益が正の割合、取引数は仮想Fill数、最終残高は最終時点の現金＋保有評価額である。fee/slippageは設定画面の仮定値として、各Fillに金額と計算根拠を残す。

Strategy Core接続：本体の各完成M1 Barは、選択した TURTLE_SYS1 または TURTLE_SYS2 とEntry/Exit期間を持つ StrategyConfig で、既存の autotrade.strategy.service.process_closed_bars に1本ずつ渡す。Coreが返した SignalEvent の理由・方向・Signal IDをLedgerへ保存し、そのSignalを仮想約定の入口／出口として同じRunの残高へ反映する。Coreの停止理由が返った場合はRunを成功にしない。BacktestRunner は入力Probeの契約検証にも使い、UIへはCore内部型を直接返さない。

保存物場所上書き保持
Run/Job/操作履歴ローカルApplication store禁止実行用目安30日。完了Evidenceは自動削除しない。
結果results/<run_id>/相対領域禁止Runと同じ保持目安。
CSVcsv/<job_id>/禁止Jobと同じ保持目安。
Evidencetests/evidence/phase5R/<RunId>/capture ID単位手動整理。外部共有なし。

7. 正常系・異常系フロー

sequenceDiagram
  participant U as UI
  participant A as Application API
  participant S as Service
  participant D as Local Data
  participant C as Core
  U->>A: preflight(spec)
  A->>S: validate typed spec
  S->>D: read approved local bars
  D-->>S: completed bars
  S-->>A: checks PASS
  U->>A: create/start Run
  A->>S: queue Run
  S->>C: replay bars in time order
  C-->>S: signal/fill/trace or STOPPED
  S-->>A: progress/result/failure
  A-->>U: RunView + metrics + provenance

Data不良、未来参照、範囲外、checkpoint不一致、結果欠落、CSV失敗、holdout早期参照は、理由コードを返して次の処理へ進めない。Unknownは表示してPassにしない。
