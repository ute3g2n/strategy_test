バックテスト手順書

最初に結論：この画面では、保存されている過去の市場Dataに、売買ルール（Strategy）を仮想的に当てはめて、「もし過去にこのルールを使っていたら、どんな結果になったか」を調べられます。実際の注文は出ません。将来の利益も保証しません。

この手順書は、投資を始めたばかりの人でも読めるように書いています。画面に出る英語や数字は残し、そのすぐ近くに意味を説明します。まず「できること一覧」から目的の機能を選び、その行のリンクから操作へ進んでください。

1. Backtestとは

1.1 何をする機能？

Backtest（バックテスト）は、過去の市場Dataを使う実験です。たとえば、過去の値動きが書かれたノートを1行ずつ読みながら、「このルールなら買う」「このルールなら売る」と仮想的に計算します。

入力するもの
  • 銘柄（BTCUSDTまたはETHUSDT）
  • 調べる期間（UTC）
  • Strategy（TURTLE_SYS1またはTURTLE_SYS2）
  • 初期残高、Entry／Exit lookback、Fee、Slippageの想定値
確認できるもの
  • 計算が安全に開始できたか
  • 計算中の進み具合
  • 5つの指標と、その計算の根拠
  • Signal、Virtual Fill、残高の時系列
  • 候補比較、Holdout、Walk-forwardの結果

1.2 この結果は現実の取引？

いいえ。結果は仮想結果です。過去に実際に注文した記録ではなく、過去のDataに現在のルールを当てはめて計算したものです。実際の市場では、価格の動き、注文の成立、手数料、通信などが違う場合があります。

投資の注意：Backtestの良い結果は、将来の利益を保証しません。良い期間だけを選んだり、結果を見ながら条件を何度も変えたりすると、実力以上に良く見えることがあります。Holdoutは、条件を決めた後の確認に使います。

次の表が、このBacktestモジュールで利用者ができることの全体です。目的に近い行を選び、青いリンクから操作へ進んでください。複数のリンクがある機能は、通常の操作と、失敗・復旧の操作を分けています。

IDこの機能でできることいつ使う？画面の場所操作手順成功の見方
BT-F-01Backtest画面と、使ってよいData・期間・安全境界を確認できます。最初に必ず確認します。画面上部、「P5R実行範囲」画面と条件を見るBTCUSDT／ETHUSDT、Spot、1m、UTC、期間、外部接続なしが表示される。
BT-F-02銘柄、期間、Strategy、初期残高、Entry／Exit lookback、Fee、Slippageを指定できます。調べる実験の条件を決めるとき。「Single Backtest条件」入力欄を読む ／ 条件を検査する入力値が画面に残り、Preflightへ送れる。
BT-F-03開始前に、入力の型・Data範囲・UTC・品質・未来参照を点検できます。Single Runを始める前。「開始前Preflight」Preflightを通す ／ 不正な入力を止める5つの検査がPASS、または停止理由が読める。
BT-F-041つの条件でBacktestを実行し、Run ID、状態、進捗、Bar数、ETAを確認できます。1つの条件を詳しく調べるとき。「Single Run開始」「実Run」Single Runを開始する実Run IDと、QUEUED／RUNNING／SUCCEEDEDなどの状態が表示される。
BT-F-05完了したRunの総損益、最大ドローダウン、勝率、取引回数、最終残高とDataの由来を確認できます。計算が終わった後、結果を読むとき。「Backtestの5指標」「結果Ledgerと由来」5指標を読む5指標と、期間・Data範囲・Core検証が同じRunに結び付いている。
BT-F-06Signal、Virtual Fill、残高／Equityを時刻順のLedgerで確認できます。指標の中身を確かめたいとき。「Detailsを読込」「結果Ledgerと由来」Ledgerを読む ／ CSVにするUTC時刻、銘柄、方向、価格、理由などの行を確認できる。
BT-F-07実行中のSingle Runを取消し、保存されたcheckpointから再開できます。時間を止めたいとき、途中から続けたいとき。「取消」「チェックポイントから再開」Single Runを取消する ／ Single Runを再開するCANCELLEDとcheckpoint、再開後のSUCCEEDED、再開回数を確認できる。
BT-F-08Sweepで現在の条件から2つの候補を作り、親Jobと子Runの結果を確認できます。Entry lookback候補をまとめて試すとき。「Sweep」タブSweepを実行する候補数、完了数、失敗数、各子Runの状態が表示される。
BT-F-09Sweepの一部失敗を隠さず、部分失敗として確認できます。候補の1つが失敗した場合の表示を確認するとき。「2番目の候補を意図的に失敗させる」部分失敗を見る親JobがPARTIAL_FAILED、失敗した子に理由が表示される。
BT-F-10Sweepを途中で取消し、親Jobと子Runの停止状態を確認できます。候補実験を途中で止めたいとき。「Sweep取消」Sweepを取消する親SweepがCANCELLEDになり、子Runの状態も残る。
BT-F-11過去のRun履歴を更新し、条件・状態・進捗・結果を開けます。前に実行した結果を見直すとき。「履歴・比較」タブ履歴を開くRun IDと条件を間違えずに再表示できる。
BT-F-12条件が合うRunを比較し、条件が合わない比較を拒否されたことも確認できます。2つの実験の違いを比べたいとき。「選択Runと比較」Runを比較するcomparable=true／falseと理由が表示される。最良Runは自動決定しない。
BT-F-13完了RunのLedgerを、時間のかかるCSV Jobとして作り、ダウンロードできます。表を保存したい、全行を調べたいとき。「CSV生成」「CSVダウンロード」CSVを作るCSV JobがSUCCEEDEDになり、ダウンロードリンクが出る。
BT-F-14確定前のHoldout（最後まで隠しておく評価用Data）へのアクセスを止められます。調整前に、評価用Dataを見ていないことを確認するとき。「確定前を試す」確定前Holdoutを止めるEARLY_HOLDOUT_ACCESSでSTOPPEDになる。
BT-F-15確定後のHoldoutを一度だけ評価し、調整へ再利用しないことを確認できます。条件を決めた後の最後の評価を行うとき。「確定後に評価」確定後Holdoutを評価するSUCCEEDED、行数、再利用しない表示が出る。二度目は止まる。
BT-F-16学習・検証・評価を時間順の3窓に分け、未来のDataを混ぜずに評価できます。1回の期間だけでなく、時間をずらして確かめたいとき。「Holdout・Walk-forward」タブWalk-forwardを実行する窓3、future_reference=false、holdout_reused=falseを確認できる。

3. できないことと安全範囲

項目この手順書での扱い初心者向けの意味
Data既存P5ローカルDataのみ。BTCUSDT／ETHUSDT、Spot、1分足、UTC、P5R許可期間。インターネットから新しいDataを取ってくる画面ではない。
実行仮想Fillによる過去Dataの計算。実際に買う・売る注文は出さない。
費用Fee・Slippageの想定値。本当に市場でその費用になると約束する数字ではない。
SweepBacktest専用の候補実験。複数人・複数Unitが同時に動く本番運用ではない。
下部の「画面の状態を確認」UIの表示状態を検査するテスト用表示。ここを切り替えても、Backtestの計算やRun状態は変わらない。
後続PhaseForward、Shadow、Paper、Live候補、小規模Live、通常Liveは別Phase。実注文や実資金も扱わない。Backtestの成功だけで本番運用へ進まない。
停止の基本：PreflightがSTOPPED、Core検証が失敗、結果が未完了、Holdoutが確定前などの場合は、無理に先へ進みません。表示された理由を記録し、入力や状態を直してから再確認します。

4. 初めての人の最短コース

まず通常の1回のBacktestを最後まで行うなら、次の順番です。各項目の詳しい手順はリンク先にあります。

  1. 画面とP5Rの安全範囲を確認する。
  2. 初期条件のままPreflightを実行し、5つの検査がPASSか読む。
  3. Single Runを開始し、SUCCEEDEDまで待つ。
  4. 5指標を、条件と費用想定と一緒に読む。
  5. DetailsとLedgerを開き、数字の根拠を読む。
  6. 途中で止まった場合だけ、取消と再開を使う。
開発環境を自分で起動する場合：プロジェクトのルートで、ローカルAPIをpy -3 scripts/phase5r/backtest_api_server.py --port 8765、UIをui/mockでnpm run build後にnpm run preview -- --host 127.0.0.1で起動します。ブラウザではhttp://127.0.0.1:4173を開きます。すでに起動済みなら、この説明は飛ばしてください。

6. 操作手順

各手順のタイトルにあるIDは、上の機能一覧へ対応しています。手順の最後にある「機能一覧へ戻る」を使うと、次の機能を選べます。

BT-MAN-01：画面と、使ってよい条件を確認する

この操作でできること：この画面が、実注文ではなく、P5Rで許可されたローカルDataだけを使うBacktest画面だと確認できます。

いつ使う？毎回、最初に使います。初めての人は、ここを飛ばさないでください。

画面の場所：左メニューの「Backtest条件設定」→画面上部の「Backtest製品機能（P5R実API）」、安全境界、「P5R実行範囲」。

  1. 左メニューの「Backtest条件設定」をクリックします。スマートフォンでは、先に「メニューを開く」をクリックします。
  2. 見出し「Backtest製品機能（P5R実API）」を読みます。実APIとは、画面の見本だけでなく、ローカルのApplication APIに実際に問い合わせるという意味です。
  3. 安全境界で「外部市場データ、Broker、Secret、実注文、Paper／Liveには接続しません」と表示されることを確認します。
  4. 「P5R実行範囲」で、BTCUSDTまたはETHUSDT、Spot、1m、UTC、期間、Data: P5 local read-onlyを確認します。
  5. 「Single Run」「Sweep」「履歴・比較」「Holdout・Walk-forward」の4つのタブがあることを確認します。タブは、機能を切り替える見出しです。

確認できれば成功：実行範囲と安全境界が画面に見え、実注文を出す画面ではないと分かる。

失敗・異常時（表示が違うとき）：対象外銘柄、外部接続、Broker、実注文が表示されるなら操作を止めます。画面の表示と時刻を記録し、P5Rの完了扱いにしません。

この結果から言ってはいけないこと：画面を開けたことは、Backtestが実行済み、本番運用可能、利益が保証されたことを意味しません。

関係する用語：Backtest、Application API、Data、read-only ／ 受入条件: P5R-AC-02、P5R-AC-16

BT-MAN-02：条件を入力し、PreflightをPASSにする

この操作でできること：Backtestを始める前に、入力値とDataが安全な条件かを確認できます。Preflightは、車で出発する前の点検のようなものです。

いつ使う？Single Runを始める前、または条件を変更した後に使います。

画面の場所：「Single Run」タブ→「Single Backtest条件」→各入力欄→「Preflight実行」。

  1. 「銘柄」でBTCUSDTまたはETHUSDTを選びます。
  2. 「市場」「時間足」「タイムゾーン」は、Spot、1m、UTCになっていることを読みます。1mは1分ごとの値動き、UTCは世界共通の時刻です。
  3. 「開始（UTC）」と「終了（UTC）」を、例のように2025-02-24T00:00:00Zの形式で入力します。末尾のZはUTCであることを示します。
  4. 「Strategy」でTURTLE_SYS1またはTURTLE_SYS2を選びます。Strategyは、買う・売る・手仕舞いを決めるルールです。
  5. 「初期残高（USDT）」、Entry lookback、Exit lookback、Fee（bps）、Slippage（bps）を確認します。入力語の意味は用語集で確認できます。
  6. 「Preflight実行」をクリックします。
  7. 「開始前Preflight」に、TYPE_AND_UNIT、P5_DATA_SCOPE、UTC_AND_CALENDAR、QUALITY、LOOKAHEADがすべてPASSになることを確認します。

確認できれば成功：「Preflight PASS。実Runを開始できます。」と表示され、「Single Run開始」ボタンが押せる状態になる。

止まったとき：PASSでない検査の名前とメッセージを読みます。銘柄・期間・単位・UTC・Data範囲を直してから再度Preflightします。PreflightがPASSでないままSingle Runを始めません。

この結果から言ってはいけないこと：Preflight PASSは、利益が出るという意味ではありません。開始してよい入力形式とData範囲だという意味です。

関係する用語：Preflight、UTC、Strategy、lookback、bps ／ 受入条件: P5R-AC-01、P5R-AC-02

BT-MAN-03：UTCではない日時を安全に止める

この操作でできること：時刻の意味が決められない入力を、計算開始前に止められることを確認できます。時刻がずれると、別のDataを読んでしまう危険があります。

いつ使う？入力間違いを安全に止める機能を確認するときに使います。通常の実験では、正しいUTC形式を入力してください。

画面の場所：「Single Backtest条件」→「開始（UTC）」→「Preflight実行」。

  1. 「開始（UTC）」を2025-02-24T00:00:00に変更します。最後のZをわざと外します。
  2. 「Preflight実行」をクリックします。
  3. 「Preflight STOPPED。停止理由を直してから再実行してください。」と表示されることを確認します。
  4. 検査結果のUTC_AND_CALENDARと、停止理由を読みます。
  5. 開始時刻を2025-02-24T00:00:00Zに戻し、再度「Preflight実行」をクリックします。

確認できれば成功：UTCを示すZがない入力が、Run開始前にSTOPPEDになる。

止まったままのとき：開始・終了の両方がUTC形式か、開始が終了より前か、P5R範囲内かを確認します。

この結果から言ってはいけないこと：STOPPEDは、システムが壊れたという意味ではありません。意味の決められない入力から計算を守るために止めた状態です。

関係する用語：UTC、STOPPED ／ 受入条件: P5R-AC-01、P5R-AC-16

BT-MAN-04：Single Runを開始し、進み具合を見る

この操作でできること：1つの条件でBacktestを実行し、実際のRun ID、状態、処理済みBar数、進捗率、ETAを確認できます。Runは1回分の実験です。

いつ使う？PreflightがPASSになった後、1つの条件を詳しく調べるときに使います。

画面の場所：「Single Backtest条件」→「Single Run開始」→「実Run」。

  1. BT-MAN-02でPreflightがPASSになっていることを確認します。
  2. 「Single Run開始」をクリックします。
  3. 「実Run」にRUN-P5R-...のようなRun IDが表示されることを確認します。Run IDは、実験を取り違えないための名前です。
  4. 状態がQUEUED（順番待ち）からRUNNING（計算中）へ変わることを読みます。
  5. 進捗率、処理済みBar数／全Bar数、ETA（あとどれくらいかの目安）を確認します。
  6. SUCCEEDED（計算完了）になるまで待ちます。待機中に別のRunを作る場合は、Run IDを記録します。

確認できれば成功：Run IDがあり、計算中の状態と進捗が表示され、最後にSUCCEEDEDになる。

失敗したとき：FAILEDなら停止理由を読みます。QUEUEDやRUNNINGをSUCCEEDEDと読み替えません。結果が出る前にDetailsやCSVを開くと、RESULT_NOT_READYになる場合があります。

この結果から言ってはいけないこと：進捗100%やSUCCEEDEDは、利益が出たという意味ではありません。計算が最後まで終わったという意味です。

関係する用語：Run、QUEUED、RUNNING、SUCCEEDED、ETA ／ 受入条件: P5R-AC-03、P5R-AC-14

BT-MAN-05：5つの指標を、条件と一緒に読む

この操作でできること：計算が終わったRunについて、5つの数字と、その数字がどの条件の結果かを確認できます。

いつ使う？Single RunがSUCCEEDEDになった後に使います。

画面の場所：Single Runの結果に出る「Backtestの5指標」と「結果Ledgerと由来」。

  1. 「総損益」を読みます。初期残高から、最後の残高までにどれだけ増減したかを示します。単位はUSDTです。
  2. 「最大ドローダウン」を読みます。残高が、それまでの最高地点から最も大きく落ち込んだ幅です。大きいほど、途中の落ち込みが大きかったという意味です。
  3. 「勝率」を読みます。決済まで終わった取引のうち、利益がプラスだった割合です。勝率だけで結果の良さは決まりません。
  4. 「取引回数」を読みます。画面ではVirtual Fill（実注文ではない仮想的な約定）の回数です。
  5. 「最終残高」を読みます。計算の最後の時点での残高です。
  6. FeeとSlippageが想定値として表示されていることを確認します。bpsは割合を細かく表す単位です。
  7. Dataの期間、Strategy、Entry／Exit lookback、初期残高も一緒に記録します。数字だけを切り取らないでください。

確認できれば成功：5指標、単位、同じRunの条件、費用想定、Data由来を一緒に読める。

表示が空のとき：RunがSUCCEEDEDか確認します。未完了なら待ちます。失敗したRunに、画面にない数字を想像で足しません。

この結果から言ってはいけないこと：総損益がプラスでも、将来の利益、実際の約定、手数料込みの現実の利益を保証しません。勝率が高くても、1回の大きな損失があれば全体結果は悪くなることがあります。

関係する用語：5指標、最大ドローダウン、勝率、Virtual Fill、Fee、Slippage ／ 受入条件: P5R-AC-05

BT-MAN-06：DetailsとLedgerを読んで、数字の根拠を確かめる

この操作でできること：5指標だけでなく、StrategyのSignal、仮想的な約定、残高の変化を時刻順に確認できます。Ledgerは、実験中の出来事を時刻順に書いたノートです。

いつ使う？数字の理由を詳しく調べたいとき、Strategy Coreの判断を確認したいときに使います。

画面の場所：SUCCEEDEDになった「実Run」→「結果・詳細を表示」または「Detailsを読込」→「結果Ledgerと由来」。

  1. SUCCEEDEDのRunで「結果・詳細を表示」をクリックします。
  2. 「Data由来」「期間」「Data範囲」「Core検証」「利益の意味」を読みます。
  3. Ledgerの「種類」を読みます。Signalは売買ルールから出た判断、Virtual Fillはその判断を仮想的に約定させた記録です。
  4. 「時刻（UTC）」「銘柄」「Signal」「方向」「価格」「残高／Equity」「理由」を、上から順に読みます。
  5. 理由にSYS1_ENTRY、SYS2_ENTRY、EXIT_LONGなどがあれば、選んだStrategy Coreの判断理由として記録します。
  6. 表に表示される行数を超えて全件が必要なら、BT-MAN-12のCSV操作を使います。画面にない行を想像で補いません。

確認できれば成功：5指標からLedgerの時系列へ移動でき、Data由来とCore検証が同じRunに結び付いている。

読めないとき：RunがSUCCEEDEDか、対象Run IDが正しいかを確認します。結果が未完了ならRESULT_NOT_READYとして待ちます。

この結果から言ってはいけないこと：LedgerにSignalがあることは、実際の注文が成立したことを意味しません。Virtual Fillは仮想的な記録です。

関係する用語：Ledger、Signal、Virtual Fill、Equity、Provenance ／ 受入条件: P5R-AC-06

7. 止まったときの読み方

エラーコードは、システムが出す短い名前です。名前だけでなく、意味と次の操作を読みます。

表示かんたんな意味次にすることしてはいけないこと
TYPE_AND_UNIT入力の種類や単位が合わない。数値、単位、日時形式を確認してPreflightをやり直す。数字を想像で置き換える。
P5_DATA_SCOPE銘柄・期間がP5Rの範囲外。BTCUSDT／ETHUSDTと許可期間へ戻す。範囲外Dataを勝手に追加する。
UTC_AND_CALENDARUTCやカレンダーが確認できない。日時の末尾Zと順序を確認する。ローカル時刻のまま計算する。
QUALITYData品質が条件を満たさない。表示された理由を記録し、品質確認済みDataを使う。欠けたDataを想像で補う。
LOOKAHEAD未来のDataを先に使う可能性がある。条件と時間窓を見直し、未来参照なしを確認する。結果が良いから無視する。
CORE_VALIDATION_...Strategy Coreが条件を受け付けなかった。Coreの停止理由を記録し、成功扱いにしない。結果を手入力して完成にする。
RESULT_NOT_READY計算が終わる前に結果を読もうとした。同じRun IDがSUCCEEDEDになるまで待つ。画面にない数字を推測する。
CANDIDATE_FORCED_FAILURESweepの検査で候補を意図的に失敗させた。親JobがPARTIAL_FAILEDであることを確認する。失敗した子を隠して全成功にする。
EARLY_HOLDOUT_ACCESS確定前にHoldoutへアクセスした。調整へ使わず、確定後評価まで待つ。見た数字で条件を直す。
WALK_FORWARD_OVERLAP時間窓が重なっている。学習・検証・評価の順序と境界を直す。未来参照の可能性を無視する。
CANCELLED利用者の取消などで停止した。checkpointと再開可否を確認する。完了結果とみなす。
PARTIAL_FAILEDSweepの一部候補が失敗した。親と子を分けて記録する。親をSUCCEEDEDへ書き換える。

8. 用語集

ここでは、この手順書で使う言葉を、投資初心者向けに説明します。

Backtest
過去の市場Dataに売買ルールを当てはめる仮想実験。実際の注文記録ではない。
Application API
画面から受けた操作を計算サービスへ渡し、結果を画面へ返す窓口。このP5Rではローカルで動く。
Data
計算の材料になる過去の値動き。Dataの期間、銘柄、時刻の意味が違うと結果も変わる。
read-only
読むだけで、元のDataを書き換えないこと。
銘柄（symbol）
どの取引対象を調べるかを表す名前。この画面ではBTCUSDTまたはETHUSDT。
Strategy
いつ買うか、いつ売るか、いつ手仕舞いするかを決めるルール。TURTLE_SYS1とTURTLE_SYS2がある。
UTC
世界で共通に使う時刻の基準。入力の末尾にZを付け、別の地域の時刻と混同しない。
Entry／Exit lookback
Entry（入り口）やExit（出口）を判断するときに、過去の何本のBarを見るかを表す設定。
bps
FeeやSlippageの割合を細かく表す単位。画面の想定値を、実際の市場費用と混同しない。
Fee
取引を想定したときの手数料。このP5Rでは入力した想定値。
Slippage
注文したい価格と、実際に成立すると仮定した価格のずれ。このP5Rでは想定値。
Preflight
Backtestを始める前の安全点検。入力、Data範囲、UTC、品質、未来参照を確認する。
Run
1回分のBacktest実験。Run IDで、どの条件の実験かを区別する。
QUEUED
計算の順番を待っている状態。
RUNNING
現在計算している状態。
SUCCEEDED
そのRunの計算が最後まで終わった状態。利益が出たという意味ではない。
STOPPED
安全条件を満たさないため、開始や読込を止めた状態。
CANCELLED
利用者の取消などで途中停止した状態。
ETA
完了までの残り時間の目安。
checkpoint
途中までの計算状態を、後で再開できるように保存したもの。
再開（resume）
checkpointを使って、同じRunの続きから計算すること。
Sweep
条件の候補を複数作り、Backtest実験をまとめて行う機能。本番運用Unitではない。
親Job・子Run
親Jobは候補全体をまとめるもの。子Runは候補1つごとの実験。
PARTIAL_FAILED（部分失敗）
複数候補の一部だけが失敗した状態。全体成功とは違う。
5指標
総損益、最大ドローダウン、勝率、取引回数、最終残高。
最大ドローダウン
残高が過去最高から最も大きく落ち込んだ幅。
勝率
決済まで終わった取引のうち、利益がプラスだった割合。
Signal
Strategyが出した「買う、売る、手仕舞いする」などの判断。
Virtual Fill
Signalに基づき、仮想的に注文が成立したと計算した記録。実注文ではない。
Ledger
Signal、Virtual Fill、残高などを時刻順に記録した表。
Equity
その時点で持っているものを含めた評価上の残高。
Provenance
結果がどのData、期間、Strategy、Core検証から生まれたかを示す由来情報。
履歴
過去に作ったRunの一覧。古い結果を新しい結果で上書きせず、取り違えないために使う。
comparable
2つのRunを同じ問題として比べてよいかを示す表示。falseなら理由を確認する。
Job
CSV作成など、画面とは別に時間をかけて行う処理。
CSV
表の行と列を保存するファイル形式。保存形式であり、結果の正しさを保証するものではない。
Holdout
条件を決める間は隠しておき、最後に一度だけ評価するData。
調整
Strategyの設定や期間などを変え、結果を良くする方向を探すこと。
学習・検証・評価
過去の条件を決める期間、途中で確かめる期間、最後に評価する期間。順番を守る。
Walk-forward
時間窓を順番にずらしながら、学習・検証・評価を繰り返す確認方法。
未来参照
その時点ではまだ分からない未来のDataを、条件決定やSignalに使ってしまうこと。結果を不自然に良くするため禁止する。

9. 結果から言ってはいけないこと

  • 総損益がプラスだから、「将来も儲かる」と言ってはいけません。
  • SUCCEEDEDだから、「実際の注文も同じ価格で成立する」と言ってはいけません。
  • 勝率が高いから、「安全」と言ってはいけません。最大ドローダウンや1回の損失も読みます。
  • 比較結果が良いから、「最良Strategyが自動で選ばれた」と言ってはいけません。
  • Sweepの子Runが複数成功したから、「複数の運用Unitが本番で動く」と言ってはいけません。
  • Holdoutを評価したから、結果を見ながら条件を調整してよいとは言えません。
  • Walk-forwardがSUCCEEDEDだから、Forward、Shadow、Paper、Liveが開始できるとは言えません。
  • この手順書は投資助言ではありません。特定の銘柄を買う・売る判断を勧めるものではありません。
