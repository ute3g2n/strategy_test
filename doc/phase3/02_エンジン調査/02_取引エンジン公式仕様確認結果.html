5. 最小Adapter境界

候補エンジンの型をCoreへ持ち込まず、次の一方向の境界にする。エンジンを変えても、StrategyとMarket Dataの意味を変えないことが目的である。

MarketEvent列 + DataVersionManifest
          │
          ▼
  EngineInputAdapter（Coreの値を候補エンジンのBar/CustomDataへ変換）
          │  外部型はここだけ
          ▼
  Candidate Backtest Engine（NautilusTrader または LEAN）
          │
          ▼
  EngineOutputAdapter（Signal / OrderIntent / Fill / Healthを内部契約へ戻す）
          │
          ▼
  Experiment Manifest + Replay結果 + 監査証跡
境界入力出力禁止する漏れやさしい説明
EngineInputAdapterMarketEvent、data_version、Catalog版、固定時刻候補エンジンのBar/CustomDataとStrategy設定SDKのrecord class、Broker ID、Secret、現在時刻こちらのデータを、相手の道具が読める形へ翻訳します。相手の内部番号は、こちらの設計に持ち込みません。
Strategy境界確定済みの時系列イベントだけSignalEvent、OrderIntentまたはTargetPositionRisk最終判定、OMS、Broker送信Strategyは「こうしたい」という合図までを出し、実際に注文してよいかは別の係に任せます。
EngineOutputAdapterエンジンの状態・Fill・ログ内部の結果、HealthEvent、Manifest参照エンジン固有IDを本線IDとして利用相手の道具の返事を、プロジェクト共通の言葉へ戻します。
Manifest接続入力hash、設定、engine版、code revisionExperiment Manifest、結果hash、再実行情報不明な版、可変な現在時刻、後からのfixture変更どの材料で実験したかを、後で同じように作れる一覧へ残します。

9. H3-2で承認してもらう内容

  1. NautilusTrader 1.231.0のCPython 3.12 wheel、またはLEAN Docker tag 17991のどちらをPoC固定候補にするか。
  2. 候補を使う場合の完全hash、配布元、ライセンス文書、SBOM、保存先を固定すること。
  3. 依存導入を許可する範囲（wheel/package/image/NuGet）と、外部通信を初回準備時だけに限定すること。
  4. 長期データを取得・保存するか。取得する場合はE:\strategy_test_data\phase3\datasets\配下だけを使うこと。
  5. OD-02を「Phase 3のローカルPoC候補決定」までにするか、「Phase 4 Paper証拠後の最終決定」まで保留するか。

承認結果（2026-08-09）: H3-2は承認済み。LEANを主PoC候補、NautilusTraderを代替候補とする。P3-08Aで固定版・hash・ライセンス・公式配布元・ローカル実行方法をRun Manifestへ固定し、P3-09ではその固定物だけを使う。長期データを使う場合は E:\strategy_test_data\phase3\datasets\ に限定する。Broker、Secret、実注文、Live運用は承認範囲外とする。

やさしい説明: 道具を入れて練習試験を始めてよい、という許可を受けました。ただし、版番号と中身の確認印を先に記録し、本物の売買にはまだ使いません。
