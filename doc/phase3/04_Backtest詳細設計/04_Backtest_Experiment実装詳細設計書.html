1.1 実装契約の先取り：API、状態、不変条件

次の署名はP3-05のRED試験とP3-06以降の実装で変えない公開契約です。Result[... ]は成功または固定BacktestFailureを値として返し、通常のデータ異常を例外で握り潰しません。I/Oを行うのはResultStoreだけです。

class ReplayOrder(Protocol):
    def normalize(self, events: tuple[MarketEvent, ...], gate: DataGateDecision,
                  binding: AggregatorBinding) -> Result[tuple[MarketEvent, ...]]: ...

class TimeframeAggregator(Protocol):
    def accept(self, event: MarketEvent, state: AggregatorState,
               calendar: CalendarSnapshot, gate: DataGateDecision,
               binding: AggregatorBinding) -> Result[AggregationTransition]: ...
    def snapshot(self, state: AggregatorState, binding: AggregatorBinding) -> AggregatorSnapshot: ...
    def restore(self, snapshot: AggregatorSnapshot, binding: AggregatorBinding) -> Result[AggregatorState]: ...

class FillModel(Protocol):
    def evaluate(self, directive: Directive, bar: TradableBar,
                 profile: FillProfile) -> Result[FillDecision]: ...

class CalendarPort(Protocol):
    def session_for(self, instant_utc: datetime, calendar: CalendarSnapshot,
                    binding: AggregatorBinding) -> Result[SessionBoundary]: ...
class SlippageModel(Protocol):
    def apply(self, side: Direction, base_price: Decimal,
              profile: FillProfile) -> Result[SlippageDecision]: ...
class CostModel(Protocol):
    def apply(self, fill: FillDecision, slippage: SlippageDecision,
              profile: FillProfile) -> Result[CostBreakdown]: ...
class RollPnLModel(Protocol):
    def evaluate(self, binding: RollBinding, old_price: Decimal, new_price: Decimal,

class EngineAdapter(Protocol):

                          manifest: ExperimentManifest) -> Result[AdapterValidation]: ...

class BacktestRunner(Protocol):

class ResultStore(Protocol):

5.1 決定的アルゴリズム

normalize(events, gate, binding):
  require gate.signal_allowed
  for event in events:
    require BAR_1M, UTC, close == event_time + 1 minute
    require event.data_version == binding.data_version
  sort by (bar_close_time, event_time, instrument_id, event_id)
  same event_id and same canonical payload -> keep one
  same instrument + same one-minute interval and different payload -> DUPLICATE_1M_CONFLICT
  return ordered events

accept(event, old_state, calendar, gate, binding):
  require gate.signal_allowed and calendar.published_at_utc <= event.bar_close_time
  require event key > old_state.last_order_key, except exact replay no-op
  candidate = copy(old_state) and add the one-minute event to each eligible session bucket
  if any required minute is missing at a closing boundary: PARTIAL_BAR_REJECTED
  close every complete M1/M15/M30/H1/H4/D1 bar in canonical timeframe order
  if the expected cohort at this close is not exact: COHORT_INCOMPLETE
  batch = canonical ClosedBarBatch(all closed bars)
  return new_state(last_order_key=key, last_batch_sha256=batch.hash), batch

run_one_event(event, simulator_state):
  first evaluate prior confirmed protective stops and pending directives
  only against this event's matching tradable bar, in pending canonical order
  mark each consumed fingerprint exactly once; no later eligible bar -> NO_ELIGIBLE_BAR / UNFILLED
  then pass event to Aggregator; no new Directive can use this event for Fill

run_one_batch(batch, prior_execution_view):
  require batch complete and all Calendar/Roll published_at <= batch.decision_time
  update every Strategy timeframe view; call Strategy exactly once
  write Directive rows as uncommitted audit rows
  append new Entry/Add/Channel Exit as ScheduledDirective in canonical pending order
  append Strategy output, then Snapshot/SimulatorState, then one commit marker

resume(snapshot, files):
  reject unknown schema, binding/hash/offset/watermark mismatch, partial commit
  start from the event strictly after last_committed_event_id
  never append a duplicate batch, directive, fill, or commit id

7. 仮想約定・費用・Gap・Roll

標準ProfileはConservativeOHLCv1です。OHLCだけでは足の中の順番が分からないとき、都合のよい順番を想像しません。

場面固定する価格・結果理由
Longのstop退出min(bar.open, stop_trigger)。slippage/costはさらに不利側へ。窓開けでstopより低く始まった場合も、希望価格で売れたことにしない。
Shortのstop退出max(bar.open, stop_trigger)。slippage/costはさらに不利側へ。窓開けでstopより高く始まった場合も、希望価格で買い戻せたことにしない。
上抜けEntry / Addmax(bar.open, trigger)を基準に、不利側コストを加える。開始時点で既に突破していたとき、低い突破価格を使わない。
下抜けEntry / Addmin(bar.open, trigger)を基準に、不利側コストを加える。開始時点で既に下へ飛んだとき、有利な高値を使わない。
同一bar内のEntry/Add/Exit/Stop順が不明INTRABAR_PATH_AMBIGUOUSで未約定・実験停止。1本の足だけでは先後を知れないのに、勝ちやすい順を選ぶのを防ぐ。
値幅制限、ゼロ出来高、価格不整合未約定、理由を監査、保有は既存状態のまま。取引できない値段で約定したことにしない。
RollSignal seriesは連続価格でよいが、Fill/Roll PnLはCatalog解決済みtradable instrumentと非調整価格だけを使う。グラフ上の連続価格を、実在しない約定価格にしない。

23.3 唯一の正本経路と処理順

公開入口はBacktestRunner.run(request: BacktestRunRequest) -> BacktestRunResultだけです。既存のdict predicateは削除するか、このDTOへ厳格に変換する薄い互換入口に限り、入力されたPASSやTrueだけで成功を返してはいけません。

def run(request: BacktestRunRequest) -> BacktestRunResult:
    strict_validate_manifest(request.manifest)
    validate_p2_market_events_and_data_gate(request.replay)
    ordered = normalize_replay(request.replay)
    for event in ordered:
        consume_existing_protective_stop(event)
        consume_only_eligible_pending_directives(event)
        transition = calendar_and_timeframe_aggregate(event)
        update_all_views_in_fixed_order(transition)
        if transition.decision_point is not None:
            strategy_result = call_strategy_exactly_once(transition.closed_bar_batch)
            schedule_new_directives_for_next_bar(strategy_result)
        append_result_row_and_snapshot()
        append_commit_marker_last()
    atomically_publish_after_recomputing_all_hashes()
    return BacktestRunResult(status="COMMITTED", ...)

順序は、strict Manifest検証 → P2 MarketEvent/Data Gate検証 → Replay正規化・重複処理 → 各1分Eventで既存protective stopとeligible pendingだけを処理 → Calendar/時間足集約 → 同一close cohortを全更新 → Strategy一回 → 新Directiveを次bar用pendingへ追加 → Snapshot/Result append → marker commit → atomic publishです。どこか一つでも失敗したら、以後のSignal、Directive、Fill、Resultを追加せず、構造化STOPPEDへ遷移します。
