1. 目的と範囲

P2-07で固定したData Quality / Replay fixtureを出発点に、Databento取得条件を安全に表現するCLI、fixture Gateway、承認後のbounded HTTPS Gateway、metadata保存方針、外部応答のHealthEvent分類を定義した。Strategyの利益評価、Backtest採用、連続取得運用は対象外である。

2. Adapter境界と処理

flowchart LR
    CLI[固定引数・UTC] --> Validate[Request validation]
    Validate --> Plan[Deterministic request plan]
    Plan --> Fixture[FixtureGateway]
    Fixture --> Check[SHA256 / schema check]
    Check --> P207[P2-07 fixed payload]
    Error[401/403/206/404/429/degraded] --> Health[HealthEvent]
    Health --> Stop[Data Gate停止 / 縮退]
    H22[H2-2 approval] -.未承認.-> External[External gateway disabled]

CoreはDatabento SDK、HTTP status、API keyを参照しない。外部仕様はAdapterで内部のrequest plan、HealthEvent、metadataへ変換する。
