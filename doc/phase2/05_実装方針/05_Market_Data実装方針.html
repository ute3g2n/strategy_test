P2-D09 Market Data実装方針

Phase / Step: Phase 2 / P2-07
文書状態: v0.1 / P2-07最小実装反映
実装Run: RUN-P2-DQR-001

範囲: 固定fixtureだけを使うローカル実装である。Databento、Broker、Live、Secret、外部ネットワーク、実データはこの実装へ接続しない。P2-05のCatalog Resolverは変更せず、Raw / Normalized / Quality / Manifestの境界を追加した。

1. 実装済み範囲

部品ファイル実装内容停止条件
共通型store_contracts.pyRawWriteRequest、NormalizedBar、QualityReport、DataVersionManifest、MarketEventを型として定義。時刻・品質・版の必須情報がない入力は後続へ渡さない。
Raw Storeraw_store.py内容確認値付きで固定payloadを保存し、同一内容だけ再利用する。完成物を上書きしない。checksum不一致、UTCでない受信時刻、Secretらしいmetadataは拒否。
Qualityquality.py重複、重複競合、時刻逆行、価格・出来高異常、注入された品質異常を決定的に判定。停止品質印が一つでもあればpublishable=false、Signal生成停止。
Manifestmanifest.pyRaw hash、変換規則版、Catalog版、品質報告hashから時刻非依存のdata_versionを生成。必須構成要素が欠けたManifestは作成しない。
Normalized Storenormalized_store.py品質合格済みのNormalizedBarとManifestを一つのJSON snapshotへ原子的に保存し、Replay時に整合性を再確認。品質不合格、同一data_versionの異内容、Manifest整合性不一致は拒否。

2. 処理境界

flowchart LR
    Raw[固定Raw payload] --> RawStore[LocalRawStore]
    RawStore -->|raw_object_id / sha256| Quality[QualityChecker]
    Quality -->|QualityReport| Manifest[ManifestBuilder]
    Manifest -->|DataVersionManifest| Normalized[LocalNormalizedStore]
    Normalized -->|検証済みsnapshot| Replay[Replay入力]
    Quality -.停止品質印.-> Stop[Signal生成停止]
    Catalog[CatalogResolverの固定snapshot] -.catalog_version.-> Manifest

各矢印は、次の部品へ渡す識別子または証跡を表す。Raw payloadそのものをCatalogやSignalへ渡さず、Manifestが参照する版と品質報告を経由する。

3. 品質・Replay契約

観点固定した規則証拠
欠損・異常MISSING_DATA、DUPLICATE_CONFLICT、OUT_OF_ORDER、PRICE_INVALID、VOLUME_INVALID、CHECKSUM_MISMATCH、DEGRADEDは版を発行せずSignalを止める。契約テスト
同一入力再現Raw hash、変換規則版、Catalog版、品質報告hashが同じならdata_versionは同じ。generated_atや現在時刻を使わない。ManifestBuilder.build、Run Manifest
不変性Raw完成物とNormalized data_versionを上書きしない。同じ版への異内容保存は停止する。Storeテスト
外部入力実装はfixture-only。外部SDK、通信、API key、Broker接続を持たない。安全レビュー
未来情報未来足で過去公開済みSignalを変更しない契約をP2-06 fixtureへ固定。実Replay比較はP2-09で完了させる。Pythonレビュー
