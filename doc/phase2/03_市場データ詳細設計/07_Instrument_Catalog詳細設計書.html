1. 目的と責務

Instrument Catalogは、外部vendorの記号や数値を内部の不変なInstrumentId、契約定義、営業日、取引可能性へ変換する正本である。Market Data Adapterは観測結果を渡し、Catalogは内部IDと有効期間を管理する。StrategyはCatalogを直接更新しない。

責務CatalogAdapter / Strategyとの境界
内部ID不変の内部InstrumentIdを発行・参照。vendor instrument_id/raw_symbolを正本IDにしない。
mappingvendor symbol、stype、外部ID、有効期間を版管理。partial/ambiguousはTradableに昇格しない。
契約定義満期、tick、multiplier、通貨、instrument classを管理。未確認値はUnknownまたはplaceholder。
営業日timezone、session、休日、early close、business dateを管理。UTC時刻を現地営業日に変換する規則を版管理。
証拠金margin placeholderと参照元・有効時点だけを保持。Riskの最終証拠金計算は対象外。未確認値を安全側と誤認しない。

2. 内部InstrumentId

内部IDは外部IDを含めない正規化された契約同一性から生成し、生成後は変更しない。product rootやcontinuous seriesは取引可能な契約IDとは別のCatalog entityとして扱う。

Entity識別キー例・制約
Instrumentvenue、product_root、contract_year、contract_month、instrument_class一つの取引可能なfuture/spread等を表す。生成後immutable。
Productvenue、product_root、asset_classMCL等の親。直接MarketEventの取引対象にはしない。
ContractSelectionproduct_id、selection_rule_version、rank、validitycalendar/volume/open-interest等の選択結果。roll承認前はUnknown。
InstrumentId内部namespace + canonical identity hashinst_...形式のopaque ID。vendor symbolから再生成できるが、vendor IDを文字列へ露出しない。
一意性: 同じ契約を別vendorから取得しても内部InstrumentIdは同じcanonical identityへ解決する。canonical identityを構成できない場合は新IDを作らず、UNKNOWN_INSTRUMENT_IDENTITYとして停止する。

3. Vendor Symbol Mapping

項目必須内容
mapping_idYes内部mappingの不変ID。
instrument_idYes解決後の内部ID。未解決時はnullのままCatalog候補。
vendor / dataset_idYes外部参照の所有者。
stype_in / input_symbolYes要求に使用したparent/raw/continuous等。
stype_out / output_symbolYes解決後のraw_symbol等。Databentoの表現を内部IDと混同しない。
external_instrument_idConditionalvendor側の数値ID。関連属性として保持。
valid_from_utc / valid_to_utcYesmappingの有効期間。日付を跨ぐ再利用を許容するため期間が必須。
resolution_statusYesresolved、partial、ambiguous、not_found、expired、unknown。
source_raw_object_id / mapping_versionYes外部観測証跡とmapping規則版。
検証合格条件不合格時
一意性同一有効期間・同一入力symbolが一つの内部IDへ解決。MAPPING_AMBIGUOUS、Tradable/Replay停止。
期間event_time_utcがmapping有効期間に含まれる。MAPPING_OUT_OF_RANGE、対象範囲除外。
クラスfutureとspreadをinstrument_classで分離。INSTRUMENT_CLASS_UNKNOWN、自動採用しない。
再取得新mappingは旧行を更新せず新versionとして保存。旧mappingを保持し、差分Reviewへ。

4. Contract Metadata

項目必須性設計ルール
venue / product_root / instrument_class必須契約を分類する内部項目。parent symbolそのものを保存しない。
contract_year / contract_monthfutureは必須満期とidentityに使用。
listing_at_utc / expiration_at_utc / last_trade_at_utc確認値point-in-time定義として有効期間を持つ。未確認はUnknown。
tick_size / price_scale必須価格検証と丸めに使用。単位を明記し、未確認値で計算しない。
contract_multiplier / currency必須Notional計算の入力。Risk計算の最終仕様は後続Phase。
calendar_id / timezone必須sessionとbusiness_dateの解決先。
status / effective_from / effective_to必須active、expired、halted、unknown等を有効期間付きで管理。
source_ref / observed_at_utc必須どのRaw/definition観測から得た値かを追跡。

5. Trading Calendar

項目内容
calendar_id / calendar_version市場・venue・timezoneごとの版。
timezoneexchange_time_localの変換先。夏時間規則を含めて版管理。
session_intervals通常取引、休止、early close、再開区間。
holiday_rules休日、臨時休場、営業日とbusiness_dateの対応。
effective_period後からカレンダーが変更されても過去判定を再現。

欠損判定はCalendarだけで決めず、Databento Dataset Condition、Raw範囲、schemaの「取引なし区間はレコードなし」の意味を組み合わせる。判断不能はUNKNOWN_SESSION_STATEとしてData Gateへ送る。

6. Tick、Multiplier、Margin Placeholder

項目保持項目Phase 2の扱い
Tick sizevalue、unit、price_scale、source_ref、effective_periodNormalized価格検査に使用。未確認なら価格検査をPassにしない。
Contract multipliervalue、currency、unit、source_ref、effective_periodNotionalの入力として保持。Riskの限度値は後続Phase。
Margin placeholdermargin_rule_ref、initial_margin、maintenance_margin、currency、source_ref、observed_at、status値が未確認ならnull/Unknown。ゼロや仮値で安全性を主張しない。
Trading statusactive、halted、expired、unknown、effective_periodunknown/expiredはTradableへ昇格させない。

7. Continuous / Rollとの接続

Catalogはcontinuous seriesを取引可能Instrumentそのものとせず、ContractSelectionとして表現する。選択ルール、対象product、rank、対象期間、解決されたInstrumentId列、価格の調整有無、ルール版を保存する。

項目例制約
selection_rule_versionroll-v0.1H2-1承認前はUNKNOWN。
selected_instrument_id期間ごとの内部InstrumentIdCatalog mappingの有効期間内でなければ不合格。
selection_reasoncalendar、volume、open_interest、manual根拠が欠ける選択を本線へ入れない。
price_adjustment_policyunadjusted、back_adjusted等Rawを変更しない。派生系列の仕様として別versionにする。

8. data_versionへの接続

Catalog version項目Run Manifest / Replayへの接続

10. 型付きデータ契約

from dataclasses import dataclass
from datetime import datetime
from hashlib import sha256
from typing import Literal

@dataclass(frozen=True)
class ResolveInstrumentRequest:
    vendor: str; dataset_id: str; stype: str; symbol: str
    event_time_utc: datetime

@dataclass(frozen=True)
class ResolveInstrumentResult:
    status: Literal["resolved", "partial", "ambiguous", "not_found", "unknown"]
    instrument_id: str | None
    mapping_id: str | None
    catalog_version: str
    reason_code: str | None

@dataclass(frozen=True)
class SymbolMapping:
    mapping_id: str; instrument_id: str | None
    vendor: str; dataset_id: str; stype_in: str; input_symbol: str
    stype_out: str; output_symbol: str; external_instrument_id: str | None
    valid_from_utc: datetime; valid_to_utc: datetime | None
    status: str; source_raw_object_id: str; mapping_version: str
@dataclass(frozen=True)
class CatalogSnapshot:
    schema_version: Literal["catalog-v1"]
    catalog_version: str
    catalog_snapshot_sha256: str
    instruments: tuple["Instrument", ...]
    mappings: tuple[SymbolMapping, ...]
    calendars: tuple["TradingCalendar", ...]
    created_at_utc: datetime

    def by_id(self, instrument_id: str) -> "Instrument": ...
@dataclass(frozen=True)
class Instrument:
    instrument_id: str
    venue: str; product_root: str
    contract_year: int | None; contract_month: int | None
    instrument_class: Literal["future", "spread", "continuous", "unknown"]
    status: Literal["active", "expired", "halted", "unknown"]
    tick_size: str | None; contract_multiplier: str | None
    calendar_id: str | None

@dataclass(frozen=True)
class TradingCalendar:
    calendar_id: str; timezone: str; effective_from_utc: datetime
    session_intervals: tuple[str, ...]; holiday_dates: tuple[str, ...]

すべての時刻はtimezone-aware UTC。valid_to_utc=Noneは将来まで有効ではなく「終了未観測」を意味し、現在時刻を使った補完は禁止する。statusがresolved以外ならinstrument_idをMarketEventへ渡さない。

11. Snapshot物理契約とmigration

JSON root key必須内容制約
schema_versioncatalog-v1互換性を壊す変更はcatalog-v2と別Readerを追加。v1を書換えない。
catalog_versioncv_ + canonical JSON SHA-256の先頭20桁内容と一致。重複versionで内容が違えばIntegrityError。
instrumentsopaque instrument_id、identity、metadata、effective periodidentity欠落、future/spread不明、tick/multiplier未確認はstatus=unknown。
mappings上記SymbolMapping、source_raw_object_id同一vendor/dataset/stype/symbol/期間のresolved行は一意。
calendarstimezone、session、holiday、effective periodsession状態が不明ならgap判定をPassにしない。
auditcreated_at_utc、creator step、source refs、previous_versionSecret、vendor authentication、Account ID禁止。

snapshot JSONはキーをソートしUTF-8で直列化してhashを計算する。P2-05のwrite_if_absentは一時ファイルへ書込み、digestを確認してから最終パスへ原子的renameを行う。失敗時は完成snapshotを残さない。

12. Resolverの順序とコード例

def resolve(snapshot: CatalogSnapshot, request: ResolveInstrumentRequest) -> ResolveInstrumentResult:
    candidates = [m for m in snapshot.mappings
                  if m.vendor == request.vendor and m.dataset_id == request.dataset_id
                  and m.stype_in == request.stype and m.input_symbol == request.symbol
                  and m.valid_from_utc <= request.event_time_utc
                  and (m.valid_to_utc is None or request.event_time_utc < m.valid_to_utc)]
    resolved = [m for m in candidates if m.status == "resolved" and m.instrument_id]
    if len(resolved) != 1:
        return ResolveInstrumentResult("ambiguous" if len(resolved) > 1 else "not_found",
            None, None, snapshot.catalog_version, "MAPPING_NOT_UNIQUE")
    instrument = snapshot.by_id(resolved[0].instrument_id)
    if instrument.status != "active" or instrument.instrument_class != "future":
        return ResolveInstrumentResult("unknown", None, resolved[0].mapping_id,
            snapshot.catalog_version, "INSTRUMENT_NOT_TRADABLE")
    return ResolveInstrumentResult("resolved", instrument.instrument_id,
        resolved[0].mapping_id, snapshot.catalog_version, None)

この順序は外部symbolが複数契約へ解決されること、期限外mapping、future/spread混同をfail-closedにする。continuous/parentは取引可能契約ではないため、P2-04とH2-1承認前にresolveの成功値へ昇格しない。
