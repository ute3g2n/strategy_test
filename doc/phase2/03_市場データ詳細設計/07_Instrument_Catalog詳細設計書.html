1. ドメインの概要: 銘柄台帳は何をするものか

銘柄台帳は、外部提供元が使う記号や番号を、システムの中で変わらない内部銘柄番号へ結び付ける部品である。同じように見える記号でも、時期、取引所、満期、商品種別が違えば別の契約であるため、台帳はその違いと有効な期間を残す。

また、最小価格変動、契約の大きさ、取引時間、休日などを、いつの情報か分かる形で保管する。台帳が一つに決められない場合や必要な属性が未確認の場合は、元データを取引可能な銘柄として扱わずに止める。

利用者期待することこのドメインが返すもの
市場データ受渡し部外部の記号を観測した時点で、内部銘柄番号に一意に対応付けられることを期待する。一意の内部銘柄番号と対応関係の根拠、または対応できない理由を返す。
正規化データ保管庫価格、時刻、欠損の確認に必要な銘柄定義と取引時間を期待する。最小価格変動、営業日、対応関係の有効期間を返す。
再生処理過去の実行で使った銘柄の意味を、後から同じように解釈できることを期待する。固定したcatalog_versionと、その内容確認値を返す。
機能ID機能誰にでも分かる説明失敗時の動き
IC-F01内部銘柄番号を管理する外部の記号そのものではなく、契約の中身から一意になる内部番号を作り、後から変えない。契約の中身が足りず一意に決められない場合は、新しい番号を作らず保留する。
IC-F02外部記号との対応を管理する外部の記号が、いつからいつまでどの内部番号を意味するかを根拠付きで記録する。候補が複数、期間外、根拠不足の場合は、任意の候補を選ばず利用不可にする。
IC-F03契約と営業日の属性を管理する価格の最小単位、契約の大きさ、取引時間、休日を版付きで残す。未確認の属性をゼロや既定値で埋めず、品質確認または取引可能化を止める。

送る部品受け取る部品渡すデータ・依頼受け取り側の用途と停止条件
外部記号の観測台帳の検査SymbolObservationとして、提供元、データ集合、記号、記号形式、観測時刻、契約属性の材料を渡す。台帳の検査は観測内容を根拠として確認する。必須の属性が欠ける場合は、既定値で補わず停止理由にする。
営業日と契約属性台帳の検査営業日、契約の有効期間、最小価格変動、契約倍率などの確認済み属性を渡す。台帳の検査は観測内容と期間・属性の矛盾を見つける。不明な属性を含む候補は検査済みにしない。
台帳の検査台帳版の保存検査済みの銘柄、対応関係、営業日、作成元の元データ識別子からなる台帳候補を渡す。台帳版の保存は同じ内容に一つの版を割り当てる。検査に通らない候補や根拠のない要素は保存しない。
台帳版の保存銘柄番号を検索内容確認値で固定したCatalogSnapshotを渡す。銘柄番号を検索する処理は、検索途中で台帳内容が変わらないよう固定した版だけを使う。版が固定できなければ検索しない。
営業日と契約属性銘柄番号を検索記号が有効である期間と、契約の識別に必要な属性を渡す。検索処理は観測時刻に有効な候補だけを照合する。期間外または属性不足なら、一意な対応として返さない。
銘柄番号を検索正規化データへ渡すResolveInstrumentResultとして、対応状態、一意に決まったInstrumentId、判断根拠を渡す。正規化データの処理はresolvedだけを受け入れる。複数候補、不明、停止状態では市場データ行を作らない。
銘柄番号を検索理由を記録して停止対応できなかった理由、候補一覧、使用した台帳版を渡す。停止処理は推測による対応を行わず、理由を記録して当該行を後続の正規化から除外する。
台帳版の保存監査記録保存した台帳版番号、内容確認値、作成元の元データ識別子を渡す。監査記録は台帳が何を根拠に作られたかを追えるようにする。追記できなければ保存成功として公開しない。
理由を記録して停止監査記録停止理由、候補一覧、対象の観測識別子を渡す。監査記録は未対応を見える形で残す。理由のない停止や、理由のない成功を作らない。

4. モジュール仕様と入出力パラメータ

この表は、各ファイルが何を担当し、何を受け取り、何を返すかを説明する。外部提供元の記号や数値は型の一項目として保持しても、内部銘柄番号の代わりにしない。

ファイル / 実装単位機能説明入力出力副作用・禁止事項
catalog_validation.py / CatalogValidator.validate銘柄の同一性、対応期間、契約種別、必須属性を検査する。観測から作った銘柄候補、対応関係、契約属性、営業日を受け取る。ValidationResultとして、利用可否と理由を返す。不足値を既定値で埋めない。未確認なら停止理由として返す。
catalog_snapshot.py / SnapshotBuilder.build検査済みの銘柄、対応関係、営業日を一つの不変な台帳版へまとめる。検査済みの台帳要素と、作成元の元データ識別子を受け取る。CatalogSnapshotとして、版番号、内容確認値、全要素を返す。異なる内容を同じ版番号として作らない。根拠のない要素を含めない。
catalog_repository.py / LocalCatalogRepository.write_if_absent台帳版と内容確認値を保存し、同じ内容なら既存版を再利用する。CatalogSnapshotと、秘密を含まない監査情報を受け取る。保存した版番号と内容確認値を返す。既存版を上書きしない。書込み途中の版を完成版として見せない。
catalog_resolver.py / CatalogResolver.resolve外部記号、形式、時刻から、一つの内部銘柄番号を探す。ResolveInstrumentRequestとして、提供元、データ集合、記号、時刻を受け取る。ResolveInstrumentResultとして、対応状態、内部銘柄番号、根拠を返す。候補が複数または属性が不足なら成功を返さず、通常の市場データ行を作らせない。
catalog_audit.py / CatalogAudit.append台帳版の作成元、検索根拠、停止理由を追記形式で残す。版番号、対応関係番号、理由、元データ識別子を受け取る。追記できたことだけを返す。秘密の値を記録しない。監査記録が残せない場合は検索成功として返さない。

6. テスト仕様

この表は、本書の範囲で必要な全試験を示す。各セルは単語だけで済ませず、技術者以外の読者も、何を確かめ、どの状態なら合格なのかを判断できる文章で書く。

テストIDテスト概要テスト条件（入力値）操作期待結果合否判定基準
IC-T01根拠と必須属性がそろった個別契約から、不変の内部銘柄番号を作れることを確認する。取引所、商品根、満期年、満期月、契約種別、作成元の元データ識別子を持つ固定の銘柄候補を用意する。CatalogValidator.validateと内部番号の生成処理を呼び出す。検査済みの銘柄候補と、外部記号を含まない内部銘柄番号が返る。同じ契約候補から二回作っても同じ番号となり、外部提供元の番号が内部番号に含まれないこと。
IC-T02契約の同一性を決める情報が不足する場合、新しい内部銘柄番号を勝手に作らないことを確認する。満期年または商品根が欠けた先物候補を用意する。CatalogValidator.validateを呼び出す。UNKNOWN_INSTRUMENT_IDENTITYを含む不合格結果が返る。内部銘柄番号が発行されず、保留理由と元データ識別子が監査記録に残ること。
IC-T03同じ契約を別の外部提供元が表しても、同じ正規化された契約情報なら同じ内部番号へ対応することを確認する。外部提供元名と外部記号だけが異なり、取引所、商品根、満期、種別が同じ二つの観測を用意する。二つの観測を検査して内部番号を作る。二つの対応関係は別に保存されるが、同じ内部銘柄番号を参照する。外部提供元ごとに別の内部番号を作らず、両方の根拠を台帳版からたどれること。
IC-T04有効期間内で候補が一つだけの外部記号を、内部銘柄番号へ解決できることを確認する。指定時刻を含む有効期間を持ち、resolved状態の対応関係を一件だけ含む台帳版を用意する。CatalogResolver.resolveを呼び出す。status="resolved"、内部銘柄番号、対応関係番号を持つ検索結果が返る。返された対応関係の期間が指定時刻を含み、銘柄状態が利用可能であること。
IC-T05同じ記号と時刻で複数の対応関係が有効な場合、任意の一件を選ばずに停止することを確認する。同じ提供元、データ集合、形式、記号、時刻に対して、二件のresolved対応関係が有効となる台帳版を用意する。CatalogResolver.resolveを呼び出す。status="ambiguous"の結果が返り、内部銘柄番号は空になる。通常用の市場データ行が作られず、複数候補の対応関係番号が監査記録に残ること。
IC-T06対応関係の有効期間外の記号を、過去または将来の契約として勝手に解決しないことを確認する。指定時刻がvalid_from_utcより前、またはvalid_to_utc以降となる検索依頼を用意する。CatalogResolver.resolveを呼び出す。status="not_found"または期間外を示す理由が返る。内部銘柄番号が返らず、指定時刻を現在時刻で補正していないこと。
IC-T07親記号や連続系列を、個別の取引可能な先物契約として扱わないことを確認する。親記号または連続系列を示すstypeと、個別契約を一意に選ぶ規則が未承認の台帳版を用意する。CatalogResolver.resolveを呼び出す。status="unknown"または保留結果が返り、個別契約の内部番号は返らない。連続契約の未承認規則だけでresolvedを返さず、H2-1承認待ちの理由が残ること。
IC-T08取引停止、満期切れ、不明状態の契約を、取引可能な銘柄として返さないことを確認する。statusがhalted、expired、またはunknownの銘柄を持つ対応関係を用意する。CatalogResolver.resolveを呼び出す。利用不可を示す検索結果が返り、内部銘柄番号は通常利用へ渡されない。返却状態がresolvedではなく、正規化データ保管庫がその銘柄を使えないこと。
IC-T09最小価格変動が未確認の契約を、価格確認に使える状態にしないことを確認する。tick_sizeまたは価格の桁情報が欠けた個別契約を用意する。CatalogValidator.validateを呼び出す。必須属性不足を示す不合格またはunknown状態が返る。正規化データ保管庫へ価格確認可能な契約として渡されず、欠損をゼロで補っていないこと。
IC-T10契約の大きさが未確認のとき、仮の値で損益やリスクを計算できる状態にしないことを確認する。contract_multiplierが欠けた個別契約を用意する。CatalogValidator.validateを呼び出す。属性不足を示す状態が返り、証拠金や取引量の判断に使えないことが記録される。数値の0や既定値が入らず、後続のRisk処理へ利用可能として渡されないこと。
IC-T11営業日情報がない場合、欠損判定を合格にしないことを確認する。取引時間または休日情報が欠けたTradingCalendarを参照する契約を用意する。CatalogValidator.validateを呼び出す。UNKNOWN_SESSION_STATEを含む利用不可の結果が返る。正規化データ保管庫がその契約の空区間を取引なしとして扱えず、品質確認が停止すること。
IC-T12同じ内容の台帳版を二回保存しても、一つ目を改変せずに再利用できることを確認する。同じ銘柄、対応関係、営業日、根拠を持つCatalogSnapshotを二回用意する。LocalCatalogRepository.write_if_absentを二回呼び出す。二回目は最初と同じ台帳版番号を返し、新しい内容を書き込まない。二回目の内容確認値と保存済みJSONが一回目と一致し、監査記録が過去内容を更新していないこと。
IC-T13同じ台帳版番号に異なる内容を書き込もうとした場合、過去の台帳を上書きしないことを確認する。同じcatalog_versionで、対応関係または契約属性が異なる二つの台帳を用意する。一つ目を保存した後に二つ目のLocalCatalogRepository.write_if_absentを呼び出す。二つ目は整合性エラーとなり、最初の台帳版は変わらない。先のJSONと内容確認値が維持され、異なる内容が同じ保存場所へ混ざらないこと。
IC-T14台帳版の保存中に失敗した場合、未完成のJSONを利用可能な版として見せないことを確認する。一時ファイルから完成場所への名前変更が失敗する保存環境を用意する。LocalCatalogRepository.write_if_absentを呼び出す。保存失敗の結果が返り、完成した台帳版番号は返らない。未完成の一時ファイルが検索処理から読めず、同じ入力で後から安全に再実行できること。
IC-T15保存済みの台帳版が後から改変された場合、内容確認値の不一致として検出できることを確認する。正しく保存した台帳JSONの一項目だけを、内容確認値を更新せずに変更した状態を用意する。LocalCatalogRepository.loadを呼び出す。CatalogIntegrityErrorが返り、改変された台帳版を検索に使わない。内容確認値の再計算結果と保存値の不一致が監査記録に残り、resolveが実行されないこと。
IC-T16対応関係を更新するとき、過去の有効期間を持つ行を直接書き換えず、新しい版として残せることを確認する。既存の対応関係と、その後の期間に適用する異なる対応関係を用意する。新しい対応関係を含むCatalogSnapshotを作って保存する。過去の台帳版は不変のまま残り、新しい版にだけ新しい対応関係が入る。過去の再生実行が旧版を読むと旧対応関係を再現でき、新版を読む場合だけ新しい対応関係となること。
IC-T17証拠金の仮置き値が未確認の場合、注文可否を決める値として使わないことを確認する。initial_marginまたはmaintenance_marginが空で、status="unknown"の属性を用意する。契約属性の検査と取引可能性の判定を呼び出す。仮置き値は台帳に残せるが、取引可能性またはリスク計算の成功結果には使われない。空値を0へ置換せず、後続の注文可否へ値を渡さないこと。
IC-T18検索成功の監査記録が残せない場合、成功として内部銘柄番号を返さないことを確認する。検索条件は正しいが、CatalogAudit.appendが書込み失敗を返すようにした環境を用意する。CatalogResolver.resolveを呼び出す。監査記録失敗の結果となり、通常利用へ渡すresolved結果は返らない。内部銘柄番号、対応関係番号、検索理由のいずれかが記録できないまま成功扱いにしていないこと。
IC-T19正規化データ保管庫との結合で、対応関係の根拠まで持つ内部銘柄番号を渡せることを確認する。P2-D05の観測に相当する固定入力、一意の対応関係、P2-D06が受け取る変換依頼を用意する。銘柄検索後にP2-D06の変換処理を呼び出す。正規化行に内部銘柄番号、対応関係番号、元データ識別子が入る。外部記号だけを持つ行が保存されず、後から台帳版と元データまで逆引きできること。
IC-T20再生処理が固定した台帳版だけを使い、現在の台帳内容を混ぜないことを確認する。同じ外部記号に対して旧版と新版で異なる対応関係を持つ二つの台帳版と、旧版を指定するRun Manifestを用意する。指定された旧版でCatalogResolver.resolveを呼び出す。旧版に記録された対応関係だけが使われ、新版の内容は参照されない。返されたcatalog_versionと内容確認値がRun Manifestと一致し、現在版へ自動的に切り替わらないこと。

出来事の固定名作る条件受け取る先成功として知らせるための条件
CatalogVersionPublished検査済みの台帳JSONと内容確認値を完成場所へ保存できたときに作る。正規化データ保管庫と再生処理が受け取る。保存後に読み直した内容確認値が、作成した台帳版の値と一致していること。

11. エラー分類と閉じた側へ倒す規則

この表は、台帳の判断に失敗したときに何を止めるかを決める。対象の契約を一つに決められないなら、売買に使える銘柄として返さない。

エラーの固定名起きた状況の例この部品が行う処理利用可否と停止判断
UNKNOWN_INSTRUMENT_IDENTITY取引所、商品根、満期、種別など、内部番号を一意にする情報が不足している。内部銘柄番号を発行せず、不足項目と作成元を監査記録へ残す。保留状態とし、正規化データ・再生・売買判断へ渡さない。
MAPPING_AMBIGUOUS同じ外部記号と時刻に、複数の有効な対応関係が見つかる。候補を全て記録し、任意の一件を選ばない。内部銘柄番号を返さず、該当行を通常利用から除外する。
MAPPING_OUT_OF_RANGE指定時刻が対応関係の有効期間に入らない。期間外であることと検索条件を記録する。過去または将来の対応を流用せず、通常利用を停止する。
CATALOG_INTEGRITY_FAILED台帳JSONの内容確認値、形式の版、保存物が一致しない。改変または破損した版を読み込まず、監査記録へ残す。その台帳版を使う再生処理と銘柄検索を停止する。
REQUIRED_ATTRIBUTE_UNKNOWN最小価格変動、契約の大きさ、営業日などが未確認である。未確認のままにして、値をゼロや既定値で補わない。必要な処理に応じて品質確認または取引可能化を停止する。

12. 利用可否の状態

この表は、銘柄または対応関係を後続で使ってよいかを状態ごとに説明する。状態が不明な銘柄を、利用可能な銘柄と同じように扱わない。

状態を表す固定値人にとっての意味後続での使い方
RESOLVED根拠、有効期間、契約状態、必須属性を確認し、一つの内部銘柄番号に決まった。正規化データの行に内部銘柄番号と対応関係番号を入れて使える。
PENDING観測はあるが、根拠の確認または台帳版の保存がまだ終わっていない。通常利用へ渡さず、確認が終わるまで保留する。
AMBIGUOUS候補が複数あり、どの契約を意味するか決められない。任意の候補を選ばず、該当行を停止する。
UNAVAILABLE満期切れ、取引停止、期間外、台帳改変、必須属性不足のため利用できない。再生・売買判断へ渡さず、監査または再調査だけに使う。
UNKNOWN必要な事実または規則が足りず、利用可否を決められない。Passにせず、Unknown台帳の決定または人間承認まで停止する。

実行方法受け取る入力この部品の動き許される変更

catalog_validation検査結果と不足項目だけを公開する。共通データ型、台帳候補、作成元の識別子を参照してよい。外部提供元へ問い合わせたり、未確認値を補ったりしない。
catalog_repository台帳版の保存と読取口だけを公開する。共通データ型、内容確認値の計算、ファイル操作を参照してよい。記号の解釈、売買判断、外部通信を担当しない。
catalog_resolver一意な内部銘柄番号を探す受取口だけを公開する。検証済みの台帳版と監査記録口だけを参照してよい。台帳版を直接書き換えたり、候補を勝手に選んだりしない。

ここでは、実装者が作る主な型と関数の形を示す。英語はPythonの予約語、型名、変数名だけであり、業務上の意味は前後の日本語で説明する。

from dataclasses import dataclass
from datetime import datetime

    stype_out: str
    output_symbol: str

    valid_to_utc: datetime | None
    status: str
    source_raw_object_id: str

class CatalogRepository(Protocol):
    def load(self, catalog_version: str) -> "CatalogSnapshot": ...
    def write_if_absent(self, snapshot: "CatalogSnapshot") -> str: ...

次の表は、上の公開関数を人が判断できる言葉で説明する。検索の成功は、台帳版の内容確認値、対応関係の期間、契約の状態を通過した場合だけである。

関数の固定名返すもの起こり得るエラー繰り返し実行した場合と変更の内容
load内容確認値まで検査した不変の台帳版を返す。版がない、形式が違う、内容確認値が違う場合に停止する。読み取りだけを行い、保存済みの台帳版を変更しない。
write_if_absent保存した、または再利用した台帳版番号を返す。同じ番号に異なる内容を書こうとした、書込みが失敗した場合に停止する。同じ内容なら既存版を返し、異なる内容は別の版として扱う。
resolve一意の内部銘柄番号と対応関係番号、または利用できない理由を返す。複数候補、期間外、属性不足、監査記録失敗の場合に成功を返さない。検索だけを行い、台帳版や対応関係を変更しない。

18. 誤実装しやすい規則のコード例

この節は、対応関係を時刻で絞り、候補が一件以外なら成功にしない規則を示す。現在時刻を使って過去の検索条件を補正してはならない。

def resolve(snapshot: CatalogSnapshot,
            request: ResolveInstrumentRequest) -> ResolveInstrumentResult:
    candidates = [mapping for mapping in snapshot.mappings
        if mapping.vendor == request.vendor
        and mapping.dataset_id == request.dataset_id
        and mapping.stype_in == request.stype
        and mapping.input_symbol == request.symbol
        and mapping.valid_from_utc <= request.event_time_utc
        and (mapping.valid_to_utc is None
             or request.event_time_utc < mapping.valid_to_utc)]
    resolved = [mapping for mapping in candidates
        if mapping.status == "resolved" and mapping.instrument_id is not None]
    if len(resolved) != 1:
        return ResolveInstrumentResult("ambiguous" if len(resolved) > 1 else "not_found",
            None, None, snapshot.catalog_version, "MAPPING_NOT_UNIQUE")
    instrument = snapshot.by_id(resolved[0].instrument_id)
    if instrument.status != "active" or instrument.tick_size is None:
        return ResolveInstrumentResult("unknown", None, resolved[0].mapping_id,
            snapshot.catalog_version, "REQUIRED_ATTRIBUTE_UNKNOWN")
    return ResolveInstrumentResult("resolved", instrument.instrument_id,
        resolved[0].mapping_id, snapshot.catalog_version, None)

20. 人間承認の対象

H2-1では、内部銘柄番号の同一性、外部記号との対応期間、最小価格変動と契約の大きさの必須性、営業日版、連続契約を個別契約と同一視しない方針を承認する。H2-2で実取得、費用、利用権限を承認するまでは、実値を台帳の確定値として採用しない。
