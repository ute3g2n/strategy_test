1. 目的と境界

本書は、Databento等の外部Market Data sourceを内部のRaw Store、Normalized Store、Instrument Catalog、Replay入力へ接続するAdapterの実装可能な契約を定義する。外部SDK、HTTP型、vendor symbol、API keyをCore、Strategy、Risk、OMSへ漏らさない。

対象責務非対象
Market Data Adapter取得要求、外部応答のRaw化、mapping/definition取得、エラー分類、HealthEvent生成。Strategy判断、売買注文、Risk判断、roll ruleの最終採否。
内部Port外部に依存しないRequest/Result/Event/Health契約を提供する。Databento client object、HTTP response、API key値の公開。
後続Store/CatalogRaw/Normalized永続化と内部InstrumentIdの正本管理へ渡す。Rawの改変、品質警告の削除、未知状態の成功変換。

4. 出力イベントと順序

イベント生成条件下流品質条件
RawBatchReceivedpayload、metadata、checksumを保存できた。Raw Store、DataVersion Builder保存成功とchecksum計算が揃わない限り発行しない。
SymbolMappingResolved指定期間のmappingが完全かつ一意に解決された。Instrument Catalogpartial/ambiguousなら別の警告イベントとし、成功イベントにしない。
InstrumentDefinitionUpdated定義の新規観測または有効期間更新。Instrument Catalog過去のCatalog行を上書きせず、effective periodを追加する。
MarketDataGapDetected期待セッションと受信範囲の不一致、またはcondition異常。Data Gate、Health対象範囲をSignal/Replayから除外または停止。
MarketDataConnectionChanged接続、認証、再接続、切断状態が変化。Health、Execution ModelLive/Paperでは新規利用を停止し、Backtestではfailure injection対象。
DataVendorRateLimitedrate limitとRetry-Afterを観測。Health、Retry Coordinator上限回数超過後は停止。無制限再試行をしない。

5. エラー分類とFail-closed

ErrorCode例処理Health / Gate
AUTHENTICATION_FAILEDSecret不在、認証失敗Secret値をログに出さず停止。手動確認待ち。Unhealthy / Data Gate stop
ENTITLEMENT_DENIEDdataset権限不足、費用上限実取得を停止し、H2-2または再承認へ。Unknown / Human Gate
RATE_LIMITEDHTTP 429Retry-Afterのみを使った限定再試行。上限後停止。DegradedからUnhealthy
SYMBOL_PARTIALHTTP 206、部分解決解決済み部分だけを本線へ流さない。対象をPending。Data Gate stop
SYMBOL_NOT_FOUND404、候補不在候補を除外または条件付きへ隔離。自動代替しない。Unknown ledger
DATASET_DEGRADEDdegraded/pending/missing該当日・範囲にquality flagを付与し、採用不可として扱う。Data Gate stop/degrade
CHECKSUM_MISMATCH再取得したpayloadとの差異、破損新規Rawとして隔離し、既存Rawを置換しない。Integrity Gate stop
DECODE_OR_SCHEMA_ERRORDBN/CSVの解読・schema不一致Normalized化しない。原形とエラー証跡を保存。Data Gate stop
STORE_WRITE_FAILEDRaw/Normalized保存失敗受信成功を下流へ通知しない。再試行後停止。Health Unhealthy
UNKNOWN_EXTERNAL_STATEmapping、定義、conditionが不明Unknownとして台帳化し、Strategy/Replay入力へ流さない。Unknown / fail-closed

6. HealthEvent状態

health_state意味下流利用
HEALTHY取得、保存、mapping、品質確認が完了。通常利用可能。
DEGRADED警告はあるが対象範囲が明確で、隔離可能。明示的に縮退指定された範囲だけ利用。
UNHEALTHY取得、保存、整合性、認証の重大失敗。対象Market Data利用を停止。
UNKNOWN状態を判定できない、または観測が欠けている。Passにせず停止。人間または後続Stepで決定。

10. 型付き公開契約

from dataclasses import dataclass
from datetime import UTC, datetime
from hashlib import sha256
from typing import Literal, Protocol

@dataclass(frozen=True)
class HistoricalRequest:
    request_id: str                 # required; caller-generated UUID text
    dataset_ref: str                # required; e.g. vendor/dataset alias, not a Secret
    schema_ref: str                 # required
    symbols: tuple[str, ...]        # required; non-empty; vendor syntax stays here
    start_utc: datetime             # required; timezone-aware UTC
    end_utc: datetime               # required; start_utc < end_utc
    source_mode: Literal["fixture", "external"]

@dataclass(frozen=True)
class GatewayPayload:
    payload: bytes
    metadata: dict[str, str]        # Secret/authorization header is prohibited
    condition: Literal["available", "degraded", "pending", "missing", "unknown"]

class VendorGateway(Protocol):
    def fetch(self, request: HistoricalRequest) -> GatewayPayload: ...

class HistoricalDataPort(Protocol):
    def ingest(self, request: HistoricalRequest) -> "IngestionResult": ...
@dataclass(frozen=True)
class IngestionResult:
    raw_object_id: str
    payload_sha256: str
    health_event_id: str
    created: bool

@dataclass(frozen=True)
class HealthEvent:
    event_id: str
    component_name: Literal["market_data_adapter"]
    state: Literal["HEALTHY", "DEGRADED", "UNHEALTHY", "UNKNOWN"]
    reason_code: str
    affected_range_start_utc: datetime | None
    affected_range_end_utc: datetime | None
    observed_at_utc: datetime

    @classmethod
    def degraded(cls, request_id: str, reason_code: str) -> "HealthEvent":
        return cls(request_id, "market_data_adapter", "DEGRADED", reason_code,
                   None, None, datetime.now(UTC))
API戻り値エラー冪等性・副作用
ingest(request)IngestionResult(raw_object_id, sha256, health_event_id)InvalidRequest, ExternalStateError, RawWriteErrorrequest fingerprintが同じpayloadなら既存Raw参照を返す。新payloadは新Rawとしてのみ保存。
gateway.fetch(request)GatewayPayloadAuthenticationError, RateLimited, PartialSymbolResolution副作用はGateway内部だけ。CoreへHTTP/SDK例外を送らない。
reporter.record(event)None永続化不能時は呼出元をUNHEALTHYへ遷移監査イベントは追記のみ。

11. 正常系・失敗系シーケンス

正常系
Caller -> IngestionService.ingest(fixture request)
  -> validate UTC range / H2-2 source_mode
  -> VendorGateway.fetch
  -> sha256(payload), request fingerprint
  -> RawStore.put_if_absent
  -> HealthReporter.record(HEALTHY)
  -> IngestionResult (RawBatchReceivedの内部表現)

失敗系: partial / degraded / checksum or write failure
  -> RawStoreへ成功として通知しない
  -> HealthReporter.record(DEGRADED or UNHEALTHY)
  -> DataGate入力へ対象rangeとreason_codeを渡す
  -> Normalizer / Replay / SignalへMarketEventを発行しない
  -> retry可能なのはRATE_LIMITEDのみ。Retry-After不明または上限到達は停止。

復旧: 再実行は同じrequest fingerprintで開始する。payload hashが異なる場合は旧Rawを更新せず、P2-D06のredelivery_diffを作成し、UNKNOWN_EXTERNAL_STATEとしてData Gateを停止する。

def ingest(self, request: HistoricalRequest) -> IngestionResult:
    if request.source_mode == "external" and not self.h2_2_approved:
        raise ExternalStateError("EXTERNAL_FETCH_NOT_APPROVED")
    if request.start_utc.tzinfo is None or request.end_utc.tzinfo is None:
        raise InvalidRequest("UTC_REQUIRED")
    payload = self.gateway.fetch(request)
    if payload.condition != "available":
        self.reporter.record(HealthEvent.degraded(request.request_id, payload.condition))
        raise ExternalStateError(f"DATASET_{payload.condition.upper()}")
    digest = sha256(payload.payload).hexdigest()
    return self.raw_store.put_if_absent(request, payload, digest)

13. 設定、監査、テスト、Manifest

区分契約
設定MARKET_DATA_SOURCE_MODEはfixtureが既定。MARKET_DATA_VENDOR_API_KEYは将来Gatewayだけが参照する名前であり、値・存在有無をHTMLやログへ出さない。

テスト正常fixture、H2-2未承認external、partial、degraded、429相当、破損payload、Raw書込失敗、同一payload再実行、異なるpayload再取得を単体テスト化する。

14. H2-1承認対象

H2-1では、Raw/Normalized/Catalogの方式、main/conditional候補の扱い、continuousまたは明示的contract selectionの方式、roll ruleのversioning、degradedデータの停止・縮退方針、Phase 3へ渡すdata_version契約を承認する。

承認前は、roll済み系列を本線へ昇格しない。UnknownをPassにせず、fixtureまたは対象範囲縮退で設計・テストを続ける。
