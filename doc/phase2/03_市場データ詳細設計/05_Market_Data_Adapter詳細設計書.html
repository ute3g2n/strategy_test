1. ドメインの概要: 市場データ受渡し部は何をするものか

市場データ受渡し部（Market Data Adapter）は、外部データ提供元から届く市場データを、システムが安全に保管し、後で同じ条件で読み直せる形に受け渡すための入口である。データ提供元ごとの呼び方、通信方式、銘柄記号の表記、認証方法を、この入口の内側だけに閉じ込める。

たとえば、外部から「ある銘柄の1分足をください」と受け取ったデータを、そのまま戦略へ渡すことはしない。まず元のデータを改変せず保管し、どの条件で取得したか、壊れていないか、必要な銘柄が全部そろったかを確認する。問題があれば、下流へ進めずに理由を残して止まる。これがこのドメインの役目である。

利用者このドメインに期待することこのドメインが返すもの
P2-05の取得ジョブ指定期間・指定銘柄のデータを安全に取り込む。Raw保存結果、checksum、健康状態、失敗理由。
Raw / Normalized Store元データと取得条件を改変せず受け取る。payload、metadata、request fingerprint、受信時刻。
Instrument Catalog外部シンボルを内部InstrumentIdへ対応付ける材料を受け取る。symbol解決結果、definition観測、失敗理由。
Replay / Data Quality問題のあるデータを混ぜず、再現できる版を使う。健康状態、quality理由、Raw参照、data_version候補。
機能ID機能誰にでも分かる説明失敗時
MDA-F01取得依頼の確認期間、時刻、銘柄、利用モードに抜けや矛盾がないかを、外部へ問い合わせる前に確認する。問い合わせずにInvalidRequestを返す。
MDA-F02データ取得fixtureまたは将来の提供元Gatewayから、元データと取得に関する説明を受け取る。認証、権限、部分取得、rate limitを成功にしない。
MDA-F03Raw保存への受渡し元データの指紋を計算し、同じ内容を何度も上書きしない形でRaw Storeへ渡す。保存失敗時は「取得成功」と知らせない。
MDA-F04シンボルと契約情報の観測外部の名前を内部の銘柄台帳が判断できる材料へ変換する。ただし台帳を勝手に確定しない。一意に決まらなければPendingとして止める。
MDA-F05健康状態と監査今のデータが使えるか、どこで問題になったかを、Secretを出さずに記録する。DEGRADED、UNHEALTHY、UNKNOWNでは下流利用を止める。

4.1 HistoricalRequestの入力パラメータ

パラメータ名型必須説明と検証
request_idstr必須呼出側が一意に付与する依頼ID。空文字不可。再試行時も同じ論理依頼なら保持する。
dataset_refstr必須datasetを指す公開可能な別名。API keyやURL queryを含めない。
schema_refstr必須要求するデータ形式の別名。未確認schemaを既定値で補完しない。
symbolstuple[str, ...]必須1件以上。外部表記はこの値の中だけに留め、Core IDとして扱わない。
start_utcdatetime必須timezone-aware UTC。end_utcより前であること。
end_utcdatetime必須timezone-aware UTC。未来時刻を勝手に丸めない。
source_mode"fixture" | "external"必須externalはH2-2承認済みだけ。未承認なら即時停止。

5.3 symbol / definition観測フロー

これは、外部の銘柄記号を銘柄台帳へ伝える流れである。この部品は観測した事実を渡すだけで、内部銘柄番号を自分で決めない。

flowchart LR
    依頼["銘柄記号・契約情報の照会依頼"] --> 取得["外部表記のまま照会する"]
    取得 --> 判定{"一つの候補に決まったか"}
    判定 -- "いいえ。候補不足・複数候補・未発見" --> 保留["保留と問題理由を記録する"]
    保留 --> 停止["銘柄台帳へ成功として渡さない"]
    判定 -- はい --> 観測["観測した事実をまとめる"]
    観測 --> 台帳["銘柄台帳へ観測記録を渡す"]
    台帳 --> 受領["受領結果を受け取る"]

内部銘柄番号（InstrumentId）を作るのはP2-D07の銘柄台帳だけである。

6. テスト仕様

本表はP2-D05が要求する全テストケースである。P2-05で機能を増やす場合は、対応するケースを追加してから実装する。テスト入力はすべてfixtureまたはmockであり、外部APIを呼ばない。

テストIDテスト概要テスト条件（入力値）操作期待結果合否判定基準
MDA-T01問題のない固定入力を、元データ保管庫へ安全に渡せることを確認する。協定世界時の開始・終了時刻、有効なdataset_refとschema_ref、銘柄記号1件、source_mode="fixture"、内容が正しい固定入力ファイルを用意する。取得受取口のingestを一度呼び出す。元データが保管され、利用可能状態（HEALTHY）と取込結果が返る。created=trueであり、保管済みの内容確認値が入力内容と一致し、状態記録がHEALTHYになっていること。
MDA-T02依頼を識別する番号が空の場合、外部へ問い合わせずに止めることを確認する。request_id=""とし、それ以外は一見正しい取得依頼を用意する。依頼確認処理のvalidate_requestを呼び出す。不正な依頼を示すInvalidRequestが返る。データ取得口、元データ保管庫、状態記録部のいずれも一度も呼ばれていないこと。
MDA-T03対象銘柄が一件も指定されない場合、あいまいな取得を開始しないことを確認する。symbols=()とし、空の銘柄一覧を持つ取得依頼を用意する。依頼確認処理のvalidate_requestを呼び出す。不正な依頼を示すInvalidRequestが返る。理由コードがSYMBOLS_REQUIREDであり、外部取得処理が始まらないこと。
MDA-T04世界共通時刻か判別できない時刻を、取得条件として受け入れないことを確認する。start_utc.tzinfo=Noneとし、時間帯情報を持たない開始時刻を用意する。依頼確認処理のvalidate_requestを呼び出す。不正な依頼を示すInvalidRequestが返る。理由コードがUTC_REQUIREDであり、時刻を勝手に補正して取得を続けないこと。
MDA-T05終了時刻が開始時刻以前の依頼を、取得前に止めることを確認する。start_utc >= end_utcとなる、時間の並びが逆または同じ取得依頼を用意する。依頼確認処理のvalidate_requestを呼び出す。不正な依頼を示すInvalidRequestが返る。データ取得口が一度も呼ばれず、誤った期間での取得が始まらないこと。
MDA-T06人間承認前の外部取得を、通信も保管も行わずに止めることを確認する。source_mode="external"かつh2_2_approved=falseの取得依頼を用意する。取得受取口のingestを呼び出す。外部状態が未承認であることを示すExternalStateErrorが返る。ネットワークへ接続する取得口と元データ保管庫が呼ばれず、成功結果が一切返らないこと。
MDA-T07固定入力を使う試験では、外部ネットワークへ接続しないことを確認する。内容が正しい固定入力を指定した、source_mode="fixture"の取得依頼を用意する。FixtureGateway.fetchを呼び出す。固定入力の内容が取得結果として返る。外部通信を行う部品が生成されず、模擬部品の呼出し履歴にも通信が残らないこと。
MDA-T08指定された固定入力ファイルが存在しないとき、成功扱いにしないことを確認する。存在しない固定入力ファイルの場所を設定した取得依頼を用意する。FixtureGateway.fetchを呼び出す。固定入力が見つからないことを示すFixtureNotFoundが返る。元データの保管、利用可能状態の記録、取込成功結果のいずれも作られないこと。
MDA-T09認証情報を含む説明情報を、保存も記録もせずに拒否することを確認する。metadata={"authorization":"x"}のように、認証情報らしい項目を含む取得結果を用意する。取得受取口のingestを呼び出す。説明情報が不正であることを示すInvalidMetadataが返る。元データと説明情報が保管されず、認証情報の値が例外、監査記録、画面表示のどこにも現れないこと。
MDA-T10提供元が品質低下と通知したデータを、通常利用へ渡さないことを確認する。condition="degraded"を持つ取得結果を用意する。取得受取口のingestを呼び出す。ExternalStateErrorが返り、状態はDEGRADEDとして記録される。元データ取込の成功結果、実行記録の候補、再生入力のいずれも作られないこと。
MDA-T11提供元が準備中と通知したデータを、不明状態として止めることを確認する。condition="pending"を持つ取得結果を用意する。取得受取口のingestを呼び出す。ExternalStateErrorが返り、状態はUNKNOWNとして記録される。停止理由を示すreason_codeがデータ利用判定部へ渡り、後続の利用が始まらないこと。
MDA-T12提供元が欠損と通知したデータを、取得成功として扱わないことを確認する。condition="missing"を持つ取得結果を用意する。取得受取口のingestを呼び出す。ExternalStateErrorが返り、状態はUNKNOWNとして記録される。受信成功を示すイベントも、通常利用へ渡すデータも作られないこと。
MDA-T13partial symbol停止GatewayがPartialSymbolResolutionを送出ingest分類済み例外、DEGRADED解決済み一部だけをRaw/Replay本線へ渡さない。
MDA-T14認証失敗GatewayがAuthenticationErroringest分類済み例外、UNHEALTHYSecret値/Authorization値が例外・監査に含まれない。
MDA-T15権限不足GatewayがEntitlementDeniedingest分類済み例外、UNKNOWNH2-2再確認対象となり、Raw保存なし。
MDA-T16rate limit限定再試行成功最初だけRateLimited、Retry-Afterあり、次回okingest1回待機後に成功指定上限内、Retry-After未満で再試行しない。

本書は、Databento等の外部Market Data sourceを内部のRaw Store、Normalized Store、Instrument Catalog、Replay入力へ接続するAdapterの実装可能な契約を定義する。外部SDK、HTTP型、vendor symbol、API keyをCore、Strategy、Risk、OMSへ漏らさない。

12. HealthEvent状態

health_state意味下流利用
HEALTHY取得、保存、mapping、品質確認が完了。通常利用可能。
DEGRADED警告はあるが対象範囲が明確で、隔離可能。明示的に縮退指定された範囲だけ利用。
UNHEALTHY取得、保存、整合性、認証の重大失敗。対象Market Data利用を停止。
UNKNOWN状態を判定できない、または観測が欠けている。Passにせず停止。人間または後続Stepで決定。

16. 型付き公開契約

from dataclasses import dataclass
from datetime import UTC, datetime
from hashlib import sha256
from typing import Literal, Protocol

@dataclass(frozen=True)
class HistoricalRequest:
    request_id: str                 # required; caller-generated UUID text
    dataset_ref: str                # required; e.g. vendor/dataset alias, not a Secret
    schema_ref: str                 # required
    symbols: tuple[str, ...]        # required; non-empty; vendor syntax stays here
    start_utc: datetime             # required; timezone-aware UTC
    end_utc: datetime               # required; start_utc < end_utc
    source_mode: Literal["fixture", "external"]

@dataclass(frozen=True)
class GatewayPayload:
    payload: bytes
    metadata: dict[str, str]        # Secret/authorization header is prohibited
    condition: Literal["available", "degraded", "pending", "missing", "unknown"]

class VendorGateway(Protocol):
    def fetch(self, request: HistoricalRequest) -> GatewayPayload: ...

class HistoricalDataPort(Protocol):
    def ingest(self, request: HistoricalRequest) -> "IngestionResult": ...
@dataclass(frozen=True)
class IngestionResult:
    raw_object_id: str
    payload_sha256: str
    health_event_id: str
    created: bool

@dataclass(frozen=True)
class HealthEvent:
    event_id: str
    component_name: Literal["market_data_adapter"]
    state: Literal["HEALTHY", "DEGRADED", "UNHEALTHY", "UNKNOWN"]
    reason_code: str
    affected_range_start_utc: datetime | None
    affected_range_end_utc: datetime | None
    observed_at_utc: datetime

    @classmethod
    def degraded(cls, request_id: str, reason_code: str) -> "HealthEvent":
        return cls(request_id, "market_data_adapter", "DEGRADED", reason_code,
                   None, None, datetime.now(UTC))
API戻り値エラー冪等性・副作用
ingest(request)IngestionResult(raw_object_id, sha256, health_event_id)InvalidRequest, ExternalStateError, RawWriteErrorrequest fingerprintが同じpayloadなら既存Raw参照を返す。新payloadは新Rawとしてのみ保存。
gateway.fetch(request)GatewayPayloadAuthenticationError, RateLimited, PartialSymbolResolution副作用はGateway内部だけ。CoreへHTTP/SDK例外を送らない。
reporter.record(event)None永続化不能時は呼出元をUNHEALTHYへ遷移監査イベントは追記のみ。

17. 正常系・失敗系シーケンス（詳細）

正常系
Caller -> IngestionService.ingest(fixture request)
  -> validate UTC range / H2-2 source_mode
  -> VendorGateway.fetch
  -> sha256(payload), request fingerprint
  -> RawStore.put_if_absent
  -> HealthReporter.record(HEALTHY)
  -> IngestionResult (RawBatchReceivedの内部表現)

失敗系: partial / degraded / checksum or write failure
  -> RawStoreへ成功として通知しない
  -> HealthReporter.record(DEGRADED or UNHEALTHY)
  -> DataGate入力へ対象rangeとreason_codeを渡す
  -> Normalizer / Replay / SignalへMarketEventを発行しない
  -> retry可能なのはRATE_LIMITEDのみ。Retry-After不明または上限到達は停止。

復旧: 再実行は同じrequest fingerprintで開始する。payload hashが異なる場合は旧Rawを更新せず、P2-D06のredelivery_diffを作成し、UNKNOWN_EXTERNAL_STATEとしてData Gateを停止する。

20. H2-1承認対象

H2-1では、Raw/Normalized/Catalogの方式、main/conditional候補の扱い、continuousまたは明示的contract selectionの方式、roll ruleのversioning、degradedデータの停止・縮退方針、Phase 3へ渡すdata_version契約を承認する。

承認前は、roll済み系列を本線へ昇格しない。UnknownをPassにせず、fixtureまたは対象範囲縮退で設計・テストを続ける。
