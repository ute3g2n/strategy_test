1. ドメインの概要: 元データ・正規化データ保管庫は何をするものか

このドメインは、外部から受け取った市場データを、あとから「いつ、どの条件で、何を受け取ったか」まで確かめられる形で残すための部品である。元の受信内容は元データ保管庫へそのまま保管し、利用しやすい共通の形へ変換した結果は正規化データ保管庫へ別に保管する。

この二つを分けることで、変換の規則を直した場合でも、元データを取り直したり書き換えたりせずに作り直せる。内容が壊れている、欠けている、品質が確認できない場合は、後続の再生処理や売買判断へ渡さずに止める。

利用者期待することこのドメインが返すもの
市場データ受渡し部受け取った内容を、重複保存や改変をせずに証跡として残せることを期待する。内容確認値付きの元データ識別子、または保存できない理由を返す。
再生処理どの版のデータを使ったかを後から同じ条件でたどれることを期待する。品質確認済みの正規化データ一式と、それを識別するdata_versionを返す。
品質確認担当者欠損、重複、順序異常、再取得差分を隠さず確認できることを期待する。品質報告、監査記録、停止理由を返す。
機能ID機能誰にでも分かる説明失敗時の動き
RNS-F01元データを不変に保管する受け取ったファイルと説明情報を、内容確認値を付けて保管し、後から中身を上書きしない。内容確認値を作れない場合は隔離記録だけを残し、通常の保管成功として扱わない。
RNS-F02共通形式へ変換する元データを、時刻・銘柄番号・価格・品質印を持つ共通の行へ変換する。変換、銘柄対応、品質確認のどれかが失敗した場合は正規化データの版を発行しない。
RNS-F03再現できる版を発行する使った元データ、変換規則、銘柄台帳、品質報告をまとめて、一つのデータ版として固定する。必要な証跡が一つでも欠ける場合は、再生処理に渡す版を作らない。

3.1 モジュール間データ受渡し表

この表は、図の矢印で短く示した受渡し内容を説明する。どの情報が次の処理の判断材料になり、どの情報が不足したときに処理を止めるかを、図だけでは省略された粒度で確認できる。

送る部品受け取る部品渡すデータ・依頼受け取り側の用途と停止条件
市場データ受渡し部元データ保存RawWriteRequestとして、受信した元データ、依頼の識別値、秘密を除いた説明情報を渡す。元データ保存は内容確認値を計算して不変に保存する。内容が空、または秘密を含む場合は保存せず停止する。
元データ保存共通形式へ変換保存済みの元データ識別子、内容確認値、再読込に必要な説明情報を渡す。変換処理は保存済みの内容だけを読み込む。内容確認値が一致しない場合や元データが読めない場合は変換しない。
銘柄台帳共通形式へ変換銘柄検索結果と、判断に使った台帳版を渡す。変換処理は一意に決まった内部銘柄番号だけを使う。複数候補、不明、台帳版不明なら通常行を作らない。
共通形式へ変換品質確認正規化した市場データ行と、変換時に見つけた警告・除外候補を渡す。品質確認は重複、欠損、時刻、価格を確かめる。必要な判断材料がない場合は合格にしない。
品質確認正規化データ保存合格した行、QualityReport、DataVersionManifestを渡す。正規化データ保存は合格した組だけを一つの不変な版として保存する。不合格または不明の報告では保存しない。
正規化データ保存データ版一覧保存済みのdata_version、内容確認値、構成要素の一覧を渡す。データ版一覧は後続の再生処理が同じ入力を探せるようにする。構成要素が欠ける版は公開しない。
品質確認監査記録と停止QualityReport、不合格または不明の理由、除外範囲を渡す。監査記録は理由を追記し、利用可能なデータ版を発行しない。警告を握りつぶして先へ進めない。
元データ保存監査記録と停止元データの内容確認値、保存結果、再取得時に見つけた差分を渡す。監査記録は差分を残す。既存の元データを新しい内容で置き換えず、差分の確認まで利用を止める。

4. モジュール仕様と入出力パラメータ

この表は、各ファイルが何を担当し、何を受け取り、何を返すかを説明する。固定の関数名と型名だけをcodeで示し、動作の説明は日本語で記す。

ファイル / 実装単位機能説明入力出力副作用・禁止事項
raw_store.py / LocalRawStore.put_if_absent受信内容と説明情報を内容確認値付きで保存し、同じ内容は既存の保管物を返す。RawWriteRequestとして、元データ本体、依頼の識別値、秘密を除いた説明情報を受け取る。RawWriteResultとして、元データ識別子、内容確認値、新規作成の有無を返す。完成済みの元データを更新しない。秘密らしい項目を見つけた場合は保存しない。
normalization.py / Normalizer.normalize元データを、内部銘柄番号と世界共通時刻を持つ共通行へ変換する。検査済みの元データ、銘柄台帳の対応関係、変換規則の版を受け取る。NormalizationResultとして、変換した行と品質確認へ渡す観測結果を返す。元データを変更しない。銘柄が一つに決まらない行を通常行として返さない。
quality.py / QualityChecker.check重複、時刻の逆行、欠損、価格の異常を確認し、利用できるかを決める。正規化した行、銘柄台帳の営業日情報、元データの提供状態を受け取る。QualityReportとして、問題、除外範囲、利用可否を返す。品質が不明または不合格なら、成功としてのデータ版を発行しない。
normalized_store.py / LocalNormalizedStore.write_if_absent品質確認済みの正規化行と品質報告を、一つの不変なデータ版として保存する。行の並び、品質報告、DataVersionManifestを受け取る。NormalizedSnapshotResultとして、保存した版の識別子と内容確認値を返す。既存の版を更新しない。品質報告が合格でなければ書き込まない。
manifest.py / ManifestBuilder.build再生処理が同じ入力を探せるように、利用した証跡を一つの一覧へまとめる。元データ識別子、変換規則、銘柄台帳の版、品質報告を受け取る。DataVersionManifestとして、不変のdata_versionと構成要素を返す。入力が欠ける一覧を作らない。既存のdata_versionへ別内容を上書きしない。

6. テスト仕様

この表は、本書の範囲で必要な全試験を示す。各セルは単語だけで済ませず、技術者以外の読者も、何を確かめ、どの状態なら合格なのかを判断できる文章で書く。

テストIDテスト概要テスト条件（入力値）操作期待結果合否判定基準
RNS-T01初めて受け取った元データを、内容確認値付きで不変に保存できることを確認する。空でない固定入力、秘密を含まない説明情報、有効な世界共通時刻を持つRawWriteRequestを用意する。LocalRawStore.put_if_absentを一回呼び出す。新しい元データ識別子と内容確認値が返り、元データ本体と説明情報が完成した場所へ保存される。created=trueであり、保存済み内容から再計算した内容確認値が返却値と一致すること。
RNS-T02同じ依頼と同じ内容を二度保存しても、過去の元データを増やしたり書き換えたりしないことを確認する。RNS-T01と同じRawWriteRequestを二回使えるように用意する。LocalRawStore.put_if_absentを続けて二回呼び出す。二回目は最初と同じ元データ識別子を返し、新たな保存物を作らない。二回目のcreatedがfalseであり、最初の保存物の内容確認値と更新時刻が変わらないこと。
RNS-T03同じ取得条件でも内容が異なる再取得を、過去の元データを上書きせずに区別できることを確認する。同じrequest_fingerprintで、内容確認値が異なる二つの元データを用意する。一つ目を保存した後に二つ目を保存し、差分監査の処理を呼び出す。二つの元データ識別子が残り、旧新の関係と観測時刻が監査記録へ残る。一つ目のファイル内容が変わらず、二つ目が同じ識別子へ上書きされていないこと。
RNS-T04秘密らしい項目を説明情報に含む依頼を、保存前に拒否できることを確認する。metadataにauthorizationまたはapi_keyという項目を含む依頼を用意する。LocalRawStore.put_if_absentを呼び出す。InvalidMetadataが返り、元データも説明情報も完成場所へ保存されない。例外と監査記録に秘密の値そのものが含まれず、保存先に新しいディレクトリがないこと。
RNS-T05時間帯情報のない受信時刻を、正しい時刻として補正せずに止めることを確認する。received_at_utc.tzinfo=Noneとした元データ保存依頼を用意する。LocalRawStore.put_if_absentを呼び出す。時刻が不正であることを示す例外が返り、保存処理を開始しない。ファイルが一件も作られず、時刻を現在時刻や世界共通時刻へ勝手に置換していないこと。
RNS-T06途中で書込みに失敗した場合、未完成の元データを正常な保管物として見せないことを確認する。一時保存領域への書込みが途中で失敗するようにした固定入力を用意する。LocalRawStore.put_if_absentを呼び出す。保存失敗の例外または停止結果が返り、完成した元データの場所は作られない。次回に同じ依頼を実行でき、未完成の一時領域が再生処理から参照されないこと。
RNS-T07外部記号が一つの内部銘柄番号に決まる行だけを正規化できることを確認する。一意の対応関係を返す銘柄台帳と、正しい価格・時刻を含む固定の元データを用意する。Normalizer.normalizeを呼び出す。各行に内部銘柄番号、世界共通時刻、元データ識別子を持つNormalizedBarが返る。返されたすべての行が一意のinstrument_idを持ち、外部記号だけで利用可能としていないこと。
RNS-T08外部記号が複数候補に対応する場合、都合のよい候補を選ばずに止めることを確認する。銘柄台帳が複数の有効な対応関係を返す元データ行を用意する。Normalizer.normalizeを呼び出す。保留または不合格の品質結果が返り、その行を含む通常用のデータ版は作られない。任意のinstrument_idを選んだ正規化行がなく、停止理由が品質報告に残ること。
RNS-T09同じ銘柄、時刻、種別で同じ値の行が重複した場合、重複の事実を残して一行にまとめられることを確認する。同じ内容の二行を含む固定の正規化候補を用意する。QualityChecker.checkを呼び出してから正規化データを保存する。一行だけが保存候補となり、重複した回数が品質報告に記録される。保存候補が一行であり、重複を何もなかったことにする報告になっていないこと。
RNS-T10同じキーで価格などの値が異なる重複を、どちらかを選ばずに停止できることを確認する。同じ銘柄・時刻・種別で、終値だけが異なる二行を用意する。QualityChecker.checkを呼び出す。DUPLICATE_CONFLICTを含む不合格の品質報告が返る。正規化データの版もdata_versionも発行されず、二つの候補が監査記録で追えること。
RNS-T11時刻が逆行する行を、再生処理が使える順序として保存しないことを確認する。同じ銘柄で後の時刻の行の後に前の時刻の行が来る固定入力を用意する。QualityChecker.checkを呼び出す。OUT_OF_ORDERを含む品質報告が返り、通常のデータ版は発行されない。順序を勝手に並べ替えて合格にせず、問題の元データ識別子と行番号が報告されること。
RNS-T12取引がなかった時間帯と、あるはずのデータが欠けた時間帯を区別できることを確認する。銘柄台帳の営業日情報で休止と分かる区間、および営業中なのに行がない区間を持つ入力を用意する。QualityChecker.checkを呼び出す。休止区間にはNO_TRADE_INTERVAL、実欠損にはMISSING_DATAが記録される。実欠損を取引なしとして合格にせず、欠損がある範囲のデータ版を発行しないこと。
RNS-T13未確定の時間足を、売買判断に使える確定値として保存しないことを確認する。bar_close_timeが確定していないことを示す行を用意する。Normalizer.normalizeとQualityChecker.checkを順に呼び出す。UNCONFIRMED_BARが記録され、その行は再生用の正規化データから除外される。未確定行を含むdata_versionが、通常利用可能として返らないこと。
RNS-T14価格が銘柄の最小変動単位に合わない場合、丸めて隠さずに止めることを確認する。銘柄台帳が示す最小変動単位に一致しない価格を含む行を用意する。QualityChecker.checkを呼び出す。PRICE_INVALIDを含む不合格の品質報告が返る。元の価格を丸めた正規化行が保存されず、停止理由と対象行が報告されること。
RNS-T15同じ元データ、変換規則、銘柄台帳なら、何度実行しても同じデータ版になることを確認する。固定した元データ内容、変換規則の版、銘柄台帳の内容確認値を用意する。正規化からManifestBuilder.buildまでを二回実行する。二回とも同じdata_versionと同じ正規化データの内容確認値が返る。二回の一覧内容と保存データが同一であり、現在時刻などの変わる値を版番号の材料にしていないこと。
RNS-T16品質報告が不合格または不明な場合、正規化データの版を作らないことを確認する。停止が必要な品質印、または判断不能な品質状態を持つQualityReportを用意する。LocalNormalizedStore.write_if_absentを呼び出す。保存拒否の結果が返り、正規化データと一覧の完成場所は作られない。再生処理が参照できるdata_versionが返らず、停止理由が監査記録に残ること。
RNS-T17同じデータ版番号で内容が異なる保存を、上書きせずに拒否できることを確認する。同じdata_versionで、異なる行または異なる品質報告を持つ二つの保存依頼を用意する。一つ目を保存した後に二つ目のLocalNormalizedStore.write_if_absentを呼び出す。二つ目は整合性エラーとなり、先に保存した版は変わらない。先の版の内容確認値が維持され、二つ目の内容が同じ場所へ混ざらないこと。
RNS-T18一覧ファイルの保存中に失敗した場合、部分的なデータ版を利用できないことを確認する。正規化行の保存後に一覧ファイルの原子的な名前変更が失敗するようにした環境を用意する。LocalNormalizedStore.write_if_absentを呼び出す。データ版は成功として返らず、未完成の一時ファイルは隔離または削除される。完成した一覧への参照がなく、次回の同じ実行で安全に保存をやり直せること。
RNS-T19再生処理が一覧に書かれたすべての証跡を確認してから入力を返すことを確認する。元データ、銘柄台帳、品質報告、正規化データの内容確認値が一致する完全な一覧を用意する。read_replay_snapshotを呼び出す。指定したdata_versionだけの正規化行が、検証済みとして返る。返された行の元データ識別子、銘柄台帳の版、品質報告の内容確認値が一覧と全て一致すること。
RNS-T20一覧の証跡が一つでも一致しない場合、再生処理を開始しないことを確認する。品質報告の内容確認値だけを改変した一覧、または参照先を欠いた一覧を用意する。read_replay_snapshotを呼び出す。整合性エラーが返り、再生用の正規化行は一行も返らない。不一致の項目名とデータ版番号が監査記録に残り、利用可能な結果として返らないこと。

18. 誤実装しやすい規則のコード例

この節は、元データを上書きしないことと、データ版の番号を再現可能に作ることを示す。実装者は、時刻や一時ファイル名のように毎回変わる値を版番号の材料に入れてはならない。

def derive_data_version(raw_sha256s: tuple[str, ...], rule_version: str,
                        catalog_sha256: str, quality_sha256: str) -> str:
    material = "|".join(sorted(raw_sha256s) + [
        rule_version, catalog_sha256, quality_sha256, "normalized-v1"
    ])
    return "dv_" + sha256(material.encode("utf-8")).hexdigest()[:20]

def put_if_absent(request: RawWriteRequest) -> RawWriteResult:
    reject_secret_keys(request.metadata)
    require_utc(request.received_at_utc)
    payload_sha = sha256(request.payload).hexdigest()
    object_id = sha256(f"{request.request_fingerprint}:{payload_sha}".encode()).hexdigest()
    if completed_path(object_id).exists():
        return verify_existing(object_id, payload_sha)
    write_to_temporary_path(object_id, request, payload_sha)
    verify_temporary_path(object_id, payload_sha)
    rename_to_completed_path(object_id)
    return RawWriteResult(object_id, payload_sha, True, completed_uri(object_id))
