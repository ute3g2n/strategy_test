1. 目的とレイヤー分離

本書は、外部データの取得証跡を保持するRaw Storeと、内部共通schemaへ変換したNormalized Storeを分離する。Rawは正本の取得証跡、Normalizedは再生成可能な変換結果であり、どちらもStrategyの都合で書き換えない。

レイヤー正本性書込主体下流利用
Raw Store外部取得payloadと取得メタデータの不変証跡。Market Data Adapter / Raw Writer再正規化、監査、再取得差分、DataVersion。
Normalized Store特定のNormalizationRuleVersionによる再生成結果。NormalizerReplay Reader、Data Quality、Feature/Signalの入力。
Tradable / Signal本書の外部保存層ではない。Catalog / StrategyPhase 3以降で利用。Rawへ逆書きしない。

2. Raw Store保存単位

保存単位は「一つの取得要求に対応する不変Raw Object」とする。大きな要求を日付・銘柄・schema単位に分割する場合も、各Objectの元requestと分割順をmetadataに残す。

項目必須内容
raw_object_idYes内部不変ID。vendorのjob IDやfile nameを正本IDにしない。
sourceYesvendor、dataset_id、schema_id、encoding、compression、source_version。
request_metadataYesrequest_id、symbols、stype_in/out、start/end UTC、request fingerprint、secret_ref名のみ。
acquired_at_utcYes取得完了時刻。送信時刻・イベント時刻とは別に保持。
payload_uriYesRaw payloadの格納場所。Gitへ大容量データを無条件に追加しない。
byte_count / sha256Yes保存前後のサイズと内容同一性。checksum計算不能なら下流へ発行しない。
dbn_metadata_refConditionalDBNの場合のmetadata header参照。元requestを再現できる証跡。
condition_snapshotYesavailable/degraded/pending/missing、対象日、last_modified情報。
created_at_utc / supersedesYesObject作成時刻と、訂正版があれば参照先。既存Objectの置換ではない。
Secretルール: API key、Authorization header、account ID、個人情報はRaw metadata、HTML、ログへ保存しない。必要な場合は環境変数参照名またはSecret manager参照名だけを保存する。

3. Raw上書き禁止と再取得差分

状況処理禁止事項Gate
同一論理request・同一sha256既存Objectを再利用し、再取得観測をAuditへ追加。重複Objectを正本として増やすこと。Pass。ただし再利用証跡は残す。
同一論理request・sha256差異新raw_object_idで保存し、supersedesまたはdiff_ofを付ける。旧Objectを削除・置換・上書きすること。Integrity Review / Data Gate stop
同一payload・metadata差異別request versionとして保存し、data_version候補を分ける。metadataを後から書き換えて同一取得に見せること。Unknownまたは要承認
checksum不明・保存失敗隔離領域にエラー証跡を保存し、RawBatchReceivedを発行しない。Normalized化、Signal生成、Replay入力化。Fail-closed

4. Normalized Store必須列

列型・制約意味
record_id内部一意IDNormalized recordの識別子。
event_id / run_idD07準拠イベントとReplay実行の追跡。
instrument_id内部ID必須外部instrument_id/raw_symbolではなくCatalogの正本ID。
event_time_utcUTC必須イベントが意味する時刻。順序、監査、Replayの正本。
received_at_utcUTC必須システムが受信した時刻。遅延と再取得の観測。
exchange_time_local / business_dateCatalog calendarで算出取引所現地時刻と営業日。UTCからの変換ルールをversion管理。
bar_close_time確定済みのみLook-ahead防止。未確定バーをStrategyへ渡さない。
event_kindbar/trade/statistics/definition等異なるschemaを混同しないための分類。
open/high/low/close/volume価格scaleを併記値と固定精度を保持。null/未適用値を0と同一視しない。
source_seqnullable外部順序。欠落時は内部順序だけで正本化しない。
raw_object_id / mapping_id参照必須RawとCatalog mappingまで逆引き可能にする。
quality_flagsbitsetまたは列挙集合missing、duplicate、out_of_order、degraded、partial、price_invalid、volume_invalid、checksum_unverified、no_trade_interval等。
data_version / normalization_rule_version必須同じRawから異なる変換結果を区別する。

5. 時刻、重複、欠損検知

検査ルールフラグ・処理
UTC正本永続化・順序・監査はUTC。現地時刻と営業日はCatalog calendarから導出。変換不能ならTIME_INVALIDで停止。
バー確定bar_close_timeが確定するまでSignal入力にしない。UNCONFIRMED_BAR、Replay除外。
重複第一キーは(instrument_id, event_time_utc, event_kind, data_version)。補助にsource_seqとraw_object_idを使う。同値重複はdedup countを保存。値違いはDUPLICATE_CONFLICTで停止。
順序逆行event_time_utcとsource_seqを検査。整列不能な場合は下流へ流さない。OUT_OF_ORDER、HealthEvent。
空区間ohlcv仕様上、取引なし区間はレコードなしの場合がある。NO_TRADE_INTERVALと実データ欠損を分離。
実欠損Catalogのsession、Dataset Condition、前後範囲、期待最小履歴から検知。MISSING_DATA、Data Gate stopまたは明示的除外。
異常値high/low/open/close、tick size、volume、価格scale、契約定義を照合。PRICE_INVALID等。ゼロや補間で隠さない。

6. data_version構造とRun Manifest

Phase 3のReplayは、個別ファイル名ではなく、次のDataVersionManifestをRun Manifestから参照する。同じIDでRaw、Normalized、Catalog、品質、roll方式が再現できない場合はReplay Gateを通さない。

DataVersionManifest項目内容Run Manifestへの接続
data_version_id不変のDataVersion ID。run_manifest.data_version必須値。
raw_object_ids利用Raw Objectの完全な集合。再取得差分の監査。
normalized_snapshot_idNormalized生成スナップショット。Replay Readerの入力。
catalog_version / calendar_versionInstrument定義・営業日・tick/multiplier計算の版。同一契約解釈を再現。
normalization_rule_versionUTC、scale、dedup、missing、qualityの規則版。同じRawからの変換差異を追跡。
roll_rule_versioncontinuous/contract selectionの版。未承認ならUNKNOWN。H2-1未承認時はSignal入力へ昇格不可。
quality_gate_result対象範囲、除外範囲、未解決Unknown、判定日時。Replay Gateの入力。
manifest_sha256Manifest自身の同一性。Run証跡と再実行比較。
Phase 3参照例: Run Manifestがdata_version=mdv2_...を指定し、Replay ReaderがDataVersionManifestからNormalized snapshot、Catalog version、quality gate resultを解決する。未解決またはUnknownの要素があれば、MarketEventをStrategyへ供給しない。

9. H2-1承認対象

Raw Objectの不変保存、Normalized schema、quality flag、data_versionの必須構造、degradedの扱い、保存先と大容量データ方針を承認する。承認前は未確定の保存方式や品質判断をPhase 3の本線入力にしない。
