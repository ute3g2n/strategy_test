1. 概要

Phase 2は、Phase 3のStrategy / Backtest基盤が再現可能なMarketEvent入力を使えるように、Market Data基盤の詳細設計、最小実装、Data Quality / Replay検証を行うPhaseである。本書では、P2-01時点でスコープ、入力条件、成果物、初期候補、Unknown、Human Gateを固定する。

Phase 2は投資助言、売買推奨、特定商品の取引推奨を目的にしない。初期候補は検証対象データの候補であり、実取引開始の承認ではない。

3. 対象と非対象

区分内容根拠
対象Market Data Adapter詳細、Databentoを第一候補とする取得仕様、Raw Store、Normalized Store、Instrument Catalog、Symbol mapping、1分足catalog、Continuous signal series、roll map、Data Quality test、Replay入力、data_versionとRun Manifestへの接続。要件定義8章、Phase 1 D10/D11/D18、Phase 2計画書。
非対象Strategy本体、Backtest Engine本体、Broker Paper接続、OMS実装、Risk Live採用値、Shadow/Paper/Live運用Runbook、外部API全パラメータの完全固定。Phase 2計画書のdetail_boundary、Phase 1詳細設計バックログ。
参照のみPhase 1専用AI部品、Phase 0研究用ハーネス、P10研究用取得補助。AI部品ルール、Phase 2計画書、要件定義9.3。

4. Phase 2で固定する判断

判断ID固定する判断根拠影響
DEC-P2-01Raw Storeは外部取得データと取得メタデータを上書き不可で保持する。D10のRaw / Normalized分離、要件8.1。再取得差分やchecksum不一致は上書き補正せずData Gateへ送る。
DEC-P2-02Normalized StoreはUTC、共通schema、内部InstrumentId、quality_flagsを必須にする。要件8.2、D10 MarketEvent、D11 data_version。StrategyやBacktestはベンダー記号や外部SDK型へ直接依存しない。
DEC-P2-03Databentoは第一候補Data Vendorとして調査・設計するが、取得可否と費用承認前の実API取得はHuman Gate対象にする。要件8.4、P2計画 H2-2、Secretルール。未承認時はdry-runまたはfixtureに縮退する。
DEC-P2-04Phase 2の最小再生単位は1分足とし、日足は1分足から生成する。要件8.3、REQ-Q20。Phase 3へ渡すReplay入力は1分足由来で証跡化する。
DEC-P2-05Continuous signal seriesはRawの正本ではなく、Catalogとroll ruleに基づくSignal入力として版管理する。REQ-Q19、REQ-OD03、D10レイヤー分離。OD-03未承認時はSignalを本線入力に昇格しない。
DEC-P2-06データ欠損、重複、時刻逆行、異常価格、異常出来高、checksum不一致、degraded品質警告はPass扱いせずData Gateで判定する。要件8.5、D18 Data Gate、D10 fail-closed。該当範囲のSignal生成停止またはUnknown化を必須にする。
DEC-P2-07P10研究用ハーネスは参照証跡に限定し、本番Market Data Adapterとして流用しない。要件9.3、D10 Adapter境界。研究コード依存はP2-05レビュー対象にする。
