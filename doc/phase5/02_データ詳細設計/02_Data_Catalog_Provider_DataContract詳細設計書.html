1. ドメインの概要と設計目的

Data Catalogは、戦略や検証が参照する論理的な市場対象、資産種類、時間足、版を管理する部品である。外部Providerが使う実Symbolや取引所を勝手に決める部品ではなく、確認済みの対応付けをEvidenceとGateに結び付ける部品である。

Data Contractは、将来のData requestが何を要求し、どのRaw／Normalized／Quality／Manifest／Evidenceへつながるかを固定する。P5-02では外部へ送信せず、未確認または未承認の入力を閉じた側へ倒して拒否する。

利用者期待すること返すもの失敗時
Catalog／Data設計論理ID、4資産種類、5時間足の構造を安定して参照したい。immutableなCatalogVersionとmapping状態。版不一致・範囲外・未確認は理由付きで停止。
P5-03 Raw／Quality取得前提と保存・hash・provenanceを受け取りたい。DataRequest契約、path／hash方針、ProviderCapabilityRef。契約・権限・Gate不足はrequestを作らず拒否。
P5-04 Test／Evidence固定仮定と実測値を混同せず試験したい。TEST-P5-02-*の拒否条件、EvidenceRef、GateRef。UnknownをPassにせず、HUMAN_GATE_REQUIRED。

5. 正常系・失敗系の処理フロー

5.1 正常な設計契約評価

正常とは、外部接続に成功することではなく、未承認の要求を実行せず、必要な契約参照をそろえたDecisionを返すことである。

sequenceDiagram
  participant 呼出元 as 呼出元
  participant Catalog as Catalog
  participant Policy as Request policy
  participant Audit as 監査参照
  呼出元->>Catalog: LogicalInstrumentId + VersionRef
  Catalog-->>呼出元: MappingDecision
  呼出元->>Policy: DataRequest + CapabilityRef + GateRef
  Policy->>Audit: DecisionEvent + ReasonCode
  Audit-->>Policy: AuditRef
  Policy-->>呼出元: REQUEST_DENIEDまたはREQUEST_ALLOWED（送信なし）

5.2 Fail-closedフローチャート

いずれかの確認が不明なら、成功扱いで下流へ渡さず、理由・scope・version・hashの参照だけを監査へ残す。

flowchart TD
  start([DataRequestを受ける]) --> scope{"対象・時間足はP5 scopeか"}
  scope -- いいえ --> deny["REQUEST_DENIEDを記録"] --> end1([終了])
  scope -- はい --> mapping{"MappingはCONFIRMEDか"}
  mapping -- いいえ --> deny
  mapping -- はい --> contract{"契約・権限・費用・再配布は確認済みか"}
  contract -- いいえ --> gate["HUMAN_GATE_REQUIREDを記録"] --> end1
  contract -- はい --> human{"P5-DATA-G1が対象scopeで承認済みか"}
  human -- いいえ --> gate
  human -- はい --> path{"相対path・hash・retentionが有効か"}
  path -- いいえ --> deny
  path -- はい --> safe["REQUEST_ALLOWEDを返す（外部送信は別承認）"] --> end2([終了])

16. 型付き公開契約（実装前の擬似コード）

このコード例は、実装者が入力・出力・エラー・副作用を誤解しないための擬似コードである。実在しない依存やProvider SDKは使用していない。

class MappingStatus(Enum):
    UNCONFIRMED = "UNCONFIRMED"
    CONFIRMED = "CONFIRMED"
    RETIRED = "RETIRED"

class DataRequest:
    request_id: str
    catalog_version_ref: CatalogVersionRef
    mapping_ref: MappingRef
    timeframe_id: TimeframeId
    period_ref: PeriodRef
    gate_decision_ref: GateDecisionRef
    path_hash_contract: PathHashContract
    secret_reference: SecretReference | None

def validate_data_request(request: DataRequest) -> RequestDecision:
    require_scope(request.timeframe_id in {D1, H4, H1, M30, M15})
    mapping = resolve_mapping(request.mapping_ref)
    if mapping.status != CONFIRMED:
        return deny("MAPPING_UNCONFIRMED")
    capability = resolve_capability(mapping.provider_capability_ref)
    require(capability.contract_status == "CONFIRMED")
    require(request.gate_decision_ref == "P5-DATA-G1:APPROVED")
    require(relative_path(request.path_hash_contract))
    require(valid_hashes(request.path_hash_contract))
    require(secret_reference_is_metadata_only(request.secret_reference))
    return allowed_without_external_send(request.request_id)
契約項目固定内容エラー副作用・冪等性
入力検証scope、版、mapping、capability、Gate、path、hashを順に検査する。最初の安全な理由を返し、詳細なSecret値は返さない。読み取り専用で、同じinput hashは同じdecisionになる。
外部境界REQUEST_ALLOWEDは将来Runnerへの契約準備状態である。Runner、通信、Secret、費用が未承認ならDENIED。P5-02では送信・retry・取得を行わない。
保存DecisionEventとAuditRefだけをsanitizedで保存する設計。監査保存不能なら許可を返さない。decision_idを冪等キーとし、既存決定を上書きしない。

17. 正常・失敗・再実行の詳細フロー

ここでは、Catalog参照からDataRequest判定までの成功、主要失敗、再実行を同じ契約で追えるようにする。

sequenceDiagram
  participant C as 呼出元
  participant R as CatalogResolver
  participant V as RequestValidator
  participant A as AuditRecorder
  C->>R: resolve_catalog(input)

def confirm_mapping(candidate, evidence, gate):
    if candidate.logical_id is None:
        reject("LOGICAL_ID_MISSING")
    if candidate.external_fields.any_value_is_guessed:
        reject("GUESSED_EXTERNAL_VALUE")
    if evidence is None or gate.scope != candidate.scope:
        keep_unconfirmed("EVIDENCE_OR_SCOPE_MISSING")
    if gate.name != "P5-DATA-G1" or gate.decision != "APPROVED":
        keep_unconfirmed("HUMAN_GATE_REQUIRED")
    return immutable_new_catalog_version(candidate, evidence, gate)

def validate_path_hash(contract):
    if is_absolute_or_unc(contract.object_relative_path):
        reject("ABSOLUTE_PATH")
    if not contract.content_hash or not contract.schema_hash:
        reject("HASH_MISSING")
    if contract.retention_ref is None or contract.redistribution_ref is None:
        reject("RETENTION_OR_REDISTRIBUTION_UNKNOWN")
    return "PATH_HASH_CONTRACT_VALID"
