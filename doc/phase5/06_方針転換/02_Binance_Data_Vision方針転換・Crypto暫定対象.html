Binance Data Vision方針転換・Crypto暫定対象

文書ID: P5-ART-ALT-DATA-DECISION-001
決定ID: DEC-P5-BINANCE-001
Phase / Step: PHASE5_MARKET_DATA_OPERATIONALIZATION_EVIDENCE_2026_08_12 / P5-08方針変更
決定日: 2026-08-14（Asia/Tokyo）
状態: PROVIDER_DECIDED / SCOPE_AMENDMENT_REQUIRED
根拠入力: plan/backtest_and_turtles_full_chat_history.md と運用者の「Binance Data Vision にする。…銘柄選定で候補に入ったcryptoの銘柄を初期運用の暫定対象とする。」という指示。

1. 今回の決定を一言でいうと

市場Data Providerの方向をDatabentoからBinance Data Visionの公開アーカイブへ変更し、初期運用の銘柄候補は従来のCME Micro futures 5件をいったん白紙化する。

現時点で履歴に具体的に書かれているCrypto銘柄だけを、初期運用の暫定対象として BTCUSDT と ETHUSDT にする。「主要アルトコイン」は分類名であり、具体的な銘柄名ではないため、勝手にBNB・SOL・XRPなどを追加しない。

これはProviderとData対象の設計方針を変更する決定であり、実Dataのダウンロード、外部通信、Secret読取、実運用、注文、Broker、Paper、Liveを開始する許可ではない。旧DatabentoのP5-DATA-G1承認は履歴として残し、P5-08にはBinance用の新しい申請範囲・request・Runner・Evidence rootが必要である。

2. 何が白紙になり、何を暫定対象にするか

区分対象現在の扱い理由・境界
旧初期候補MCL、M6A、MZC、MZS、MZWINITIAL_OPERATION_CANDIDATE_RETIRED既存のP5／Databento前提で作った履歴。削除せず、初期運用の正式候補から外す。CME先物をBinance Cryptoと同一視しない。
暫定対象BTCUSDTPROVISIONAL_TARGET履歴に「BTC」「BTC/USDT」が具体的に記載されているため、Binance Spotのシンボル表記へ正規化した候補。
暫定対象ETHUSDTPROVISIONAL_TARGET履歴に「ETH」が具体的に記載されているため、Binance Spotのシンボル表記へ正規化した候補。
追加候補「主要アルトコイン」UNNAMED / NOT_SELECTED具体的な銘柄名・Binance symbol・市場区分が入力に存在しない。推測追加は禁止。追加時は別の対象表更新とGateが必要。
Spotの扱い: 履歴は「BTC/USDT」と記載しており、レバレッジ・Funding・清算・限月を指定していない。そのため本書では Binance Spot / BTCUSDT・ETHUSDT を安全側の推奨暫定値とする。ただし、Spotを明示した新Gateが成立するまでは SPOT_PROVISIONAL とし、USD-M／COIN-M futuresへ自動拡張しない。

3. Binance公式情報で確認できたこと

確認日はすべて2026-08-14。公式一次情報のURLを固定し、実Dataはダウンロードしていない。

確認項目公式情報P5への意味
公開入口Binance Data Collection は誰でも使える公開市場Dataの入口で、日次または月次ファイルを提供。API keyを使わず、公開アーカイブをHTTPSで取得するProvider境界を設計できる。
市場区分公式 binance-public-data README はSpot、USD-M Futures、COIN-M Futuresを別区分として説明。Spotと先物のファイル階層・契約意味を混ぜない。今回の暫定値はSpotだけ。
KlineSpot Klineの列はOpen time、OHLC、Volume、Close time、Quote volume、Trade count、Taker buy volume等。1m、15m、30m、1h、4h、1dなどのintervalが記載されている。最初は1分KlineをRawの基底にし、D1／H4／H1／M30／M15を同じUTC境界から生成する。
時間単位公式READMEはSpot Dataについて、2025-01-01以降のtimestampがmicrosecondsになると注意書きしている。Timestamp unitをファイル期間から自動推測せず、Provider区分・年月・manifestへ記録してUTCへ変換する。
配布単位日次・月次のZIPアーカイブ。公式READMEには月次Spot Klineのパス例がある。月次を主取得、日次を境界確認・差分確認に使う設計が可能。ただし同一期間の二重保存は明示する。
完全性確認各ZIPと同じフォルダに .CHECKSUM があり、SHA-256で検証できる。ZIP、checksum、展開CSV、NormalizedをそれぞれhashでManifestへ接続する。
更新リスク公式READMEは、問題発見後にアーカイブが更新される場合があると説明する。取得日だけでなくURL、ファイルhash、checksum、Manifest versionを固定し、再取得差分を隠さない。
APIとの違いSpot REST API公式文書 のKlineはsymbol・interval・UTC start/endを受け、1回の最大limitは1000。初期経路は大量取得に向くData Vision ZIPを使い、REST APIのページングを主経路にしない。API keyやLive接続へ拡張しない。

公式README末尾のリポジトリLicense表示だけから、データアーカイブの再配布・商用利用条件まで断定しない。P5では外部再配布を禁止し、利用条件が必要な用途は別確認へ送る。

4. Binance版P5-DATA-G1の推奨入力値

以下は新しい申請表へ移すための推奨値。DECIDED／PROPOSED は方針決定または設計推奨、UNKNOWN は実行前に確認が必要な項目を表す。

項目推奨値根拠・システムとの相性状態
ProviderBinance Data Vision / Binance Public Data公開アーカイブを使うため、Databentoの使用量課金・API key・dataset entitlementを初期取得の前提にしない。Provider固有処理はAdapter境界へ閉じ込める。DECIDED
Data URLhttps://data.binance.vision/公式公開入口。許可先はData VisionのHTTPSだけに限定する。PROPOSED
API key／Secret使用しない。既存環境変数のキーも読まない。公開Historical ZIPの取得にAPI keyは不要。Secretを使わない構成は、ログ・環境・Evidenceへの漏洩面を減らす。DECIDED
資産種類asset_type=cryptoCrypto固有の24/7、symbol、quote asset、volume単位をCatalogへ分離し、旧futures contract／expiry／rollを持ち込まない。DECIDED
市場区分market_segment=spot（暫定）履歴のBTC/USDT表記に合わせ、funding・leverage・liquidation・expiryがないSpotを初期値にする。Futuresは別Gate。SPOT_PROVISIONAL
暫定symbolBTCUSDT、ETHUSDT履歴で具体的に出たBTC・ETHだけをBinance symbolへ正規化。銘柄名のない「主要アルト」は追加しない。PROVISIONAL_TARGET
基底DataSpot Kline 1m の月次ZIPを主経路。必要な月だけ日次ZIPで境界照合。1分から上位時間足を再生成でき、Raw／Normalized／Quality／Manifestの既存P5契約へつながる。Tick／Order bookは初期対象外。PROPOSED
生成時間足D1、H4、H1、M30、M15既存P5の時間足を維持し、Providerの各intervalを混在させず、1m Rawから同じ集計規則で生成する。INHERITED
時間・Calendar保存・集計はUTC、CRYPTO_24_7_UTC。休場カレンダーは置かない。Crypto SpotはCMEの休日・DST・限月・Rollを適用しない。データがない区間は自動ゼロ埋めせず、欠損・取引停止・配布欠落を別分類する。VERSION／HASH要確認
対象期間2025-02-24T00:00:00Z以上、2026-08-01T00:00:00Z未満を比較用に暫定継承。旧P5の共通比較期間を維持して差分を小さくする。Binanceの利用可能な全履歴を採用する決定ではない。長期期間は別判断。INHERITED／再承認要
TimestampSpotの2025-01-01以降はmicroseconds想定。Manifestにunitを固定し、UTC datetimeへ変換。公式READMEの注意書きに対応。millisecondsとして誤読すると、時間が1000倍ずれてQuality停止になる。REQUIRED
Raw保存RUN-P5-08-BINANCE-001/raw/spot/klines/1m/{symbol}/{YYYY-MM}.zip と同名.CHECKSUM、展開後CSVのhash。取得元・配布月・checksum・展開内容を残し、上書き禁止。旧Databento Evidence rootと混ぜない。NEW REQUEST／RUN要作成
NormalizedP5-NORMALIZED-BAR-v1.0.0を再利用。symbol、quote asset、bar start/end UTC、OHLCV、raw／checksum hash、quality refを必須。ProviderのCSV列やtimestamp unitをCoreへ漏らさず、P4のNormalizedDatasetRef／DataGateDecisionへ接続できる。DESIGN FIT
CostProviderの公開アーカイブData料金は 0 USD。外部費用を前提にしない。内部の保存・通信・実行上限は別途budget control。DatabentoのGB課金を廃止する方向と一致。ただし無料は品質・保存費用・利用条件の無条件保証ではない。PROVIDER_COST_0 / INTERNAL_UNKNOWN
Qualitychecksum、月次ファイルの存在、CSV列数、timestamp単調性、重複、OHLC整合、1分間隔の欠損、月次／日次境界を検査。公式アーカイブは後日更新される可能性がある。部分取得やhash不一致を下流へ渡さない。実Dataで未実証
費用・停止ファイルhash不一致、checksum不一致、対象外symbol、Spot／Futures階層違い、timestamp unit不明、欠損・重複・未来Data、通信先逸脱で停止。UnknownをPassへ変換せず、既存P5 fail-closedと一致。DESIGN RULE
保持・再配布承認済みローカルEvidence rootのみ。外部公開・第三者再配布・Cloudコピーは禁止。契約・利用条件確認後に保持期限を固定。公開URLで取れることと、再配布権があることは別。不要な権限を追加しない。TERMS／RETENTION UNKNOWN
実運用境界Backtest用Historicalだけ。Broker、Paper、Live、実資金、実Risk、Futures、Funding、Liquidation、注文は対象外。Cryptoの価格Dataを取得できても、取引可能性・収益性・Live適合性の証明にはならない。OUT OF SCOPE

7. 次に必要な実務作業

  1. この文書の BTCUSDT、ETHUSDT、Spot、1m、期間、UTC、保存先を新しいP5-DATA-G1 amendmentへ転記する。
  2. 旧Databento requestとは別に RUN-P5-08-BINANCE-001 とrequestを作り、Data VisionのURL template、対象月、checksum検証、target pathsを固定する。
  3. 実行前に、Runnerの固定性、外部通信allowlist、Secret非使用、保存先、利用条件、停止条件を確認する。
  4. 承認済み範囲で初めて最小の限定取得を行い、ZIP／checksum／展開CSV／Normalized／Quality／Manifestを同じRunへ束ねる。
  5. P5-09で品質・Calendar・Cost／Gap・期間分割・Holdoutを検証し、未取得・未確認の項目をPASSへしない。
