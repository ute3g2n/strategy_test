要約

本書は、Backtest / Shadow / Paper / Live で共通に使う概念モデル、状態、イベント、識別子、時系列の意味を固定する。実装クラスやBroker固有の例外は固定せず、Strategy、OMS、Risk、Adapterが同じ用語とイベント意味論を共有できることを目的とする。

対象と非対象

区分内容
対象MarketEvent、SignalEvent、OrderIntent、Order、Fill、Position、AccountSnapshot、RiskSnapshot、TimerEvent、HealthEvent、注文状態、識別子、時刻意味論、復旧の最小情報。
非対象実装クラス、DBテーブル詳細、Broker例外コード、注文タイプごとの細かい制約、Live専用運用手順。
詳細設計バックログ注文例外パターン、部分約定の細則、証拠金計算、通貨換算、Broker別差異はPhase 4以降で詳細化する。

概念モデル

概念意味必須属性の最小集合備考
MarketEventStrategyと実行系へ流す市場入力イベント。event_id, run_id, instrument_id, event_time_utc, exchange_time_local, event_kind, source_seq価格足、ティック、ロール、欠損通知を含む。
SignalEventStrategyが内部判断として出すシグナル。event_id, run_id, strategy_id, instrument_id, signal_type, decided_at_utc, rationale_ref発注命令ではない。
OrderIntentStrategyが希望する売買意図。intent_id, run_id, strategy_id, instrument_id, side, target_units, intent_time_utc, reason_codeRiskとOMS通過前は注文ではない。
OrderOMSが管理する内部注文。client_order_id, run_id, instrument_id, side, quantity, order_state, submitted_at_utcBroker注文IDはAdapter側の関連付けで保持。
Fill約定結果。fill_id, client_order_id, instrument_id, filled_qty, fill_price, fill_time_utc, broker_exec_ref部分約定を許容する。
Position内部ポジション状態。position_id, instrument_id, net_qty, avg_cost, realized_pnl, unrealized_pnl_mark_time正本は内部集計、外部照合はReconciliationで行う。
AccountSnapshot口座残高と制約の時点断面。account_snapshot_id, account_ref, snapshot_time_utc, equity, cash, margin_used, margin_availableStrategyへは必要最小の要約のみ渡す。
RiskSnapshot現在のリスク利用状況。risk_snapshot_id, snapshot_time_utc, current_exposure, dd_ratio, kill_switch_state, risk_versionRisk判定の根拠に使う。
TimerEvent市場入力に依らない定時イベント。event_id, run_id, timer_kind, scheduled_time_utc, fired_time_utcバー確定、ハートビート、日次締めなど。
HealthEvent監視・障害状態イベント。event_id, run_id, component_name, health_state, observed_at_utc, severity停止要求の根拠になり得る。

モデル境界: StrategyはMarketEvent、PortfolioやAccountの要約、RiskSnapshotの必要最小情報を読む。Order、Fill、Broker固有応答はStrategyの入力にしない。

注文ライフサイクルの標準状態

Draft
  -> RiskAccepted
  -> Planned
  -> Submitted
  -> Acknowledged
  -> PartiallyFilled
  -> Filled

Submitted / Acknowledged / PartiallyFilled
  -> CancelRequested
  -> Cancelled

Draft / RiskAccepted / Planned / Submitted / Acknowledged
  -> Rejected

Any active state
  -> Expired
  -> Failed
  -> UnknownExternalState
状態意味遷移責務
DraftOMS未確定の意図。OMS
RiskAcceptedRiskで許可された。Risk
Planned注文計画が確定した。OMS
SubmittedBroker送信要求済み。Adapter
AcknowledgedBroker受付済み。Adapter
PartiallyFilled一部約定。Adapter / Reconciliation
Filled完全約定。Adapter / Reconciliation
CancelRequested取消要求送信済み。OMS
Cancelled取消完了。Adapter / Reconciliation
Rejected送信前後の拒否。Risk / Adapter
Expired期限切れ。OMS / Adapter
Failed送信失敗または処理失敗。OMS / Adapter
UnknownExternalState外部状態が不明で照合待ち。Reconciliation

識別子命名方針

ID命名方針不変条件
event_id`evt_{run}_{stream}_{seq}`run内で一意。重複判定キーに使う。
client_order_id`coid_{run}_{strategy}_{instrument}_{ordinal}`OMS正本。Broker注文IDとは分離する。
run_id`run_{mode}_{yyyymmddThhmmssZ}_{manifest}`1回の実行単位を一意に識別する。
strategy_id`strat_{family}_{variant}_{version}`設定とコード版を追跡可能にする。
instrument_id`inst_{asset}_{venue}_{symbol_family}`Broker記号、Data Provider記号から独立させる。

Phase 1ルール: 外部系のIDを内部正本IDとして使わない。Broker注文ID、約定ID、データベンダ記号は関連属性として保持し、内部IDと分離する。

UTC、取引所現地時刻、営業日、バー確定時刻の扱い

概念定義扱い
event_time_utcイベント正本時刻。永続化、順序判定、監査はUTCで行う。
exchange_time_local取引所現地時刻。市場カレンダー判定、営業日判定、バー境界で使う。
business_date取引所カレンダー上の営業日。日次集計、日跨ぎ判定、先物ロールの文脈に使う。
bar_close_timeバーが確定した時刻。Strategyが日足や時間足を読む起点にする。
observed_at_utc監視系が観測した時刻。HealthEventや遅延監視に使う。

市場入力がティックであっても日足であっても、内部の順序と監査はUTCを正本とする。営業日とバー確定判定は、取引所現地時刻と市場カレンダーに依存する。

順不同イベント、重複イベント、再起動後復旧

論点方針
順不同イベント`event_time_utc` と `source_seq` を併用して整列する。整列不能な場合は `HealthEvent` を出し、Strategyへ直接流さない。
重複イベント`event_id` を第一キー、補助的に `(stream, source_seq, event_time_utc)` を使い冪等処理する。
再起動後復旧最低限 `run_id`, 最新処理位置、未完了注文状態、Position, AccountSnapshot, RiskSnapshot, 最終TimerEvent, 重複判定用水位を復旧する。
イベント再生Backtestと障害復旧の両方で同じ意味論を使う。Realtime専用の隠れ状態を持ち込まない。

復旧原則: 再起動後は、未完了注文と正本スナップショットを復元し、必要に応じてBroker照会で `UnknownExternalState` を解消してから売買を再開する。

約定、口座、ポジションの正本管理方針

対象Phase 1での正本方針補足
Order / Fill内部イベントジャーナルを正本とし、Broker状態と照合する。Broker応答は外部事実だが、内部では冪等に取り込む。
Position内部集計状態を正本とし、Broker残高とReconciliationで定期照合する。差異は自動黙殺せず、差異イベント化する。
AccountSnapshot外部口座事実を受けた時点断面を内部保持する。Strategyへは要約ビューだけを渡す。
RiskSnapshotRiskモジュールが計算した内部状態を正本とする。kill switch やDD指標の判断根拠を保持する。

設計判断

DEC-P1-DM-01: 実行モード差分より先に意味論を統一する

Backtest、Shadow、Paper、Liveで同じイベントと状態を使い、差分はAdapter、Clock、接続先に閉じ込める。

DEC-P1-DM-02: 内部IDを正本にし、外部IDは関連属性として扱う

Brokerとデータベンダの識別子は変更や再利用があり得るため、内部で不変のIDを採用する。

DEC-P1-DM-03: 注文の不明状態を明示的に表す

`UnknownExternalState` を置き、障害時や再起動時に曖昧さを隠さない。Reconciliation完了前に新規売買を進めない判断を可能にする。
