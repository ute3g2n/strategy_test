要約

D06共通ドメインモデルで定義したイベント、注文、口座、ID、時系列のうち、後続設計で参照頻度が高い最低ルールを独立成果物として明示する。これは新しい設計判断ではなく、D01-D20成果物対応を明確化するための補完である。

イベントEnvelope

項目意味必須
event_idイベント一意ID。重複排除と監査に使う。Yes
run_id実行単位。Backtest / Shadow / Paper / Liveで共通。Yes
event_time_utcイベントが意味するUTC時刻。Yes
received_at_utcシステムが受信したUTC時刻。Yes
source_seq同一source内の順序。可能な限りYes
checksum入力データや外部応答の改ざん・差分検出。保存対象でYes

注文と口座の正本

対象正本所有者禁止事項
Order / client_order_idOMSBroker order idを内部主キーにしない。
FillOMS / ReconciliationStrategyが約定正本を持たない。
PositionPortfolio / Account / Reconciliation未照合Broker値をLive注文判断に使わない。
AccountSnapshotAccountStrategyがCash、Margin、NAVを直接更新しない。
RiskSnapshotRiskStrategyがKill Switchを解除しない。

ID方針

ID所有者用途
client_order_idOMS内部注文の正本ID。
broker_order_idBroker Adapter外部Broker注文ID。対応表に閉じる。
strategy_idStrategy Registry戦略の識別と設定追跡。
instrument_idCatalogMarket Data、Strategy、Risk、OMSで共通参照。
manifest_idExecution Model再現性とGate判定の単位。

時系列方針

時刻用途方針
UTC保存、監査、順序判定。全イベントで必須。
取引所現地時刻営業日、セッション、バー確定。Signal生成時の補助情報として保持。
バー確定時刻Look-ahead防止。未確定バーをStrategy判定に使わない。
受信時刻遅延、欠損、運用監視。HealthEventと監査に使う。
