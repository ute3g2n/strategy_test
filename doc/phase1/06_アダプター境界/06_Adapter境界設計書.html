概要

本書は、Broker AdapterとMarket Data AdapterのPhase 1境界を定義する。目的は、IBKRやDatabentoなどの外部仕様をCore Domain、Strategy、Risk、OMSへ漏らさず、Phase 2のMarket Data詳細設計とPhase 4のBroker詳細設計へ引き継げる境界を固定することである。

Phase 1では、IBKR API全エンドポイント、Databento全ジョブ、注文例外の全パターン、Live Runbook全文は固定しない。固定するのは、外部IDと内部IDの対応、Portの入出力、fail-closed方針、公式一次情報で確認すべき制約リストである。

Broker Adapter

区分内容
責務内部OrderRequestをBroker固有注文へ変換する。Broker注文ID、permId、clientId等の外部識別子を内部client_order_idへ関連付ける。Broker応答をExecutionReportへ正規化する。接続断、拒否、約定、取消、状態不明を分類する。
非責務Strategy判断、Risk上限判断、口座正本の単独決定、未照合Positionの自動補正、Secrets平文保持、Human Gateの代替。
入力PortSubmitOrder、CancelOrder、QueryOpenOrders、QueryExecutions、QueryAccountSnapshot、QueryPositions、PingBroker。
出力イベントOrderSubmittedToBroker、BrokerAcknowledged、ExecutionReportReceived、BrokerRejected、BrokerConnectionChanged、UnknownExternalState、BrokerRateLimited。
内部へ漏らさないものBroker SDK型、APIセッション、認証情報、raw callback payload、Broker固有注文IDを正本IDとして扱うこと。

Market Data Adapter

区分内容
責務外部Market Data API、ファイル、Live streamからRaw取得記録を生成する。ベンダ記号と内部InstrumentIdの対応をCatalogへ渡す。取得時刻、配信時刻、イベント時刻、品質フラグを保持する。
非責務Strategy判断、Risk判断、注文発行、Broker状態照合、研究用に都合のよい補正を正本Rawへ上書きすること。
入力PortFetchHistoricalRange、SubscribeLiveMarketData、ResolveSymbols、FetchInstrumentDefinitions、FetchTradingCalendar、LoadRawFile。
出力イベントRawMarketDataReceived、MarketDataGapDetected、SymbolMappingResolved、InstrumentDefinitionUpdated、MarketDataConnectionChanged、DataVendorRateLimited。
内部へ漏らさないものData Vendor SDK型、raw_symbolを内部正本IDとして扱うこと、APIキー、レート制限リトライ実装、ベンダ固有schemaをStrategyへ直接渡すこと。

Broker側注文IDと内部client_order_idの対応

ID所有者用途Phase 1方針
client_order_idOMS内部注文の正本ID。全モードで必須。Broker注文IDとは分離する。
broker_order_idBroker AdapterBroker API上の注文ID。内部正本IDにしない。対応表で保持する。
broker_perm_idBroker AdapterBroker側の永続的またはホスト側識別子。照合補助キーとして扱う。内部Orderの主キーにしない。
broker_client_idBroker AdapterBroker接続クライアント識別。接続設定と監査に保持する。Strategy / Riskへ渡さない。
execution_idBroker Adapter約定応答識別。Fillの重複排除補助キーにする。内部fill_idとは分離する。

境界ルール: 外部IDが欠落、重複、再利用、未確定の場合は、Adapterが UnknownExternalState または照合要求を発行し、新規注文をfail-closedへ誘導する。

Market DataのRaw / Normalized / Tradable / Signal / Derived / Experimentレイヤー

レイヤー意味所有者Adapterとの関係
Raw外部から取得した原データと取得メタデータ。Market Data Adapter / Raw Store上書き不可。外部payload、取得時刻、source、checksumを保持する。
Normalized共通schemaへ変換されたOHLCV、tick、definition、status。NormalizationAdapterは変換入力を提供し、正規化規則はData設計で管理する。
Tradable取引可能性、営業日、契約、ロール、停止状態。CatalogMarket Dataのdefinitionやstatusを使うが、StrategyへはInstrumentIdで渡す。
SignalStrategyが読む確定済み市場ビュー。Event Engine / Strategyベンダ固有型を含めない。bar_close_timeとquality_flagsを必須にする。
DerivedN、Channel、特徴量、集計済み派生系列。Strategy / AnalyticsRawへ逆書きしない。計算バージョンを持つ。
Experiment研究用の候補変換、仮説検証、比較データ。Research本番正本にしない。昇格にはGolden testとレビューが必要。

設計判断

DEC-P1-ADP-01: 外部IDは内部正本IDにしない

Broker注文IDやData Vendorのinstrument_id/raw_symbolは、再利用、日付依存、client依存、取得範囲依存があるため、内部正本IDとは分離して対応表で扱う。

DEC-P1-ADP-02: AdapterはStrategy判断を持たない

Adapterは変換、送受信、分類、正規化に限定する。売買判断、Risk上限、Unit上限、口座正本の判断は担当しない。

DEC-P1-ADP-03: 状態不明は明示的にUnknownExternalStateへ落とす

接続断や外部ID対応不明を成功扱いしない。Reconciliation完了前の新規注文はfail-closedへ誘導する。

DEC-P1-ADP-04: RawとNormalizedを分離する

取得データの再現性を守るため、Rawは上書き不可とし、正規化や研究派生は別レイヤーで管理する。
