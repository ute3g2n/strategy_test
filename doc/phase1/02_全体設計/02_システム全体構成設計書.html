概要

本書は、タートルズ・トレンドフォロー自動売買システムのPhase 1における全体アーキテクチャを固定する。主眼は、研究から本番運用へ進む道筋、主要モジュールの関係、依存方向、Broker依存とMarket Data依存の隔離である。

本改訂では、AutoTradePhase1_Orchestrator_v0_1 のPhase 1制約に従い、AutoTradePhase1_A02_SystemArchitect_v0_1 が全体構成と依存方向を、AutoTradePhase1_A03_DomainArchitect_v0_1 がドメイン境界と共通概念を担当したものとして整理する。外部依存、研究コード、本番運用コードの混入を防ぐことを最優先の設計制約とする。

全体構成

Phase 1では、モジュラーモノリスを基本構造とし、内部の判断履歴はイベント駆動で扱い、外部依存はAdapterで隔離する。初期段階では分散システム化よりも、検証再現性、責務境界、監査性を優先する。

flowchart LR MDA["Market Data Adapter"] --> DI["Data Ingestion"] DI --> RS["Raw Store"] RS --> NM["Normalization"] NM --> CT["Catalog"] CT --> EE["Event Engine"] EE --> SP["Strategy Plugin"] SP --> RK["Risk"] RK --> OMS["OMS"] OMS --> BA["Broker Adapter"] BA --> RC["Reconciliation"] RC --> MN["Monitoring"]
構成要素責務依存方向
Core Domainイベント、注文意図、注文、約定、ポジション、口座断面、リスク断面の概念を保持する。外部API、DB、通知、UIに依存しない。
Application ServicesBacktest、Shadow、Paper、Liveの実行ユースケースを組み立てる。Core Domainへ依存し、AdapterはPort経由で扱う。
AdaptersBroker、Market Data、通知、永続化など外部依存を内部モデルへ変換する。外部仕様の差分を閉じ込める。
Operations監視、安全停止、監査ログ、Secrets境界、復旧判断を扱う。実行状態を観測し、停止制御点を持つ。

アーキテクチャ原則

原則固定する判断禁止すること
Core First取引判断、注文意図、注文状態、約定、ポジション、口座断面、リスク断面は内部モデルを正本にする。Broker SDK型やData Provider型をCore Domainへ持ち込むこと。
Event Journal入力、判断、Risk判定、注文状態、約定、照合、安全停止をイベントとして記録する。Liveだけに存在する隠れ状態で判断すること。
Adapter Boundary外部API差分、認証、レート制限、外部IDはAdapterで吸収する。StrategyやRiskがBroker固有ID、Data Provider固有記号、APIキーを参照すること。
Mode ParityBacktest / Shadow / Paper / Liveは同じイベント意味論と注文状態を使う。Backtest専用の都合をLive設計へ無検証で流用すること。
Human GateShadow、Paper、Live移行前にはレビュー済み成果物、Unknown台帳、実行ログを確認する。UnknownをPass扱いして次Phaseへ進むこと。

研究コードと本番運用コードの境界

領域許可すること禁止すること

共有境界読み取り専用の共通ドメイン概念、Strategy Plugin Interface、Golden test fixture。研究側から本番DBや本番Adapterを直接importすること。

Backtest / Shadow / Paper / Live で共通化する部分

共通化する部分理由差分の閉じ込め先
イベント封筒、時刻、銘柄ID、価格イベント検証と本番の入力差を小さくする。Market Data Adapter、Clock Adapter
Strategy Plugin Interface戦略差し替えとTurtle比較を同じ入口で扱う。Strategy Module
Risk、OMSの判断順序BacktestとLiveの挙動差を監査可能にする。Execution Mode Adapter

実行モード別の副作用境界

モードMarket DataBroker副作用監査要求Human Gate
Backtest保存済みデータを再生する。なし。Simulatorのみ。run_id、データバージョン、設定バージョンを必須記録。不要。ただしPoC評価前にレビュー。
ShadowLive相当の入力を読む。注文送信なし。Signal、OrderIntent相当、Risk判定を記録。Paper移行前に必須。
PaperLive相当の入力を読む。Paper口座へ送信。注文状態、約定、Reconciliation、通知を記録。Live移行前に必須。
LiveLive入力を読む。Live口座へ送信。全イベント、全停止判断、Secretsアクセス境界を記録。必須。手動承認なしに移行しない。

安全停止と統制点

統制点発火条件担当モジュール停止後の扱い
Risk Reject1Nリスク、最大DD、ユニット上限、日次損失上限に抵触。RiskOrderIntentを拒否し、Strategyへ結果イベントを返す。
OMS Guard重複注文、状態不整合、取消不能状態、未完了注文過多。OMS新規注文を止め、Reconciliationを要求する。
Broker GuardAPI拒否、接続断、外部注文状態不明、認証失敗。Broker AdapterUnknownExternalStateを発行し、自動再開しない。
Reconciliation Stop内部PositionとBroker残高が閾値以上に乖離。Reconciliation売買停止、差異イベント、手動確認待ち。
Operational Kill Switch監視異常、Heartbeat欠落、Secrets異常、手動停止。Monitoring / Operations全新規注文を停止し、未完了注文の扱いをRunbookへ送る。

設計判断

DEC-P1-ARCH-01: モジュラーモノリス、イベント駆動、Adapter方式を採用する

初期段階では単一デプロイ単位で責務境界を明確化し、イベント記録により再現性と監査性を確保する。外部依存はAdapterへ閉じ込める。

DEC-P1-ARCH-02: 研究用コードは本番注文経路から分離する

研究側は探索速度を優先できる一方、本番側は監査性、安全停止、Secrets境界を優先するため、接点をStrategy Plugin Interfaceと検証済み設定に限定する。

DEC-P1-ARCH-03: Strategyは注文意図までを出力する

StrategyはSignalとOrderIntentを作る。Risk、OMS、Broker Adapter、ReconciliationはStrategy外に置く。
