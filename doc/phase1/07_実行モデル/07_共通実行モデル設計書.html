要約

本書は、Backtest / Shadow / Paper / Liveを同じイベント意味論で実行するためのPhase 1共通実行モデルを定義する。証券会社内蔵バックテストへ依存せず、履歴イベントリプレイとリアルタイムイベント処理を同じPort、同じ状態遷移、同じ監査単位で扱う。

Phase 1では、取引エンジン実装クラス、スレッドモデル、永続化テーブル、Broker API詳細を固定しない。固定するのは、Run、Manifest、Event Stream、Environment差分、Gate、復旧時に必要な最小監査情報である。

対象と非対象

区分内容

設計原則

ID原則理由
EXE-PR-01履歴リプレイとリアルタイム処理は同じEvent Engineへ入力する。Backtest専用コードがLive前提を壊すことを防ぐ。
EXE-PR-02Backtestは証券会社内蔵バックテストへ依存しない。Broker変更やAPI制約から研究再現性を分離する。
EXE-PR-03Shadow / Paper / Liveの差分はAdapterとEnvironment Profileで吸収する。Strategy、Risk、OMSの意味論を実行モードで分岐させない。
EXE-PR-04すべてのRunはManifestで再現可能性を説明できる。データ、設定、コード、Gate結果を監査可能にする。
EXE-PR-05安全停止はイベントとして記録し、復旧前にReconciliationを必須にする。状態不明のまま新規注文へ進む事故を避ける。

実行モード

モードMarketEvent入力OrderEvent入力外部副作用主なGate
Backtest保存済みRaw / Normalizedから決定的に再生する。Simulatorが生成する。なし。データバージョン固定、Look-ahead禁止、Golden test一致。
ShadowLive相当の市場データを読む。注文送信せず仮想ExecutionReportを生成する。なし。Heartbeat、遅延、欠損、Intent監査。
PaperLive相当の市場データを読む。Broker Paperまたは検証口座から正規化する。Paper注文のみ。Paper権限、Kill Switch、Open Order再同期。
LiveLive市場データを読む。Broker Adapterから正規化する。実注文。Phase 1では設計対象外。Phase 5以降のHuman Gate必須。

イベント処理モデル

Event Source
  -> Event Envelope(event_id, run_id, source, event_time_utc, received_at_utc, seq, checksum)
  -> Event Store append
  -> Event Engine dispatch
  -> Strategy / Risk / OMS / Adapter ports
  -> Output Events and Decisions append
  -> Health and Gate evaluation
論点方針
順序同一source内はsource_seqを優先する。sourceを跨ぐ順序はevent_time_utcとreceived_at_utcを併記し、決定的な並べ替え規則をManifestに残す。
重複event_id、source_seq、checksumの組み合わせで重複排除する。排除した事実も監査イベントとして残す。
Timerバー確定、Heartbeat、日次締め、ReconciliationをTimerEventで表現し、市場データと同じEvent Engineに流す。
HealthAdapter遅延、データ欠損、Broker状態不明、Store書込失敗はHealthEventとして扱い、停止判断の入力にする。

再起動復旧

復旧対象最低限必要な情報復旧後の扱い
Event Engine最後に処理済みのevent_id、source_seq、Manifest、Event Store位置。未処理イベントから再開する。
Strategystrategy snapshot、config_version、最後にemitしたintent_id。snapshot復元後、重複Intentを禁止する。
OMSclient_order_id、Order状態、外部ID対応、未完了注文。Broker照合完了まで新規注文停止。
Portfolio / RiskPosition、AccountSnapshot、RiskSnapshot、Kill Switch状態。状態差分がある場合はHuman Gateへ送る。

品質Gate

Gate合格条件失敗時
Replay Gate同一Manifestで同一OrderIntent系列を再現できる。データまたは非決定性を調査する。
Bias GateLook-ahead、survivorship bias、未確定バー参照が検出されない。該当検証を無効にする。
Recovery Gate再起動後に重複注文、欠落Fill、Position不一致が発生しない。Paper昇格不可。
Safety GateHeartbeat欠損、Broker状態不明、Data欠損でfail-closedする。PoC候補から減点または除外する。
Human GatePoC採点、Unknown、運用リスク、Phase 2/4バックログを人間が承認する。次Phaseへ進めない。

設計判断

DEC-P1-EXE-01: イベント駆動をBacktestからLiveまで共通化する

Strategy、Risk、OMSを同じEvent Envelopeで動かし、モード差分はEvent Source、Adapter、Environment Profileで吸収する。

DEC-P1-EXE-02: Broker内蔵Backtestへ依存しない

研究再現性、データ版管理、Broker変更耐性を確保するため、内部Event StoreとSimulatorを正本にする。

DEC-P1-EXE-03: Run Manifestを昇格判定の単位にする

PoC、Backtest、Shadow、Paperの結果を比較可能にし、Phase 1でエンジン採否を判断できる証跡を残す。
