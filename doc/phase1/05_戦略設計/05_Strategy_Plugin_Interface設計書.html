概要

本書は、Strategy Plugin InterfaceのPhase 1仕様を定義する。目的は、原典 System 1、原典 System 2、現代版候補を同じ実行基盤、同じ共通ドメインモデル、同じGolden testで比較できるようにすることである。

Strategyは市場イベント、戦略設定、限定されたPortfolio / Riskビューを読み、SignalEvent、OrderIntent、またはTargetPositionを出力する。Broker接続、注文送信、口座正本、安全停止の最終判定、Secrets管理は担当しない。

Interfaceライフサイクル

メソッド目的入力出力制約
initialize新規実行の初期状態を作る。Strategy Config、run_id、strategy_id、対象Instrument、初期Portfolio View。初期StrategyState、HealthEvent。外部API接続を開始しない。
restore保存済みsnapshotから復旧する。snapshot、run_id、復旧対象時刻。復旧済みStrategyState、復旧HealthEvent。snapshotだけで再現できない隠れ状態を持たない。
on_market_eventMarketEventを取り込み、N、Donchian、Entry/Exit条件を更新する。MarketEvent、Catalog View、StrategyState。更新済みStrategyState、SignalEvent候補。bar_close_time前の未来データを読まない。
on_order_eventOMSからの注文状態イベントを取り込む。OrderStateChanged、Fill要約、client_order_id。戦略内の未完了意図メモ、HealthEvent。Order正本をStrategy側で持たない。
on_account_eventStrategy判断用の限定Account / Portfolio Viewを取り込む。Portfolio View、Risk View、AccountSnapshot要約。StrategyStateの参照ビュー更新。口座正本やBroker残高未照合値を直接使わない。
on_timerバー確定、日次締め、Heartbeatなどを処理する。TimerEvent、business_date、bar_close_time。SignalEvent、HealthEvent、snapshot要求。Timerを使って外部副作用を起こさない。
emit_intents蓄積状態からOrderIntentまたはTargetPositionを出力する。StrategyState、Risk View、実行モード。OrderIntent一覧、TargetPosition一覧、判断根拠。Riskを通過した注文として扱わない。
snapshot復旧可能な戦略状態を出力する。StrategyState、last_event_id。StrategySnapshot。Broker状態、Secrets、外部接続状態を含めない。
health戦略状態の自己診断を返す。StrategyState、last_event_time、expected_timer。HealthEvent、severity、reason_code。停止の最終判断はMonitoring / Operationsへ渡す。

System 1 / System 2 / 現代版比較

候補EntryExitFilter比較対象にする理由
原典 System 1短期Donchian breakout。原典は20日系を基準。短期Exit。原典は10日系を基準。勝ちブレイクフィルターを比較対象に含める。REQ-Q01, REQ-Q12の原典再現の中心。
原典 System 2長期Donchian breakout。原典は55日系を基準。長期Exit。原典は20日系を基準。System 1とは異なる長期追随として扱う。トレンド期間差による比較軸。
現代版候補 A終値確認Entry。終値確認Exitまたは原典Exit。Look-ahead禁止、滑りやGapに保守的。REQ-Q13の現代版比較。
現代版候補 Bintraday breakout維持。原典Exit。Whipsaw、ボラ急上昇時縮小を比較対象にする。REQ-Q15の比較。

Turtleルール表現

論点Phase 1仕様Golden test接続
NTrue Rangeの移動平均として扱う。初期化期間、丸め、欠損時の扱いをConfigで固定する。N計算fixtureで期待Nを照合。
True Rangemax(high-low, abs(high-prev_close), abs(low-prev_close))を基準にする。Gapを含む固定入力を必須にする。
Donchian ChannelEntry/Exitそれぞれ独立したlookbackを持つ。現在バーを含めるかはLook-ahead防止のため明示する。breakout直前、同値、超過の3ケースを固定。
0.5N追加最後のEntryまたは追加単価から0.5N進んだ時に追加候補を出す。pyramid_stepとmax unit到達を照合。
2N StopEntry基準または最後の追加基準から2N逆行時のStop候補を出す。採用方式はvariantで明示する。Stop発火、未発火、Gap超過を検証。
勝ちブレイクフィルターSystem 1の直前ブレイクが勝ちなら次の同方向ブレイクを無視する比較候補を表現する。勝ち/負け判定fixtureを分離。
4/6/10/12 Unit上限単一市場、同方向、相関グループ、総量の上限をStrategy Hintとして出す。最終判定はRisk。Strategy出力とRisk期待入力を分けて検証。

Strategyが担当しない責務

非責務担当先理由
Broker接続、注文送信、取消送信。Broker Adapter / OMSStrategyをBacktest / Paper / Liveで共通化するため。
口座残高、入出金、Broker残高の正本管理。Account / Reconciliation未照合値をStrategy判断に混ぜないため。
Risk最終判定、Kill Switch解除、Unit上限の強制。Risk / OperationsStrategyに自己承認を許さないため。
Secrets、APIキー、通知先、運用停止手順。Operations / Monitoring運用責務と戦略判断を分離するため。
銘柄記号変換、ロール正本、外部データ取得。Catalog / Market Data AdapterStrategyを外部ベンダ差分から守るため。

設計判断

DEC-P1-STR-01: Strategy出力はOrderIntentまたはTargetPositionまでに限定する

Strategyが注文そのものを発行するとRisk、OMS、Broker Adapterを迂回できてしまうため、発注可能な注文ではなく意図または目標ポジションとして出力する。

DEC-P1-STR-02: Strategy Configは比較軸を明示し、最適化結果を埋め込まない

Phase 1の目的は比較可能な境界の固定であり、候補資産別のパラメータ最適化ではない。

DEC-P1-STR-03: on_market_eventは未来バーを読めない契約にする

Look-aheadを構造的に防ぐため、MarketEventのbar_close_timeとsource_seqを処理可能範囲の境界にする。
