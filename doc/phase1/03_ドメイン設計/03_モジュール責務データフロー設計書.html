概要

本書は、Data IngestionからMonitoringまでの主要モジュール責務とデータフローを定義する。Phase 1では、各モジュールが何を受け取り、何を出し、何を担当しないかを固定する。

本改訂では、AutoTradePhase1_A02_SystemArchitect_v0_1 がモジュール責務と依存方向を、AutoTradePhase1_A03_DomainArchitect_v0_1 がドメインイベントと所有状態を確認したものとして、データ正本、イベントジャーナル、障害時の停止伝播を明確化する。

データフロー

1. External Market Data -> Data Ingestion -> Raw Store
2. Raw Store -> Normalization -> Catalog-resolved Market Series
3. Market Series -> Event Engine -> MarketEvent
4. MarketEvent -> Strategy Plugin -> Signal / OrderIntent
5. OrderIntent -> Portfolio / Risk -> RiskDecision
6. Approved Intent -> OMS -> OrderRequest
7. OrderRequest -> Broker Adapter -> ExecutionReport
8. ExecutionReport -> OMS / Reconciliation -> State Update or Stop Request
9. Significant Events -> Monitoring / Event Journal

重要な判断はイベントジャーナルへ記録する。失敗、拒否、差異、安全停止も正常系と同じくイベントとして扱う。

設計判断

DEC-P1-FLOW-01: OrderIntentはRiskとOMSを通過するまで注文ではない

Strategy出力をそのままBrokerへ渡す経路を禁止し、安全停止、ポジション制限、注文重複防止を中央で扱う。

DEC-P1-FLOW-02: Raw Storeは不変とする

データ補正や再取得があってもRaw履歴を上書きしない。補正はNormalization以降の派生として扱う。

DEC-P1-FLOW-03: Reconciliationは差異をイベント化する

内部状態とBroker状態の不一致は黙って補正せず、照合結果と停止要求として扱う。
