01. 読み方と v2 との関係

v3は、v2を消して作り直した文書ではない。v2に書かれた既存要件、画面、ユースケース、状態、テスト、監査、Security、Unknownの細部を継承し、そのうち「P5Rをどこに置くか」「各実行Modeをどの順番で完成させるか」「現在何が未完成か」をv3で最新の正本として更新する。

v2とv3で説明が違う場合は、P5R、Phase順序、現行状態、Human Gateについてはv3を優先する。v2の詳細な個別要件は、v3で明示的に上書きしていない限り継続する。

中学生向けの説明: v2は今までの教科書、v3は「次にどの勉強をどの順で終えるか」を書き直した最新版の教科書である。昔の問題と答えを消すのではなく、どこまでできていて、次に何を勉強するのかを正しく直す。

07. P6〜P12 — 本番へ近づく機能を順番に完成させる

07.1 P6 — 複数運用Unit、Portfolio、Risk、OMSの固定Simulation

P6は、実時間Forwardを完成させる前の安全な土台である。複数の継続Unitが同じ資金や注文に関係しても、重複・競合・部分約定・拒否・期限切れ・再起動・照合・Killを固定Simulationで説明できるようにする。

完了条件: `Signal → Target Position → OrderIntent → Order → Fill → Position` の状態、Riskが注文前に拒否できること、同じ注文を二重に扱わないこと、再起動後に照合してから再開すること、Killが新規副作用を止めることを受入する。

07.2 P7 — Forward Test（実時間・仮想）

P7は、実時間に届く確定Dataを使い、仮想のSignal、OrderIntent、Fill、Positionを連続して記録する。実注文は1件も送らない。Data遅延、欠損、重複、時刻逆行、再接続、未確定足を検出したら、判定を保留または停止する。

完了条件: 承認済みProvider範囲で、観測時刻・Bar時刻・判定時刻・仮想約定時刻・品質状態・停止理由を記録し、外部Orderが0件であることを証明できる。

07.3 P8 — Shadow（本番候補の複製・注文なし）

P8は、P10以降で使う可能性がある本番候補と同じStrategy / Config / Risk / Data経路を横で複製し、注文なしで差分を観察する。Shadowの良い結果は、実注文の許可ではない。

完了条件: Forwardとの差分、候補との差分、Data遅延・欠損、停止、比較不能を説明でき、実口座・実注文が0件である。

07.4 P9 — Paper（仮想Account・仮想Ledger）

P9は、実時間Dataを使っても、仮想Account、仮想Balance、仮想Ledger、仮想Order、仮想Fill、仮想Positionだけを更新する。Paperの約定率や損益は、実Brokerの約定・手数料・拒否を意味しない。

完了条件: 仮想Ledgerの全行を辿れ、再起動・停止・差分・再開後も整合が取れ、外部Orderが0件である。

07.5 P10 — Live候補（実注文前の最終確認）

P10は実注文を許可しない。Candidateに、P5R / Forward / Shadow / Paperの根拠、対象Data、Strategy / Config / Risk版、Account照合結果、未達、Kill、復旧手順、監視責任、予定上限をまとめる。読み取り専用の外部接続が必要になった場合も、対象・目的・Secret・費用・停止条件を別Gateで承認する。

完了条件: Start Reviewで未達を表示し、未照合・Risk不足・Kill不能・承認不足なら開始を拒否し、実注文経路が無効である。

07.6 P11 — 小規模Live（限定実資金）

P11は、このロードマップで初めて実注文と実資金を扱えるPhaseである。ただし、個別Human Gateが指定したAccount、銘柄、Unit、時間帯、期間、資金、1注文、同時Position、損失、Exposureの上限を一つでも外れてはならない。

完了条件: 実Order、実Fill、Risk判定、照合、Kill、通信異常、停止、再開が限定範囲で検証され、開始時と拡張時の承認が別記録である。

07.7 P12 — 通常Live

P12はP11を大きくしただけではない。P11の連続実績、未解決事項のレビュー、再承認された範囲、監視、Kill、照合、復旧、監査の継続条件を満たして初めて開始できる。通常Liveにも資金・損失・Exposure・対象・時間の上限は残る。
