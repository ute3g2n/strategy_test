1. 位置付けと継承

v4は、P5Rの旧完了範囲を無効化せず、P5RとP6の間にP5R2を追加してBacktest製品要件を是正する。P5Rは当時の限定Scopeにおける完了履歴として残し、P5R2-H2まではP6を開始しない。

v3からv4への主要な差分
継承元v4での扱い変更理由
AT-REQ-003 v3履歴として保持。v4の前提要件は継承する。旧Phaseの完了事実と変更履歴を失わないため。
REQ-V2-0027、REQ-V2-0028、REQ-V2-0035P5R2の時間足、UTC、source／derived境界へ具体化。1m sourceと利用者が選ぶ戦略時間足を混同しないため。
REQ-V3-0113〜REQ-V3-0117、P5R-ACP5R2のData管理、Run操作、結果Artifact、監査へ補足。既存Runを保護しながら、取消・削除を3画面で扱うため。
P5R完了HTML・Manual v0.5HISTORY / NOT_INVALIDATED。実装・検証済みの旧内容を保持。v4正式化だけで、未実装の新機能を旧手順書へ混ぜないため。

関連する旧文書：v3、P5R完了・P6引渡し（履歴）、現行手順書（P5R履歴）。

3. 時間足要件

Single Backtest、source、生成、期間の要求
ID要求Acceptanceの要点
P5R2-REQ-ROADMAP-001P5Rを履歴として保持し、P5R2をP5RとP6の間の必須是正Phaseとして扱う。P6はP5R2-H2まで停止する。v3、P5R履歴、v4、台帳、index、P5R2計画でPhase順と停止条件が一致する。
P5R2-REQ-TF-001Single Backtestの戦略時間足は15m / 30m / 1h / 4h / 1dから1つだけ選ぶ。1mを戦略時間足として選択させない。UIの選択肢が5種類だけで、1 Runの選択時間足が1つに固定される。30mは選択可能である。
P5R2-REQ-TF-002Historical sourceは1mとし、15m／30m／1h／4h／1dはローカル生成する。1m sourceとderived Dataを同一論理Dataとして混在させない。Catalog、Run入力、provenanceでsource／derivedが区別され、1mだけ固定のUIへ戻らない。
P5R2-REQ-TF-003既存の1m／M30保存Data・Run・結果は閲覧専用legacyとして表示する。新規30m選択、自動移行、再実行、実削除と混同しない。legacy属性が表示され、legacyを新規Run入力へ自動使用しない。30mの新規選択は可能である。
P5R2-REQ-TF-004上位足はUTC 00:00 anchorで生成し、終了時刻が境界でなければ直前の確定足まで切り下げる。指定終了と有効終了を表示し、partial barをRunへ渡さない。UTC、指定期間、有効期間、閉じた足だけがRun条件として確認できる。開始前または有効足0件は拒否する。
P5R2-REQ-TF-005内部の連続1分欠損がちょうど1本の場合だけ、未来値を使わず欠損直前の確定CloseでOHLCを補間し、Volumeを0とする。始端・終端欠損、2本以上、時系列逆転、上限超過、provenance欠落は使用禁止とする。警告だけのUSABLE_WITH_WARNINGとUNUSABLEを区別し、補間位置・方式・参照Close・DataSet・Job・理由をprovenanceへ保存する。
P5R2-REQ-TF-006必要期間・時間足が不足する場合はBacktest開始を止め、理由と「時間足を生成する」確認を表示する。OKの場合、その銘柄を引き継いだ時間足生成画面へ遷移する。生成画面で銘柄、複数の対象時間足、期間を選択でき、既定期間は現在生成可能な全期間である。全期間の算出規則はH1で確定し、local実装・検証Evidenceへ追跡する。

4. Historical Data要件

外部1m取得とlocal上位足生成は、同じJob基盤を再利用しても、job_type、ID、状態、入力、出力、Gateを分ける。Job完了だけではDataSetを使用可能へ昇格させない。

Download、生成、Catalog、mergeの要求
ID要求Acceptanceの要点
P5R2-REQ-HD-001UIは候補Providerを使うHistoricalDownloadJobの取得要求を作成できる。候補ProviderはBinance Data Visionとするが、実host、利用条件、symbol、期間、通信、Secret、費用、実downloadはP5R2-DATA-G1後だけ許可する。Gate前は実通信が起きず、要求・確認・監査の候補だけを扱う。公開文書の閲覧は採用・契約・通信許可とみなさない。
P5R2-REQ-HD-002Download JobとDataSetを別ID・別状態で管理する。PARTIAL / FAILED / CANCELLED Jobをusable DataSetへ自動昇格しない。Jobの取消・失敗・再試行とDataSetの使用可能状態を別表示し、失敗成果物からRunを開始できない。
P5R2-REQ-HD-003銘柄ごとに生成済み時間足、期間、品質、usable状態、legacy属性を一覧表示する。生成画面では銘柄、複数時間足、期間を選択し、既定期間を現在生成可能な全期間にする。一覧と生成画面で値、期間coverage、品質、状態、入力引継ぎを確認できる。
P5R2-REQ-HD-004同一論理DataはProvider、market、symbol、Data時間足、正規化schemaが全て同じ場合だけとする。Provider・market違い、1m sourceとderived Dataを自動混在・自動mergeしない。identity属性を保存・比較し、identity違いを拒否する。
P5R2-REQ-HD-005同一論理Dataの非重複期間は、利用者が開始したDownload／merge操作で追加できる。merge後に過去Run結果が変わることを理由にmergeを禁止しない。古いDataでのRun／結果を利用者確認後に削除し、新Dataで再実行できる。current coverage、追加区間、影響Run／結果、再実行対象、確認内容をpreviewできる。システムが無断で旧Run／結果を削除しない。
P5R2-REQ-HD-006同一timestampの完全一致barはdedupeする。値が異なる場合、利用者が明示的に新Dataでreplaceし影響Run／結果を削除する操作を選べる。選ばない場合はCONFLICTで停止する。競合、replace対象、削除対象、再実行対象を表示し、確認後に一度のpromotion単位で反映する。値競合だけを理由に利用者の明示replaceを禁止しない。
P5R2-REQ-HD-007品質検査は警告だけのUSABLE_WITH_WARNINGと、始端・終端欠損、許容上限超過、値競合、時系列逆転、必須provenance欠落等のUNUSABLEを区別する。Preflightが警告・停止理由を返し、UNUSABLE、staging、orphan、partial promotion中のDataをRun入力から拒否する。

5. Backtest Run操作要件

3画面の取消、結果Artifact削除、保存物保護
ID要求Acceptanceの要点
P5R2-REQ-RUN-001QUEUED / RUNNINGのRunだけを、実行一覧・進捗・結果サマリーの3画面から同じ判定で取消要求できる。フロントエンドはin-flight中の二重押下を禁止し、サーバーは対象Runの現在状態と操作tokenを確認する。3画面で可否と理由が一致し、二重クリック、通信再送、別画面・別タブの操作で二重状態変更しない。汎用冪等性基盤ではなくRun操作に必要な最小guardを使う。
P5R2-REQ-RUN-002SUCCEEDED / FAILED / CANCELLED / RECOVERY_REQUIRED / LEGACY_RESULT_ONLY / PARTIAL_FAILED等terminal状態への取消はRun状態を変更しない受付・監査記録とする。表示削除と取消を混同しない。terminal取消後も状態が変わらず、理由と監査記録を確認できる。
P5R2-REQ-RUN-003結果サマリー画面の「削除」は、利用者が不要と明示したterminal Runのアプリ管理result Artifactを物理削除する。保持したい結果は削除しない。Export済みCSV、Runの実行状態、Historical Data、監査記録、Evidenceは削除しない。復元操作は提供しない。削除前に対象Artifact、対象Run、CSV状態、影響数を確認し、削除後は結果を表示対象外にする。Export済みCSVと保護対象が残る。
P5R2-REQ-RUN-004Result Artifactの削除状態をRunのterminal状態と分離し、要求・拒否・成功・失敗・CSV保護を監査する。入力は論理IDだけとし、許可root外、path traversal、symlink／reparse、任意path、Artifact ID不一致を拒否する。terminal Artifactだけが対象となり、削除後はRESULT_DELETED、失敗時はDELETE_FAILEDとして表示する。Run、CSV、Data、監査、Evidenceは保護される。
運用上の意味：「削除」はシステムが勝手に結果を消す機能ではない。利用者が不要な結果を選び、CSV Export状態と保護対象を確認し、明示操作したときだけ、許可されたresult Artifactを削除する。

9.2 非hash・文書品質の確認範囲

本書の完了確認は、文書ID、版、状態、UTF-8、HTML構造、相対リンク、index到達性、Secret非掲載、Requirement ID追跡、Gate状態の非hash確認で行う。管理用hash、manifest、stale、fingerprint、hash retry、hash receiptは導入しない。保護対象hashを将来採用する場合は、目的・対象・比較時点・不一致時の停止範囲を別Human Gateで明文化する。
